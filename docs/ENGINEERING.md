# 2.0.1工程整理与选型

## 调查结果与决策

基线0076fa6：Game.tsx为958行，styles.css为2923行，v2.css为629行，refinements.css为42行。困难不是“使用了原生CSS”，而是组件、状态副作用和样式所有权混在一起，又以版本补丁形式叠加覆盖。

本次保留React、原生CSS、SVG动画和合成音效，不增加运行时库。以下是针对当前项目的取舍，不是对第三方库的普遍否定。

| 方案               | 可能收益                             | 当前项目的成本/结论                                                                                                                                      |
| ------------------ | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 完整主题组件库     | 标准表单、后台页面的统一控件         | 棋盘、符文、弹道、回合模式、召唤仪式仍要手写；为保留视觉需要改主题和覆盖样式，不能解决主要维护问题，暂不引入                                             |
| Radix Primitives   | 复杂弹窗、菜单、弹层的可访问交互     | 它本身无样式，不能消除棋盘CSS；现有native dialog与原生按钮够用。将来新增组合菜单/弹层时可按需评估，不要全仓替换                                          |
| Motion             | 手势、布局过渡、退出动画、复杂编排   | 当前事件动画是移动过渡和少量SVG/CSS特效；增量收益小。单HTML必须把动画功能也内联，不能把异步分包初始体积当成发行文件总增量。将来有拖拽布局/动画队列再评估 |
| CSS Modules        | 更强的类名局部隔离                   | 构建器支持，但现有`.hj-game`作用域及大量动态棋子状态已经可用；这轮按功能分文件保留类名，减少视觉和嵌入回归面。不是否定以后迁移                           |
| 原生CSS + 功能归属 | 无新增运行时、保留视觉、直接定位样式 | 本次采用。媒体查询、状态和主题差异跟随所属组件，不再堆“v3.css”式补丁                                                                                     |

官方材料（选型依据，不是本项目的实测体积）：[Radix Primitives](https://www.radix-ui.com/primitives/docs/overview/introduction)、[Motion bundle size](https://motion.dev/docs/react-reduce-bundle-size)、[esbuild CSS](https://esbuild.github.io/content-types/#css)。本次没有声称安装并跑分第三方库；体积对比以实际产物为准。

## 目录与职责

```text
src/
  engine/                     纯规则引擎；migrations.ts只处理已知规则存档修正
  ui/
    Game.tsx                  对外组件，页面组合根
    game/                     页面框架、比分、指令协调、快捷键
    board/                    格子、棋子、特效、操作栏
    inspector/                详情、动态状态、技能/复活选择
    hand/                     手牌、召唤选择、卡片
    library/                  图鉴、规则手册
    feedback/                 战报、提示、召唤反馈、对局弹窗
    session/                  持久化适配、会话hook、导入导出
    shared/                   原生dialog、图标/符文、属性显示、基础控件样式
    audio/                    可关闭的合成音效
    styles/                   设计变量、统一CSS入口、减少动态效果
  index.ts                    保留公开React及engine入口
scripts/
  build.mjs                   单HTML构建
  pages.mjs                   准备/检查main分支的发布文件
  dev.mjs                     本地开发服务
 tests/
  core/ ultimate/ session/    按行为分类的引擎与持久化测试
  browser/                   离线成品、HTTP续局和宿主嵌入验收
```

没有把958行搬到另一个同样长的hook里。会话hook只管理权威状态、持久化和可释放视听副作用；controller只处理选择流程及命令协调；详情、手牌、弹窗都以显式props接收数据和回调。不引入仅为避免传两层props的全局store或巨型Context。

## 样式维护

每个功能目录里的CSS放该功能的基础样式、状态和响应式规则。styles/index.css只列构建时import顺序：变量与原生元素 → 共享控件 → 各功能 → 最后的减少动态效果规则。媒体查询不再集中进一个巨大的responsive.css。

已删除旧styles.css/v2.css/refinements.css，旧版不再使用的action-buttons/skill-buttons/reforge-choices样式也移除。保留当前DOM类名和`.hj-game`作用域，避免把宿主页面按钮和标题全局重置。颜色等跨功能值优先在tokens.css维护。状态样式可保留现有v2-game选择器，但不要新建按版本追加的CSS文件。

动画依旧观察GameEvent，不反过来决定攻击/伤害；减少动态效果、关声音或快速悔棋不改变规则结果。多个嵌入实例只有当前聚焦游戏响应撤销快捷键，宿主输入和按钮不被劫持。

## 验收方式

稳定维护既有26普通、28终极和存档行为测试。新测试只针对本次新契约：号令8回合及旧档修正、空间不足/禁用存储、错误存档不覆盖、同源重新发布续局、双实例快捷键隔离。不新增大量内部组件快照，不用固定CSS行数作为CI门槛。

浏览器游戏验收直接打开file://生产HTML并关闭网络。HTTP验收在项目子路径提供根发布文件，替换HTML版本标记并关闭/重开标签后，验证局面和悔棋历史仍在；这不是声称GitHub Pages提供云存档。部署说明见PAGES.md。

## 2.1宽屏契约更新

按作者后续澄清，宽屏必须一屏看完整棋局。桌面工作区采用容器查询：在游戏自身宽度≥1100px时，紧凑顶栏与两側工具充分利用横向空间，中央以可用宽高限制9:13棋盘；仅侧栏内部滚动。核心控制固定在侧边，不随长手牌/说明滚走。不设置body overflow:hidden，不拉伸格子。--haojie-height可由嵌入宿主覆盖（默认100dvh）；嵌入页面本身的滚动不由游戏劫持。此项取代2.1初版“固定大棋盘、接受页面滚动”的错误设计。
