# 规则引擎采样优化（2026-10-21）

本文为历史实验记录，相关一次性脚本已清理；复现命令使用[固定版本 7fc8e85](https://github.com/Loremmlel/haojie2/tree/7fc8e85)。本地原始测量、冻结源码和模型继续保留。

## 目标与冻结起点

以 `6b31563` 为本轮起点，目标为 Rust 规则引擎采样时间减少至少 50%。TS 与 Rust 保持相同规则、参数域、候选顺序、预检结果、正式随机流和采样算法；语言自身的引用共享方式可以不同。2026-10-22 按作者要求停止追加优化和性能评测，清理后提交。最近完整 Rust 对照减少 `46.29%`，50% 目标尚未达到；最后保留的规则数值索引已通过聚焦验证，其速度未重新测量。

源码归档、冻结的 TS bundle、Rust 二进制、工作集、逐轮结果均保存在 `artifacts/engine-sampling-20261021/`。旧实验产物没有删除或覆盖。

## 对照方法

维护入口为 `scripts/training/native/endurance/benchmark.ts`。固定工作集包含 110 个规则夹具，以及四条真实长局前缀各自的开局、100 命令、中段和晚盘，共 126 个起点。每段固定执行 8 条命令，使用原有 TinyPolicy 和采样随机流；完整预热后交替运行前后版本。

每段严格核对完整权威状态、双方公开观察、实际命令、结束/截断状态和全部非时间计数。固定短段的命令预算截断保持未知收益。TS 额外的权威重放、摘要计算和宿主往返位于主计时之外。

`engineMs` 是内部完整采样减去 TinyPolicy 前向；`rulesMs` 再扣除编码、策略随机排序和记录时间，保留状态导入、规则查询、正式结算和循环开销。原生原有 `stepMs` 不包含 acceptance 回调内的正式结算，不能用它与树/观察分项相加代替完整规则时间。

```sh
node --import tsx scripts/training/native/endurance/benchmark.ts --mode freeze --executable artifacts/native-target/release/haojie-engine.exe --output artifacts/engine-sampling-20261021/variant
node --import tsx scripts/training/native/endurance/benchmark.ts --mode prepare --variant artifacts/engine-sampling-20261021/before-v2 --output artifacts/engine-sampling-20261021/workset.json
node --import tsx scripts/training/native/endurance/benchmark.ts --mode compare --before artifacts/engine-sampling-20261021/before-v2 --after artifacts/engine-sampling-20261021/variant --workset artifacts/engine-sampling-20261021/workset.json --backend both --rounds 7 --repetitions 5 --output artifacts/engine-sampling-20261021/comparison.json
```

每个输出路径要求尚不存在。正式测量须等待编译、测试与其他性能工作全部结束；与这些工作重叠的探索测量单独保存，不进入最终结论。

## 已实施的共同方案

- 移动点域直接读取可达场，不为每个候选展开路径；真正执行仍重建原精确路径。
- 无普通操作预算且无巨大化的单位不先生成必被拒绝的整套动作；改判仍由手牌入口生成，连续攻击和结束操作保留。
- 确定性的阶段切换、附魔、装备和部分纯技能共用完整只读准备，在预检中省去没有随机或后续拒绝的结算。低生命复活仍模拟死亡连锁。
- 区域法术的受击存在性直接遍历实体和基地，不创建完整目标包装数组。
- 攻击方向节点与叶子预检共用同一个只读路径查询；自动路径继续用原先的最短路径及正面偏好规则惰性计算。
- 死亡历史追加只分离外层数组，复活只分离命中记录；未知字段、历史顺序、240 条裁剪和外部快照保持原样。
- 参数前缀和剩余步骤只读共享。TS 使用对象及数组引用；Rust 的完整步骤保存在私有动作表，`Rc<Prefix>` 仅保存动作索引、命令和偏移。命令稀疏保存参数，来源/目标 ID 共享，选择键延迟格式化。
- 技能落点共用模板、占位索引和纯落点可达场；继承只生成技能与蓄力；同一只读投影的攻击属性惰性复用。
- 改判按完整只读资格生成来源候选；未自选的召唤与改判直接停在首次随机边界。
- 预检延迟纯展示事实，保留原始事件、序号和规则校验；模式投影复用已计算的剩余操作属性。
- 动作生成、路线和攻击来源预检共用原实体属性缓存；反击保留已成功的准备结果，直接传入同次结算。
- 完整攻击准备之后，保守排除当前来源掷骰、全场连锁随机或自动反击的非穿透攻击直接形成确定叶子，其他攻击继续原模拟。
- 训练正式步进保留全部规则结算和原始事件，只省去随后会清空的展示事实及日志；正式随机流、序号、资源和终局后处理照常推进。

## 既有双端候选域差异修复

改判的自选参数曾存在 Rust 单端来源池优先级差异：正式改判与 TS 都先使用手牌保存的 `summonPool`，旧 Rust 训练候选却先按种类推断普通池。例如 `kind: 1, summonPool: 'ultimate'` 可通过 `validState`，TS 提供终极池自选，旧 Rust 提供普通池自选。现在训练候选也复用正式 `summon_pool`，显式来源优先，缺失字段时才按原旧档规则推断；正式改判结算不变。

这项是既有候选域差异修复，单列于性能优化之外，不计作“候选域完全不变”的性能证据。`preparation-reroll-pool-*` 夹具覆盖显式来源、旧档普通/终极派生推断，以及两种冲突来源；采样差分检查完整自选节点的种类与顺序。

聚焦差分使用 debug 宿主通过：6 个合法夹具、36 次预检、12 次成功与 12 次非法正式结算；双方观察共 12 个根、46 个完整节点及编码一致。产物为 `reroll-pool-rules/` 与 `reroll-pool-nodes/`，不作为性能测量。

## 收束结果

优化实验已暂停，50% 目标未完成。当前源码保留已验证的共同流程、Rust 表示与数值索引；失效的共享 BFS、fat LTO 和合成整域原型均不进入提交，测试中的临时布局打印已删除。完整工作集、基线、冻结源码和二进制、正负结果及原始记录继续保留在本地实验目录；仅删除该目录内 `check-target`、`profile-target`、`mimalloc-target`、`lto-fat-target` 四个可再生编译缓存。清理前后核对工作集、基线归档和冻结二进制等六个文件的 SHA-256 一致，通用 `artifacts/native-target` 保留。

最近一次完整双端累计对照为第十三轮：Rust `49.815%`、TS `18.39%`；其后 TS 方向投影增量为 `3.39%`，Rust 最近完整累计为第十八轮 `46.29%`。不同版本和批次的比例分别陈列，不相加，也不替换成最终提交的双端实测。
