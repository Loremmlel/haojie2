# 训练停滞复盘与下一轮破局方案

日期：2026-09-26。审查基线：`cada9d8`，同时读取工作区已有的隔夜验收记录；没有覆盖这些未提交改动。原诊断阶段是路线诊断、现有结果重算和实验设计，没有训练新模型或运行新比赛。下文保留当时提出的研究条件；随后已按此推进无训练实验，实际结果见文末及[完整行动窗口反事实试验](COUNTERFACTUAL-2026-09-26.md)。

## 判断

当前最值得改变的是**学习任务与策略改进步骤的定义**。暂不继续扩模型、堆结构或重复隔夜自对弈。

目前把一个带搜索、预算和缓存计划的教师拆成逐条命令，再让只看当前局面的学生逐参数模仿；随后用很浅的搜索优化从旧行为轨迹拟合的价值。局部模仿、终局预测、实际选招是三个不同任务，现有实验尚未建立它们之间可重复的正向联系。更多训练只能放大已有信号，不能保证制造缺失的好决策。

这不是“Transformer不能学浩劫”或“强化学习不可行”的证明，也不能把所有失败归因于一个尚未发现的代码错误。精确规则、公开观察隔离、可重放轨迹、合法命令、取消、训练和评测设施已有价值；需要换的是这些设施接下来优化什么、何时值得扩量。

**推荐主线：保留现有教师作为可执行基线，先用精确引擎验证完整候选动作的相对收益，再学习候选排序或搜索计算分配。先证明规划能改进，再蒸馏改进；逐参数独立接管整局暂时退出主线。**

## 本轮新增核算：先检查好动作能否进入搜索

| 模型       | 候选集合包含冷教师命令 | 其中13个冷教师部署题 |
| ---------- | ---------------------: | -------------------: |
| 旧空间模型 |                  41/64 |                 6/13 |
| 全部组合   |                  38/64 |                 4/13 |
| 精简组合   |                  36/64 |                 2/13 |

精简模型的束首选与冷教师相同为15/64；候选包含36/64。因此有两个独立问题：一部分参考动作已经在集合中但没有排到第一，另一部分根本没有进入搜索。对同一裁剪集合增加PUCT次数，无法选择被排除的命令。

## 为什么要改变监督目标

当前价值数据来自旧学生与easy40实际走过的对局。它回答的是“这些行为继续下去，最终是谁赢”，没有验证“当前搜索若改走另一个动作，后续会怎样”。换边和多族校准可以排查简单席位偏差，不能自动补足后一个问题；从多个预测中挑最大值，还可能挑中外推误差。

下一轮先固定一个明确的续弈策略及其预算、缓存规则，用同一公开根局面的候选作配对比较：

```text
Δ(s, a) = 估计[执行a后，按固定策略续弈的收益]
        - 估计[执行基线动作后，按相同策略续弈的收益]
```

这样训练对象是同一局面里的相对选择，而不是用跨局面的胜负拟合间接期待动作排序。它仍然只估计特定续弈策略下的收益，不是最优Q，也没有自动超越教师的保证。

已有软纠错并没有做这个实验：`scripts/training/improvement/labels.ts`取冷教师同阶段的前8条评分记录，按排名分配20%质量，给原首选额外80%；训练仍沿原教师命令的参数前缀。它没有对每个候选独立完成续弈，也没有验证反事实收益差。因此新方案不应退化为“再调一次软标签比例”。

方法依据是把规划和泛化分开的[Expert Iteration](https://arxiv.org/abs/1705.08439)，以及显式利用动作后续代价的[AggreVaTe](https://arxiv.org/abs/1406.5979)。[DAgger](https://proceedings.mlr.press/v15/ross11a.html)解释了为什么必须在学生诱导的状态分布上验证。这里是结合本项目证据提出的工程路线，不照搬论文的成本或提升保证。

## 下一轮只做一个主实验：没有新网络时，能否选得更好

### 1. 小规模冻结，先证明算得完

先用已存在的学生轨迹做开发诊断，避免为收集题目再跑一晚。按整局/种子族冻结来源，至少跨8族，预先按指纹选择32个自然根；部署和一般行动分别报告。不要事后只保留有胜招或容易完成的题。额外使用现有战术题作正确性护栏，但不能用它替代自然状态验证。

首批只跑8个根、每根至多4个候选、每候选2个独立模拟场景，用于测量完成边界比例及成本；不训练。再决定是否按预定预算扩到32根和4个场景。所有随机场景来自独立模拟源，不读取正式seed/rng。共同随机数只能在保持各分支正确边缘概率的情况下配对，不能假定不同命令会消耗相同随机序列。

墙钟只作运行停止与成本记录，实际选招使用固定工作量。记录每根全部尝试、未完成原因和资源消耗，不能把超限分支删掉后称为完整比较。研究用的额外计算与部署预算分开记录。

### 2. 固定候选，分离覆盖与排序

保留两个候选域作受控对照：原神经命令束；原集合加冷教师首选及少量不同的合法备选。去重后按事前规则限制数量，并始终保留基线动作。候选来源、数量和裁剪原因必须可见。

首批聚焦普通play/部署决策。合成、未决反应、回合外巨大化和超长连锁继续经过共享引擎；暂不支持的搜索窗口明确回退基线并计入覆盖，不绕过规则或强行结束。范围限定的是研究能力，不能声称解决整个游戏。

在同一候选域比较原排序、当前网络价值排序、配对续弈排序。另单列直接easy40和生产hard教师，用来判断是否仅仅恢复了教师本来就会做的事。这样才能区分候选域扩大带来的收益与排序方法带来的收益。

### 3. 搜索深度按实际行动窗口定义

每个候选先完成当前己方行动窗口，再完成一次对手行动窗口，到同一指定阶段边界再比较。不是把两条命令改成任意四条或八条。反应按实际操作者处理，强制召唤和未部署手牌不能跳过；所有候选使用同一续弈策略、缓存规则和有效预算。

预算内未完成的候选是未知；只有各候选共同完成的成对场景能比较，并保留此前已完成的场景。完成比例不足，先处理候选成本和续弈效率，不把半回合分数塞进排名。

边界处评分要区分三类证据：

- 引擎确认的终局、精确概率下的战术结果：可作对应目标的可靠监督。
- 固定续弈策略继续到自然终局的配对估计：报告抽样误差和未知结果，只代表该策略下的收益。
- 完整边界上的现有手工评估：只能作廉价筛查指标，不能改名为真实胜率，也不能单靠它批准扩训。

不全面展开每条长对局。先用边界评估找有区分度的候选对，再在预先选定的子集上用独立场景延长续弈或做真实整局确认；不得用选候选的同一批幸运场景兼作最终评价。

### 4. 检查执行是否兑现

只执行当前合法命令。复用现有`plan-cache`的指纹与预算规则保留可验证的确定性续招；实际结果变化、随机/反应边界和取消时重新决策，`end`仍不能直接复用缓存。不能为了兑现计划而无视新信息，也不能让续演中“教师稍后会赢”的价值一直替无效首步背书。

现有实现可以复用：`src/ai/planning/search.ts`的候选、行动收尾与完整成对回应机制，`src/ai/planning/plan-cache.ts`的执行校验，以及`src/ai/simulation`的规则概率。内部续弈接缝需要小范围整理，不能声称完整候选后继评估接口已经现成可用。暂不重写引擎、不新增另一套技能合法性规则，也不另造通用训练框架。

实现时尤其不能直接把现有trace的`reply`分数与其中的`outcomes`配成训练样本：前者已包含回应评分，后者仍可能来自原候选节点。应从真正完成的边界输出公开Observation、概率/采样权重、完成标志和工作量，保持输入与标签对应。

## 何时才值得训练

无网络的配对选择器若不能在独立自然局面上提供有效区分，并在新族整局里重复改善，就停止该路线的训练部分。继续定位候选遗漏、续弈质量或时程，而不是把无增益搜索的访问次数生产成更多标签。

通过后，先训练线性排序器或一个小MLP：输入复用公开特征、合法动作参数及共享引擎得到的公开后继/差分特征，目标为候选相对基线的排序或收益差。沿用整族隔离；同一根的多个候选、多个随机样本不能算独立对局。不复制规则公式、不重新加一套UI或网络数值表。

比较原教师顺序、当前启发式、零增益/随机排序、学习排序；检查模型是否保留昂贵选择器的收益并节省计算。若线性模型已有收益，再比较现有空间小模型；若线性模型不能泛化，先区分标签与特征问题，不能直接断言神经网络也无效。

不确定的改招保留基线，作为保守研究约束；这不是数学上的不退化保证。最初不要求网络生成整条合法命令或预测所有阶段的最终胜负。候选和执行交给已有代码，网络先负责一个可直接验收的小任务。

## 决策门槛与停止条件

下列数字是下一轮建议的工程投入上限，必须在新结果产生前冻结；不是从本轮偶发胜局倒推的门槛。

| 检查            | 继续条件                                                                                                                                            | 失败后只处理什么                                                                |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 首批8根成本试验 | 固定预算下至少80%的根取得所有比较候选共同完成的场景，所有未知明确记录；战术护栏无回退                                                               | 候选和完整窗口成本；不加模型、不把预算外值补零                                  |
| 32根开发诊断    | 能指出真实后果支持的改招，并能在分开的自然族重复；候选召回、排序损失、退化和未知均可解释                                                            | 好招缺失则修候选；有好招却选错则修排序/标签；只有启发式涨分则补真实结果         |
| 新族整局试验    | 冻结一个选择器，至少16个新种子族换边；与生产教师基线打同一对手赛程，预注册成本上限和族级配对得分差的95%区间方法，要求区间下界大于0且规则/暂停无退化 | 完成赛程本身不通过；偶发1胜或局长增加不晋级；证据不足不在同批种子调参后自称盲测 |
| 学习排序器      | 在未训练族降低有结果依据的排序损失，并保留已验证的整局收益或在相同成本下提高结果                                                                    | 停止扩大网络；检查目标、覆盖和特征                                              |
| 自对弈扩量      | 学到的模块实际参与选招，冻结策略加搜索有收益，下一代在新族上保留收益；计算预算与对手口径匹配                                                        | 不降低晋级门槛让流水线继续运转                                                  |

开发阶段的32根和8族不足以给出强统计结论。最终比较以种子族为独立单位；成对换边不是独立加倍。先用小试验排除没有信号的路线，再为有信号的一种方法增加检验样本，避免又把七种方法各跑一遍长赛程。

整局对手包含easy40和固定生产教师，两种赛程分别报告。预注册时同时固定最大样本数及区间计算方法；16族只是起始规模，不保证能达到统计门槛。未决局保留未知并报告得分差的上下界敏感性，不能按平局造标签，也不能只删掉长局后宣布通过。若准备分批检验，先固定相应序贯规则，不能反复查看普通95%区间直到偶然通过。

部署时的目标是相同实际工作量或可接受延迟下超过现有生产AI；超过当前很弱的学生只是中间检查。离线生成标签可以多算，但不能将多算带来的优势伪装成相同成本的算法优势。

## 本轮结论与交付边界

最有希望的转向是**由“从少量整局学会独立下棋”转为“在已有可执行策略上，学会有证据的局部改进”**。它把候选、排序、对手回应和执行兑现变成可分别验证的环节，也给出明确的失败出口。

本轮确认了停滞证据，并补算候选召回；尚未证明新选择器能赢棋。本方案的第一交付应是上述无训练的反事实比较结果，而不是新的模型检查点、架构模块或一晚运行日志。现有发行AI、规则、历史回放和模型保持不变。

## 后续执行结论：成本通过，尚不能训练
