# 随机与不完全信息游戏：无人工棋谱路线的证据审查

核查日期：2026-09-26。目标仍是“浏览器端侧运行，神经网络结合搜索，对强人类胜率超过50%”。本轮阅读原论文、作者代码和官方比赛资料；没有复现这些训练，也没有产生新的浩劫棋力结果。

## 结论与对前一方案的修正

有成功先例，不能由随机性推导出神经网络几乎不可能学会策略。但是，“存在成功先例”和“浩劫能在现有资源下完成”之间仍缺少关键证据。

前一份 [DATASET-FIRST-2026-09-26.md](DATASET-FIRST-2026-09-26.md) 没有解决强标注器从哪里来的问题。若标注仍依赖现有弱教师的判断，增加清洗步骤并没有建立可靠的策略改进来源。该提案不能继续作为已经找到的破局方案。

更值得研究的参照是：DouZero 的开放训练闭环、ByteRL 的多阶段随机卡牌学习，以及 Ataraxos 将快速自对弈训练与部署搜索分开的方式。这不是认定某个方法已经适合浩劫。

LoCM 是本次找到的、机制上最接近浩劫的研究环境：随机牌库、不同能力的单位、连续出牌和攻击、对手隐藏手牌。但其效果本身是确定的，随机性主要来自抽牌及未知牌库；规则也刻意比商业卡牌游戏简单。浩劫的空间走位、随机技能、反应与回合外行动增加了迁移差异。[官方环境与比赛说明](https://legendsofcodeandmagic.com/COG22/)

Stratego 的隐藏部署与推断适合参考空间策略和不完全信息；它没有浩劫那样持续随机抽取新单位的过程。不能把这些不同类型的不确定性混为一谈。

## 可核对的训练闭环

### DouZero：没有先造一个强标注器

随机发牌 → 当前网络对合法“状态＋动作”打分并保留探索 → 三个角色完成对局 → 按角色把实际终局收益写入访问过的样本 → 回归动作价值 → 将更新后的网络交给采样进程 → 继续产生新对局。

作者代码可以直接核对：`utils.py` 在 `done` 后填充各角色的 `target_buf`；`dmc.py` 用预测值与收益的均方误差更新，再同步给采样模型。它没有先判断每步是否为专家好棋；现成规则程序和人类监督模型是评测基线，不是这个闭环的标签来源。[数据生成源码](https://github.com/kwai/DouZero/blob/main/douzero/dmc/utils.py)、[训练源码](https://github.com/kwai/DouZero/blob/main/douzero/dmc/dmc.py)

[作者仓库](https://github.com/kwai/DouZero) 提供环境、训练、模型与评测入口，可用来审查真实数据流；其说明也记录了 Windows 下 CUDA 多进程限制。代码可获取不等于本地已经复现。

### ByteRL：跨阶段优化最终胜负

随机卡池 → 共享卡牌表示的组牌/战斗网络 → 终局奖励与 V-Trace 更新 → 对当前及历史策略继续训练 → 独立比赛。论文4.5节的搜索采样优势随训练缩小，最终未采用；不能推广成“训练搜索永远无用”。[方法与消融](https://arxiv.org/html/2303.04096)

### Ataraxos：训练与实战分配不同计算量

部署网络与走棋网络产生自对弈 → 用多步回报及优势估计学习，并控制策略更新稳定性 → 从自生成数据学习隐藏棋子分布 → 实战采样可能局面，进行续弈搜索，改进当前动作选择。

[论文2.3—2.6节](https://arxiv.org/html/2511.07312)；[公开实现](https://github.com/AtaraxosAI/stratego) 包含策略、信念训练入口、CUDA引擎和预训练目录，本轮未运行。

### ReBeL：算法求解不等于固定专家模仿

其循环在公共信念状态上构建有限深子博弈，用网络估计叶子，迭代求解策略，再把求解结果作为训练目标。搜索和网络共同更新，因此不要求事先存在一个已经会打败人类的传统教师。[论文第5节](https://arxiv.org/html/2007.13544)

对浩劫的含义是：自动监督不必来自固定强AI。但设计一个有效的策略改进算法仍然很难，不能用“搜索自动标注”几个字省略这项工作。

## 运气问题与数据筛选

终局胜负不是“这局每步都是好棋/坏棋”的真值。它是当前策略、对手及随机环境共同产生的一次收益观测。学习目标可以是给定可见局面和动作后的期望收益：

`Q(s, a) = E[最终收益 | 可见局面 s，动作 a，后续双方策略]`

已经抽出的棋子应成为条件的一部分；未来未知抽取需要对其分布取期望。即使某步把胜率从20%提高到30%，实际仍有很大概率输掉。这增加了估计方差和样本需求，却不意味着期望收益中没有策略信号。反过来，若动作对结局几乎没有影响，任何学习法都不能凭空制造可利用的优势；浩劫在强人类附近还剩多少这种优势，目前没有测量。

这里的统计解释不是神经网络必然收敛的保证。少量高度相关轨迹、探索不足、只见弱对手及长时间不能终局，都可能令学习失败。多次回归同一局的几千步不会增加几千次独立胜负信息。

[DouZero+](https://arxiv.org/html/2204.02558) 对初始牌力悬殊做了直接实验：另一个小网络预测开局胜率，逐步优先选择双方更接近的开局。它与策略同时训练，监督仍来自自对弈结果；开始不筛，随后提高筛选门槛。该模块只在开局工作，不负责下棋，也不是先写好的专家。它使用三家的初始手牌来选训练局，不把这些隐藏牌交给实际出牌策略。

这支持“采样分布可能是瓶颈”，没有证明浩劫清洗后就能成功。不能把意外失败删掉当脏数据：在不公平起手中少输、在优势起手中兑现优势也属于任务。若采用训练课程，最终仍须在原始规则分布、新随机局面及强对手上验收；过滤器预测的不确定性也必须保留。

## 不应被当作直接答案的结果

- **Suphx麻将**：五个模型先用人类棋谱监督训练，仅弃牌模型就有1500万个状态—动作样本，其他模型也使用大量数据；后续自对弈不是零人类数据起步。因而不满足这里的主要约束。[原论文4.1—4.2节](https://arxiv.org/html/2003.13590)
- **PerfectDou**：从自对弈学习，但训练价值网络看全局手牌，并用动态规划计算“最少出完手牌的步数”构造中间奖励，最后移除该奖励微调。880个CPU核、8张GPU；1260局熟练人类测试报告62.5%，其中是一个人类与两个AI混合组队/对抗，不能当作纯人类队伍测试。它说明局部可计算信号有价值，但浩劫尚没有经过验证的等价信号。[方法、附录D/E](https://arxiv.org/html/2203.16406)
- **AlphaHoldem**：确有端到端自对弈流程，但不能照抄摘要的强结论。正文对战的是 OpenStack 复现；人类测试10000手的收益为10.27±65.13毫大盲/手，95%区间跨零。本次据此只记为有竞争力，不能记为已证明战胜职业人类。训练用了65亿样本。[正文表3及实验设置](https://ojs.aaai.org/index.php/AAAI/article/view/20394/20153)
- **2026年LoCM搜索预印本**：报告对 ByteRL 的51.35%胜率，10000局、95%区间[50.37%,52.33%]。但它依赖现成亚军AI产生模仿数据，固定由ByteRL为双方组牌，且显存/内存和GPU部署条件不符合原竞赛全部限制。这正是“已经有强教师”才能走的支路，不能解决浩劫的冷启动问题。[原文训练与局限](https://arxiv.org/html/2609.06816)
- **LuckyJ麻将**：作者主页报告天凤十段，腾讯官方介绍自对弈。本次未取得足够的训练数据来源、完整方法和算力明细，不能仅凭报道把它列成可复制的全流程方案。“不到1500场到十段”是线上测试场数，不是训练量。[作者说明](https://haobofu.github.io/)、[腾讯介绍](https://www.tencent.com/en-us/articles/2201746.html)
- **PureTD，2026年预印本**：报告无需专家特征的双陆棋自对弈，最终约56.2万参数的模型可以不搜索执行；但最终含倍数方块模型经历约2亿局训练。其机器为64核工作站与至少24GB显存GPU，约65小时。小部署模型不等于便宜训练，也未证明浏览器或浩劫可迁移。[训练设置与结果](https://arxiv.org/html/2608.15146)

## 浩劫还欠缺的可行性证据

本会话之前对 `continuous-night-20260925` 的原始产物审计，统计到14份新轨迹、其中6个终局。它只是特定隔夜批次，不是全部历史训练量；不能与论文的全程训练量直接当作公平性能比较。不过它已经说明，当前流程获得独立终局经验的方式，与以上成功闭环相距很远。原始统计保存在 `artifacts/training/goal-reset-20260926/audit.json`，不是新训练结果。

决定是否值得继续的优先问题应当改成以下三个，而非再选择一个网络结构：

1. **采样经济性。** 去除昂贵教师和训练时搜索后，使用小网络直接行动，完整规则每小时能产生多少真实终局？成本应按完成对局、有效决策及实际时间计量，不能拿优化器每秒处理多少张量代替。
2. **策略学习是否发生。** 从随机初始化连续更新、产生新数据，能否在预先保留的随机局面和多个固定对手上形成可重复的进步？不要用实时自对弈的约50%胜率证明无进步或有进步，也不要让所有候选反复回到同一个父模型。失败时区分实现问题、终局太稀疏和资源不足。
3. **浏览器计算能否兑现棋力。** 学习成功后，网络及可选搜索的提升必须放在真实端侧预算下比较；服务器GPU搜索成绩不算交付。最终对强人类的验收仍需独立比赛，并预先固定先后手、规则、随机分布与统计方式。

若第一个问题无法在可承受成本内解决，就应明确判断当前资源不适合继续追求原目标，重新商定预算或目标。若能够解决，才值得做独立的新训练闭环原型。现有事实不支持承诺“再清洗一批数据、再训一晚就能突破”，也不足以宣布随机游戏AI在原理上不可行。

本轮交付为资料核查与路线修正；未运行上述论文复现、未启动新训练、未变更生产AI或发布模型。
