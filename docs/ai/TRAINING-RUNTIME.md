# 单 GPU 异步训练运行时设计

2026-10-29，实施前冻结。现有实现已提交为 `d2eb7a4`。本轮先完成以下整体设计，再实现全部运行时变化，正确性通过后才统一测量性能；不进行逐点性能试验。

## 范围与不变量

保留 5,503,366 参数网络、原生 BF16、来源→动作→参数的条件概率、64/16 搜索预算、随机消耗、渐进扩宽和转置语义。单局搜索仍串行执行模拟；并行来自独立对局，不引入虚拟损失或同时展开同一搜索树。保留三阶段预训练、历史池、奖励、50 ply 截断及 25% 完整局分配。规则与手工 AI 不改。

本轮改变的是请求生命周期、进程职责和供给规模。旧实现一个 worker 提交整组请求后整体阻塞，GPU 主循环兼任回放与协调，立即执行少量已就绪请求；共享内存无法解决这些依赖。

## 进程与所有权

| 角色            | 所有内容                                                 | 与其他角色的关系                                              |
| --------------- | -------------------------------------------------------- | ------------------------------------------------------------- |
| CPU 协调进程    | 对局分配、阶段、历史池、回放采样、学习额度、结果、检查点 | 不创建 CUDA 上下文；控制 actor 和 GPU，准备至多一个待学习批次 |
| CPU actor 池    | Rust 环境、手工 AI、逐局搜索生成器、轨迹写入             | 每局独立等待/就绪，直接向 GPU 发请求；某局等待时推进其他局    |
| 单 GPU 执行进程 | 学习模型、优化器、发布模型缓存、编码缓存、推理队列       | 独占 CUDA；跨 actor 组批推理，在批次边界执行已准备的学习任务  |

默认仍为 4 个 actor，但每个承载 16 局，共 64 个独立在途对局。CPU 进程数与在途局数分离；恢复旧检查点沿用原并发。新的默认值是实施前的供给设计，不在实现过程中按跑分逐点调参。

## 数据与请求协议

每局最多一个在途神经请求，携带 actor/lane、根命令、状态键、请求类型、模型引用和数组描述。每 lane 独占可复用共享内存，初始 256 KiB，按真实负载扩容；Pipe 只传控制和数组描述。actor 写入后交给 GPU，GPU 写回 BF16 位模式并通知后才交还 actor。不同 lane 的内存和完成通知互不阻塞。

actor 使用就绪队列推进生成器。规则/手工行动产生的事件通过独立协调 Pipe 发送，推理请求直接送 GPU。GPU 完成哪个 lane 就回复哪个 lane，取消整 worker 屏障。合法参数存在顺序依赖，仍逐级解码；其他对局填补等待期间的工作。

GPU 对所有 actor 的请求建立统一队列，按模型版本和 encode/decode 分组，组内按长度排序后组批，不再把相邻长度切成很多小桶。达到目标 batch 32 或最老请求等待 2 ms 时执行；等待有界，低负载和预训练收尾也能前进。每轮推理后允许一个已准备的学习批次，兼顾请求延迟与学习进度。CPU 协调进程在学习确认前不覆盖学习槽、不重复扣额度。

回放读取和抽样在 CPU 协调进程完成；学习批次同样经独占共享内存传递。GPU 内完成张量整理、BF16 前后向和 AdamW。模型发布与检查点是低频控制操作，可以短暂占用 GPU 服务；不把磁盘回放扫描放进每次推理路径。

## 模型版本与训练阶段

GPU 在一个新根首次请求时绑定当前发布版本，后续前缀/叶评估保持该版本。历史对手保留整局固定版本。换根时清理该 lane 的旧编码缓存。发布新权重不修改旧推理模型；回收时同时保护历史池、在途历史对局、当前根和检查点引用。

协调进程继续控制 collect→imitation→self。采集期间没有学习；示范全部自然结束后独立学习；最后一次模仿更新发布完成后再分配自对弈。学习批次及其元数据在提交时固定，GPU 返回更新、损失与采样计数，协调端随后提交额度、阶段和发布状态。

## 暂停、恢复与异常

保存时停止新分配和新学习，通知 actor 停止推进，收回所有在途 GPU 回复，再让 actor 写入命令边界快照。尚未执行完的搜索按现有根 RNG、模型版本和命令前环境保存，恢复时重算；不把搜索中间值伪装成正式轨迹。

actor 全部静止且学习确认后，取得 GPU 权重、优化器、随机状态及计数，再原子写入原有 v2 检查点。CPU 对局/回放 RNG 保留；检查点之后的文件继续按现行恢复规则处理。周期保存后可继续使用原进程；退出时先保存，再关闭 actor、GPU 和共享内存。

worker/GPU 错误上报给协调进程。失败局快照保留，其他 actor 停止；只有全部必要状态齐全才替换主检查点，已有可恢复检查点不被不完整快照覆盖。失败、截断和自然终局分别记录。

## 实施顺序与最终验收

1. 抽出共用 GPU 计算核心，保留数学与单进程测试入口。
2. 一起实现逐 lane IPC、actor 就绪队列、GPU 统一队列、CPU 协调/学习通道和模型生命周期。
3. 一起接通预训练、历史对手、边界软目标、暂停恢复及异常退出。
4. 正确性验证：既有测试；跨 lane 独立完成；根版本固定；BF16 学习；旧 v2 恢复；周期保存/停止恢复；真实终局和截断记录。
5. 全部实现后才测性能。保留 `d2eb7a4` 基线，使用相同模型、16 个中后期起点、固定搜索反馈、命令数和学习批次，比较完整流水线。额外以重复同一工作集比较旧/新运行时在 64 局供给下的表现，区分调度改造与供给规模。交错三轮，中位数报告总耗时、命令/秒、实际 batch、请求数、训练/真实价值样本数、学习时间与显存；最后做实际训练运行/恢复验收。

性能结果无论正负都保留；本轮不据单项结果再追加一串局部调参。全部结果写回状态入口。

## 实施结果

上述整体改造、14 项正确性测试、真实预训练阶段切换、旧 v2 恢复及周期保存已经完成。最后统一测量的完整结果见[状态入口](STATUS.md#整体架构性能验收)：新默认相对原默认吞吐提高约 61.7%，其中供给规模贡献较大；同为 64 局时架构独立提高约 7.5%，16 局负载下降约 36.3%。保留正负结果，测量后未继续局部调参。
