# 运行内核与双端对应

本轮替换内部表示与执行流程，规则版本、概率边界、候选次序、采样算法、模型输入协议和存档版本不变。冻结参照为 `d6df36f975fbddf785b318d7a280e266ccd1cfe0`。旧分支文档的复制/提交细节是历史实现约定，当前以本文为准。

## 表示与生命周期

运行局面与外部快照分开。外部进入 TS 拥有型运行器时复制一次，之后直接持有规则数据；Rust 的 State 从入口解析一次，连续采样不再经过 Observation Value → State。外部 applyCommand 成功仍导出独立快照：入口已整图隔离的数据直接移交并删除运行标记，共享分支则复制后导出，避免重复复制。非法或未知随机结果丢弃工作分支。

| 责任           | TS                                           | Rust                                        | 共同约束                                                |
| -------------- | -------------------------------------------- | ------------------------------------------- | ------------------------------------------------------- |
| 实体定位       | runtime/position 的 EntityHandle、槽与身份表 | core/entities 的 EntityHandle、EntityIndex  | 有序数组决定遍历；槽记录当前位置，不能缓存过期实体对象  |
| 热实体字段     | Unit 的已知类型与 copyUnit                   | UnitData、Charge、AbilityUsage、Effect      | 不把实体重新解析成 JSON；可选字段缺失保留原义           |
| 命令及节点     | Command、ActionSpec、类型化 Prefix/Choice    | CommandKind、Command、Action、Prefix/Choice | 内部构造直接进规则，外部未知输入仍校验                  |
| 图鉴与特征编号 | CATALOG、预编译种类/角色映射                 | Catalog::by_kind、kind_codes、vocab_codes   | Rust 数值来自同一嵌入规则包，不能复制另一份规则常量     |
| 公开只读视图   | publicPositionView / viewPosition            | public_view / PublicPosition                | 显式白名单与观察方；无权威根、正式 RNG 或未揭示对方暗选 |
| 类型化分支     | forkRuntimePosition、own                     | State::fork、Rc::make_mut、SharedFields     | 分支内写入隔离；成功由拥有型运行器接续，失败不提交      |
| 独立外部快照   | exportOwnedPosition / clonePosition          | State::clone                                | 调用者修改返回数据不能污染输入或其他分支                |
| 策略正式步进   | TrainingEnvironment::stepTyped               | boundary::step_typed                        | 跳过内部重复解析，仍检查操作者权限与完整规则            |
| 同步编码       | createSamplingEncoder                        | encode_sampling                             | 直接读公开类型；存在掩码、实体次序、模型维度不变        |

TS 使用普通对象的紧凑实体复制及冷字段的明确写入前分离，删除通用 Proxy 图。Rust 以每个类型化实体为 Rc 复制单元，首次可变借用再分离。两端均保留有序实体列表、独立工作分支和相同提交边界；提前复制与可变借用时复制是所有权机制的差别，不改变规则或查询流程。TS 首版逐字段访问描述符经实验明显变慢，已经删除。

手牌、亡者、反应、光环、延迟效果和时钟属于冷数据或历史数据，读取不应触发复制。TS 的 own 必须在修改这些集合及其内容前调用；直接替换整个集合已获得新所有权。时钟帧中的实体快照不被后续结算原位修改。Rust 反应源和时钟帧已直接保存类型化快照，不再序列化/反序列化 Unit。新字段必须明确属于热实体、冷可变集合、历史快照或外部信息，不能默认为可共享可变对象。

JS 外部调用者可能提供别名、环或非普通对象。TS 在导入边界识别后走明确的整图复制兼容路径，保持已有别名语义；正常运行内核不会每步重测整图。公开 JSON 和 Rust 入口不具有 JS 对象身份。

实体表按分支共享布局，结构变化时重建；同长度替换和时钟原位替换还核对槽中的实际 ID。缺失身份只在数组中确实出现时触发修复，不能因基地或死亡来源查询反复分配整张表。句柄只属于当前运行环境，不写入存档或跨对局复用。

## 查询、分支与结算

一次决策的公开视图、动作树、来源准备、属性与空间查询共同存活；下一局面必须创建新的决策上下文。缓存不跨状态失效边界。动作树仍按原顺序惰性展开，选择失败后的回溯、4096 节点预算、策略随机源以及正式 RNG 相互独立。

移动用单来源可达场保存深度和前驱，多个落点直接读同一结果；需要真实路径时才重建。攻击广搜用棋盘数字索引、深度、前驱及访问位，保留向下、向上、向右、向左的搜索次序、最短路径和正面优先规则。方向/落点候选不因重写而排序、裁剪或换成近似几何判断。显式穿透路径和复杂技能仍进行原有精确检查。

攻击预检产生的准备结果直接进入同次模拟结算，避免再算一次属性和攻击路径。准备结果不可跨正式状态复用。随机攻击、伤害、死亡、反伤、反应、复活、生成实体、召唤、部署、法术、合成、神龛和个人/全局时钟都由同一个工作分支继续处理；没有切换回旧 JSON State 的适配层。

| ------------------------ | --------------------------------------- | ----------------------------------- |
| 移动、冲撞与反应         | commands/movement、combat               | commands/movement、reactions        |
| 攻击、逐份伤害、死亡连锁 | commands/combat                         | commands/combat、damage             |
| 召唤、部署、装备、资源   | commands/game、abilities、setup/shrines | commands/preparation、setup/shrines |
| 技能、复活、法术与反制   | commands/abilities                      | commands/abilities、spells          |
| 合成、神龛与时钟恢复     | setup/synthesis、shrines                | setup/synthesis、shrines            |
| 回合时钟与持续状态       | commands/lifecycle、core/state          | commands/lifecycle、core/resolution |

## 编码与外部边界

热实体、效果、反应源、时钟快照和候选命令直接写数值行；避免临时字段数组、全实体 Value 和线性类别搜索。少量低频记录字段继续无损保留在动态扩展数据中，它们不是每步权威状态与公开 JSON 往返。现有固定行与 TinyPolicy 投影复用来自基线，不计作本轮成果。

传输仍是现有二进制张量协议。原生宿主复用发送字节缓冲，完成同步写入才允许下一次覆盖；Python 解码继续拥有独立张量。状态/记录哈希仍使用既有规范编码；类型化序列化改变 JSON 键的书写顺序时，规范哈希必须相等。TS 旧存档指纹和历史轨迹不改写。

## 诊断与维护

`kernel-profile` 是独立 Cargo feature；默认构建没有这些计时或分配探针。它记录嵌套独占/包含时间，以及分配次数、累计申请字节、释放次数、累计释放字节。18 个分项包括状态导入/导出、公开视图、候选、规则准备、属性、路径、分支、实体复制、预检模拟、正式结算、编码、哈希、协议和固定策略计算。累计申请量不等于驻留峰值或实际拷贝字节；包含时间也不能相加。正式倍率只来自无探针的预热、交错测量。

引擎工作层仍执行真实候选树、预检、正式结算和编码，固定 TinyPolicy 计算另有计时。完整应用层固定实际 PyTorch 检查点、种子、预算与并发；独立审核与准备阶段的再次审核都计费。模型等待与前向时间有重叠，不能相加后冒充总成本。

新增规则或状态字段后须更新对应类型、分离策略、公开白名单和编码覆盖；至少检查非法失败、概率边界、反应顺序、同长度实体替换、快照独立性与连续运行。复现入口和实测结果见 [任务记录](README.md)。
