# TS / Rust 共用算法优化探索

## 目标与当前边界

起点为 `859cb27`。最终目标仍为浏览器端侧神经网络＋搜索对强人类胜率超过50%，累计训练预算30天、允许中断。本轮先探索候选生成和公开预检如何减少重复工作，不启动训练、不改变策略、候选范围或规则。

浏览器继续使用TS。两端应共享查询分层、参数顺序、准备条件与差分契约；语言的数据表示可以不同。先前归因中的Rust动态JSON和拥有型对象复制确实存在，但它不能替代对共用算法的优化。

所有试验实现放在忽略目录 `artifacts/training/shared-algorithm-20260927/`，正式 `src/`、`scripts/`、`native/` 和发行HTML未修改。每个方案从基线单独复制，冻结依赖图或release二进制，再做对照；组合试验单列，不能把各项倍率相乘。

## 假设与筛查

按以下四个可证伪方向探索：

1. 同一观察的属性查询重复，限定在不可变查询批次的缓存应减少计算。
2. 参数节点重复编码局面，固定部分只编码一次应减少分配；前缀与引用编号仍逐节点处理。
3. 参数的公共准备被每个候选重复执行，批量准备应减少无效检查与临时棋子复制。
4. 同一完整命令被多次预检，结果缓存应消除重复试执行。

诊断探针对原来的经典/神龛各1000条命令计数，节点、张量、logits、实际命令和工作量均与无探针版本相同。TS的完整引擎预检入口分别为96156/105659次，其中严格相同命令重复1595/2261次，约1.66%/2.14%。计数键包括字段顺序及显式默认值；语义相同但表示不同的命令未归并。TS和上一份Rust归因的入口边界不同，不拿计数差额当作规则差异。

经典39429次、神龛44928次移动预检中，仅各1018次进入完整副本结算；其余分别38411/43910次在准备阶段拒绝。这里已经避开整局复制，却仍为117个落点反复寻找操作者、投影模式、检查预算与构造错误。盯住整局深复制会漏掉这一层成本。

32根首筛后，扩大到原经济性试采的经典/神龛、tiny/uniform四份worker-0轨迹，均匀选择128个公开局面。各方案使用同一固定小网络和策略随机流，预热后交错三轮，墙钟不参与选招。基线访问1320个参数节点、343次网络评估、1076次回溯；各方案均保持不变。

| 单项隔离方案                 | 基线耗时 | 方案耗时 |  倍率 | 初步判断                          |
| ---------------------------- | -------: | -------: | ----: | --------------------------------- |
| 属性查询缓存                 |   2.065s |   1.945s | 1.06× | 小收益，先不引入通用缓存层        |
| 固定局面编码复用             |   2.065s |   1.912s | 1.08× | 有收益，可作为参数解码的局部优化  |
| 完整命令预检缓存             |   2.065s |   1.964s | 1.05× | 首筛约1.01×，命中率低，优先级靠后 |
| 最后参数层的公共条件提前检查 |   2.065s |   1.819s | 1.14× | 对无效复活记录等整批失败情况有效  |
| 移动落点批量准备             |   2.065s |   1.709s | 1.21× | 当前最值得先实施的单项            |

全部访问节点的候选内容与顺序、完整网络张量、logits和选招逐项序列化摘要一致，观察输入未修改。这里只覆盖实际访问节点，不声称遍历完整动作空间。桌面负载/频率未锁定，约5%的差异不作为可靠的大幅收益。

## 应怎样共享算法

### 先准备一次，再检查一批参数

当前移动大致为每格分别执行“找棋子→检查动作资格→计算预算→判断落点→必要时模拟”。隔离实现把前三项移到批次外，再按原有117格顺序判断落点；通过者仍进入完整预检，处理冲撞死亡、反应或能否离开占位等后续条件。

TS正式单条准备和批量落点查询调用同一个准备函数；Rust采用相同分层，普通移动和冲撞分别复用原来的准备条件。没有在训练层另写移动距离、占位或技能数值。

复活则把“选中的亡者是否仍可复活”与“落点是否合法”分开。失效亡者的117个点必然全部失败，可以在该落点节点一次返回空集合；**上一级亡者候选和空节点的访问仍保留**，维持网络输入、Gumbel抽样次数和回溯顺序。这不是把无效亡者从上一级策略候选中删掉。

公共条件探针使用读取未绑定坐标时中断的访问器，仅用于验证潜在收益。正式实现应抽取明确的准备结果，复用引擎规则函数，不把访问器/代理式部分执行器引入产品。

### 编码只复用固定部分

Observation固定时，主体实体、附属状态及主身份表不变，但动作前缀、前缀参数实体、部分引用编号和全局的前缀存在标志会变化。试验为每次采样懒构造一个基础编码，每个节点复制引用编号并追加前缀；不能缓存整份 `encodeDecision`，也不能让上个前缀注册的新ID污染下个前缀。

TinyPolicy的固定实体投影也有进一步复用的可能，但这依赖模型结构和权重不变，本轮未实施。不能推定正式Transformer中包含上下文注意力的实体输出也可以同样缓存。

### 后续几何优化复用现有边界

TS已有 `createPlacementQuery`，在不可变局面中复用占位、阵营、独行侠及部署行查询；当前训练预检未共用它。批量准备后可以单独评估接入收益。单源可达图也有可能代替逐终点广搜，但须保留分数移动的上取整边界、直线移动、2×2、地标、冲撞和路径顺序。当前原型仍调用原来的寻路，不把尚未测试的广搜复用计入收益。

## 连续采样与跨语言验证

经典/神龛分别从原种子连续选招1000条命令，预热后三轮交错。TS使用冻结的esbuild依赖图，Rust使用冻结的release二进制；只比较同一后端在本轮的改动前后，不能与旧报告绝对耗时相除后重新声称语言倍率。

| 同后端对照，三轮中位数       |                经典 |                 神龛 |
| ---------------------------- | ------------------: | -------------------: |
| TS：仅移动批量准备           | 8.542→6.768s，1.26× | 10.339→8.915s，1.16× |
| TS：移动＋公共条件＋基础编码 | 8.542→6.093s，1.40× | 10.339→8.161s，1.27× |
| Rust：仅移动批量准备         | 5.115→4.867s，1.05× |  7.525→7.320s，1.03× |

TS审核轮逐节点的候选、编码和logits摘要全部一致；所有计时轮的实际命令、8项工作量计数、权威终态及双方公开观察一致。Rust也逐条核对原来经过共享读取器审核的TS轨迹与终态。经典保持4400节点/1906次评估，神龛保持5231节点/2004次评估；分别55/46 ply截断，`returns=null`。

计时包含创建新局、观察、候选、编码、小网络、抽样、结算及内存命令记录，Rust包含批次请求和最终导出；不含进程初始化、记录指纹、压缩落盘、回放核对或优化器。这里没有自然长局吞吐结论。

**算法可以共享，但收益比例不能共享。** 移动批量准备让TS连续采样提速1.16～1.26倍，Rust仅约3%～5%提速。Rust已有专门的移动属性查询，并使用Result返回失败，避免了TS反复构造RuleError的部分成本；两个原型都保留原寻路且大部分移动本已在复制前拒绝，无法消除主要的完整副本成本。约3%的差异不作为稳定的大收益承诺。

Rust移动隔离实现已通过86个专项、172个观察根、10492次预检与414个动作树节点的对照。预检状态/错误、专项实际终态、候选、编码及logits均与冻结原版Rust相同。此处是移动相关的有限验收，未重跑71955条完整历史规则差分。

追加单项把begin、跳过合成、结束神龛入场以及召唤的纯阶段/资源资格检查前移到完整复制之前。TS诊断中每1000命令分别有11705/11131次失败发生在复制之后；这次只处理其中上述五种命令，不把全部失败都假定为可提前判断。资格检查与正式执行共用函数，不在动作生成器复制规则。

| 复制前资格检查，另批三轮交错 |                经典 |                 神龛 |
| ---------------------------- | ------------------: | -------------------: |
| TS                           | 8.400→7.940s，1.06× | 10.476→9.837s，1.07× |
| Rust                         | 5.110→4.727s，1.08× |  7.556→6.903s，1.09× |

追加方案的候选、编码、logits、完整命令序列、8项工作量和最终状态继续相同，截断标签仍为null。Rust另通过570个专项、1140根、19390次预检及2335个节点，核对原版的状态/错误、专项终态、候选、张量和logits。该单项没有加入前述TS组合，因此不能把两张表倍率相乘；Rust也没有完整组合的实测。

这一结果支持先抽取低维护成本的只读准备：阶段/资源资格放在复制前，同一参数节点的公共准备只做一次。已验证的共享改动带来的是局部改善，当前证据没有支持Rust再快数倍的结论。Rust的公开JSON转换、实体编码和拥有型数据复制仍需按残余成本单独处理。

## 实施顺序与停止条件

| 阶段           | 目标                                      | 状态与通过条件                                                     |
| -------------- | ----------------------------------------- | ------------------------------------------------------------------ |
| 探索           | 单项隔离、访问路径等价、连续轨迹计时      | 已完成；正式实现未改                                               |
| 第一轮正式修改 | 两端共用阶段/资源准备与移动批量准备的分层 | 计划；保留原条件与顺序，候选/异常原子性/完整轨迹差分通过后逐项计时 |
| 第二轮         | 复活/牵引等参数公共准备，基础编码复用     | 每项独立计时；只保留超过波动且维护成本合理的方案                   |
| 后续候选       | 占位索引、单源可达查询                    | 先复用已有查询；无独立收益不继续扩展                               |
| 经济性复核     | 自然终局、并行扩展、记录出口和中断恢复    | 重新评估累计30天，不用1000步短段外推训练产能                       |

完整命令的大缓存不优先；约2%的严格重复不足以支持复杂的哈希/失效体系。用户追问后追加了[状态分支重构实验](STATE-SHARING-2026-09-27.md)，并明确双端算法必须一致、允许Node性能下降。早期独立原型的Rust 1.42～1.44倍、TS慢约23%不能用于各选不同方案；随后完成双端统一复制粒度和事务流程的原型，现已接入TS生产引擎和Rust原型。本文的查询/编码优化仍处于隔离探索阶段。正式修改必须双端对应，性能退步不构成保留算法分叉的理由。撤销日志仍未验证。提前裁剪上一级参数域、只检查抽中的候选、修改候选特征或解码预算属于策略协议变化，需要另立实验，不能混进本轮等价加速。

## 证据和复现

隔离目录包含 `baseline/stats/encoding/memo/prefix/moves/combined/guards` 的TS源码副本、冻结 `.mjs` 与来源哈希；`native-moves/native-guards` 为Rust源码副本。原始记录只读，输出排他创建。目录由 `.gitignore` 排除，不是正式发布源码；文档纳入版本管理，实验原始证据留本机。

- `screening/`：32根首筛；带探针版本的耗时不计为优化收益。
- `roots-128/`：128根的独立方案三轮对照及一致性摘要。
- `game-profile/`：1000命令的分类计数；没有计时轮，汇总中的空计时/空倍率不构成性能结果。
- `native-validation/`：移动专项规则与候选差分、冻结二进制及来源哈希。
- `games-1000/`：连续TS采样的单项/组合对照。
- `native-games-1000/`：Rust批量移动的单项连续采样对照。
- `guards-validation/`：复制前资格检查的Rust专项对照。
- `guard-games-1000/`、`native-guard-games-1000/`：资格检查的TS/Rust各自三轮连续采样对照。

复测使用新输出名，不覆盖现有报告：

```powershell
node --import tsx artifacts/training/shared-algorithm-20260927/explore.ts --variants baseline,stats,encoding,memo,prefix,moves --output roots-recheck --cases 128 --rounds 3
node --import tsx artifacts/training/shared-algorithm-20260927/explore.ts --variants baseline,moves,combined --output games-recheck --games --rounds 3
node --import tsx artifacts/training/shared-algorithm-20260927/native.ts --output native-recheck --rounds 3
node --import tsx artifacts/training/shared-algorithm-20260927/explore.ts --variants baseline,guards --output guards-recheck --games --rounds 3
node --import tsx artifacts/training/shared-algorithm-20260927/native.ts --output native-guards-recheck --candidate guards --executable artifacts/native-guards-target/release/haojie-engine-prototype.exe --rounds 3
```

Rust复测使用的候选可执行文件由 `native-moves/Cargo.toml`、`native-guards/Cargo.toml` 以release、thin LTO及单codegen单元分别构建到 `artifacts/native-algorithm-target`、`artifacts/native-guards-target`；源码和二进制均保留。第一版Rust驱动另存为 `native-moves-driver.ts`，对应早期报告中的驱动哈希。

基础编码和公共条件组合目前只做了TS隔离原型；不能把组合的TS倍率称作已验证的Rust组合收益。本节查询/编码探索当时未改正式源码，也未重复生产行为测试、完整历史回放或离线浏览器验收；上述差分仅是探索验收，进入正式修改后仍需执行项目完整要求。后续状态分支接入的生产验收另见对应文档。本轮没有训练或棋力验收。
