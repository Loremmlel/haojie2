## 第二阶段预登记

第一阶段冻结提交 `3dc4e54`，Linux纯训练包二进制另存 `/work/phase1-engine`，Python包为source-v3。使用同一恢复权重 `3c35b5...2375c3`、CPU FP32/单前向线程，经典731270033、神龛741270037从开局各12000命令/500ply，1800秒整组保护；不得换种子、补终局或省去记录/审核/准备。先完整预热/诊断，再做三轮交错计时；测量期间不运行编译或回归。PID命名空间100ms采样RSS，记录自身与已等待子进程CPU，模型加载/进程建立包含在完整账中。

候选主方案：当前批处理每轮等待所有环境都抵达下一个模型节点，快环境会被其他环境的长查询阻塞。改为保持每环境最多一个在途请求，收到首个请求后合并已经就绪的请求一起前向，其他环境继续查询。不增加环境数量或模型预算，不插入时间相关的策略选择。TS可以使用Promise、待处理Map和普通队列实现同一调度；它不需要指针、共享内存或特殊容器，不属于Rust算法分叉。批量形状变化的FP32前向预声明绝对容差1e-6，必须同时验证命令路径、候选工作量和规则随机结果，不能用容差掩盖换轨迹。

次要候选：记录中已计算的上一after哈希可作为下一before哈希。TS对象与Rust状态均有明确提交边界，可以共同实施；先以成本账判断是否值得做，不与主方案混合归因。已有固定编码、只读准备、状态分支和失败的前驱队列/跨决策Tiny缓存不再重试。

## 成本口径与范围

设备为 Ryzen 7 5800H（8核16线程），WSL2 Ubuntu24.04 / Linux5.15.133.1，隔离根可用内存约7.76GiB；Python3.12.3、PyTorch2.14.0+cpu、Rust1.98.1。CPU前向为1线程。基线与候选使用同一个151938参数的实际恢复检查点，不是固定TinyPolicy；结论不外推至默认11.7M模型或GPU吞吐。每组1800秒上限，不运行隔夜扩训。

自然局为经典731270033和神龛741270037，从开局分别实际执行7784、3502条命令至规则终局；199713个树节点、34810次模型请求。混合切片为原冻结自然轨迹的0/1000/3000/末20命令前缀，经典与神龛共8个环境，每环境32条新命令；晚盘可提前终局。它用于开中晚盘并发差异，不能当成自然局吞吐。原始记录逐字节比较同时约束路径、正式状态哈希、策略随机状态、模型版本和结局。

完整成本账包含模型/进程创建、采样与写原始记录、一次独立审核、准备中的再次审核及编码/分片、加载、两步AdamW和全验证集损失评估。两次审核没有因优化而减少；实际只执行prepare也会完整审核，但此处没有扣掉独立验收的成本。模型棋力评测不在此成本账中；新权重确实参与有限终局采样，但不声称战胜任何对手。

Rust的treeMs包含查询与分支，inferenceMs是发出公开张量至收到logits的等待，包含Python前向及传输；不能把它与Python前向时间相加。树内复制、张量序列化和管道传输尚未逐项拆开，不能据节点数或总等待时间虚构占比。recordMs包含规范状态哈希及写盘。测量峰值为独立PID命名空间100ms采样RSS，并非连续精确峰值；所有并发进程均为本组自有进程。
