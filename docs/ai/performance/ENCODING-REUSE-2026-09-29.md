# 公开局面固定编码复用

## 范围与冻结基线

本轮从 `db9beb0597cd9563b987bceb4b2c553636f6173e` 开始，在独立分支 `perf/sampling-context-20260929` 验证一个切片：同一公开观察的固定编码复用。没有训练网络、修改规则、改变搜索或候选生成、修改状态复制策略，也没有部署或合并 main。

本机为 WSL2 Linux x86_64、Intel Core Ultra 5 225H、Node 22.23.2、Rust/Cargo 1.98.1。TS 用现有 `performance/compare.ts` 冻结 esbuild 依赖图，目标 `node22`；Rust 用 `cargo build --release --locked`，保留 `lto = "thin"`、`codegen-units = 1` 和原 Cargo.lock。桌面负载与频率未锁定。

产物根目录为 `artifacts/training/sampling-20260929/`。`baseline.tar` 保存本轮 HEAD，`baseline-frozen/api.mjs` 是冻结 TS 参照，`native-baseline-v2/engine.exe` 是 Linux 原生参照（扩展名沿用冻结工具）。此前两个冻结失败目录原样保留：Node 子进程读取 Git HEAD 在沙箱内返回 EPERM，随后经授权重跑，失败目录不用于计时。

## 当前测量和选择依据

先以 TinyPolicy 固定初始化 73129、原采样随机流，原生重新采样两局；上限各 12000 命令、500 ply。经典种子 731270001 在 4591 命令/171 ply 自然终局，神龛种子 741270001 在 8679 命令/257 ply 自然终局。两局全部命令经当前基线 TS 正式执行，最终权威状态及双方公开观察相等。

从每局取固定命令位置 0/10/50/100/250/500/750/1000、全局 16 个等距位置，并补充棋子数加亡者数最大的局面，共 50 个公开观察。经典覆盖 ply 1–166，神龛覆盖 ply 0–250；补充复杂局面为 64/85 枚棋子加 240 条亡者记录。不会只用开局 1000 条命令代表长局。工作集哈希：`9e252c4d49467eaf8b6b71ba703bd44e8cf4a3881273b83a630b5f91a984119d`。

无诊断探针的首轮原生长局中，经典动作树/编码耗时约 15.22/8.07 s，神龛约 39.00/25.19 s；这只是选热点的分项测量，不是前后对照倍率。

当前 50 局面采样诊断发现：

| 环节                   | 次数 | 明确非法 | 诊断分项耗时 |
| ---------------------- | ---: | -------: | -----------: |
| 移动预检               | 5733 |     5688 |       108 ms |
| 攻击预检               | 5967 |     5893 |       121 ms |
| 完整编码（无探针首测） |  245 |   不适用 |       207 ms |

诊断探针与无探针版本的选招及离散工作量相同；探针耗时不用来计算加速倍率。重复非法参数确实存在，但本轮固定编码是较大的独立准备成本，又可以避开规则准备/错误顺序的改动，因此只实现这一项。没有同时接入移动批量准备、技能过滤或属性缓存。

## 等价边界和双端算法对应

这是 **A 类等价优化**。既有参数域、候选顺序、前缀、编码词表、完整命令、回溯和策略随机数消耗不变，协议无需升级。不能把原有带回溯的 Gumbel 排序采样解释成完整命令的简单 softmax；本轮没有引入或重新声称任何这样的概率公式。

| 环节     | TS                                             | Rust                               | 共同约束                                                                        |
| -------- | ---------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------- |
| 生命周期 | `sampleCommand` 创建 `createDecisionEncoder`   | 每个 `Tree` 拥有 `OnceCell`        | 仅在同一不可变公开观察和观察方内复用，回合外观察单独创建                        |
| 固定准备 | `encodeBasePosition`                           | `encode_base`                      | 首个需推理节点才构造，执行原公开字段/隐私校验、固定实体、属性、身份表和全局编码 |
| 节点隔离 | `positionRows` 复制每行及两张索引表            | `Encoder` 克隆固定张量及两张索引表 | 上一个前缀或候选新增的身份编号不能污染下一个节点                                |
| 节点追加 | 原前缀、候选编码逻辑                           | 原前缀、候选编码逻辑               | 顺序、存在掩码、引用和 Float32 策略计算保持；全局第 31 项仍表示前缀存在性       |
| 单次入口 | `encodePosition` / `encodeDecision` 经同一实现 | `encoding::encode` 经同一实现      | 没有长期保留第二套旧算法，冻结旧版只供测试                                      |

没有缓存策略网络输出，也没有假设正式注意力网络可复用实体隐层。返回的数组和身份表独立拥有，调用者修改返回值不会改写缓存。批次契约与原动作树相同：调用期间不得修改观察；新局面或新观察方须新建编码器。失败的前缀编码不能污染下一次调用。私有 seed/rng/Session 与神龛暗选仍在原边界被拒绝。

每个活跃树会多保留一份固定编码，节点结果仍复制以保证独立性。本轮没有测峰值存活内存，不能把少做编码直接表述为内存占用同比下降。

## 同口径性能

50 个固定局面使用原小网络和 `982451653 + caseIndex` 的策略随机流，预热后按旧→新、新→旧、旧→新交错三轮。计时期间没有并行编译、回归或其他实验。

| TS 固定局面，三轮中位数 |       基线 |    复用后 |
| ----------------------- | ---------: | --------: |
| 总采样                  | 1021.69 ms | 896.06 ms |
| 动作树                  |  630.18 ms | 634.78 ms |
| 编码                    |  178.81 ms |  51.90 ms |
| TinyPolicy 前向         |  211.43 ms | 204.89 ms |
| Gumbel 排序             |    1.06 ms |   0.95 ms |

总采样为 **1.14×**，耗时减少约 12.3%；三轮各自为 1.173/1.154/1.135×。各分项分别取中位数，不要求相加等于总时间。双方均为 1351 个节点、245 次网络评估、11 个强制节点、1248 次回溯、最大 433 实体/112 候选，所有固定种子选招相同。此计时包括动作树、完整编码、前向和采样；不含创建权威新局、正式执行、观察复制、记录、写盘或复核。

原生另通过现有 `training-nodes` 协议请求相同 50 个观察和冻结的 1351 个访问游标。该诊断入口编码全部非空节点，因此有 256 次编码（含采样时免推理的 11 个强制节点）、3625 个候选行、累计 77435 个实体行；旧/新输出序列化摘要完全一致。

| Rust 固定节点批次 |       基线 |    复用后 |
| ----------------- | ---------: | --------: |
| 第 1 轮，旧→新    | 1008.88 ms | 992.04 ms |
| 第 2 轮，新→旧    | 1124.23 ms | 839.07 ms |
| 第 3 轮，旧→新    |  984.80 ms | 900.14 ms |
| 中位数            | 1008.88 ms | 900.14 ms |

该口径约 **1.12×**，包括 50 次请求的 JSON/IPC、动作树、编码、前向及大张量返回/解析，排除进程初始化、工作集读取和结果摘要校验。逐轮波动明显，不将它当纯原生核心倍率，也不与 TS 固定采样时间相除；它还编码了强制节点，工作口径不同。

## 验收范围和剩余成本

编码是本轮唯一变化，规则和动作树生成逻辑保持不变。已完成以下独立验收：

- 冻结旧 TS 对照：1101 夹具、32135 次预检及正式执行逐项相等，其中 21824 次预检非法、562 次遇未知随机边界；逐命令核对输入不变。2202 个双方观察根、5343 节点、3027 份完整张量及 logits 相同，检查 22833 个叶子出现项（含 582 个 `uncertain`），并对原生/继承/冻结/保护/最后生命条件下的牵引、巨大化、复活及相关反应共 38 个根穷尽有限参数分支。完整命令和参数语义以旧叶子及正式执行为参照，不仅回放被选成功命令。
- 固定 50 局面额外核对策略随机流：3614 次调用及下一随机值相等，固定种子选招相同。
- 当前 TS/Rust 差分：2202 根/5376 节点（包括专项成功命令的深层路径），完整编码与 logits 最大误差均为 0；四项隐私/未知字段拒绝通过。这个驱动与旧版差分的游标范围不同，不用节点数量宣称覆盖增减。
- 规则双端差分：1101 夹具，10394 次成功结算、22515 次非法命令、58517 次预检，`unsupported` 为空；驻留协议的错误/版本及失败原子性检查通过。
- 完整采样兼容出口：当前 TS 与 Rust 各自从冻结种子独立走完经典 4591 命令/171 ply、神龛 8679 命令/257 ply，两局都为自然终局。全部命令、八项工作量、完整权威终态及双方观察一致；两份正式 `.jsonl.gz` 通过共享读取器的指纹/权限/标签审核。该单轮只作功能验证，不以其 TS/Rust 绝对时间推导语言倍率。
- 406 项 TS 行为测试通过，含新增返回张量/身份表修改隔离、前缀顺序交换、异常后继续编码、新观察/观察方隔离和非法输入拒绝。Rust 2 项单测、release 构建、Clippy 零警告、格式、TS 类型、全仓格式、目录检查通过。
- 单 HTML 构建 833324 字节，`deploy:check` 与根 `index.html` 字节相同；实际离线 `file://` 浏览器 35 项通过，含存档恢复、悔棋/重做、手机和键盘操作，无外部请求或未捕获错误。仅在 `/tmp` 解包 Chromium 缺少的 `libnspr4/libnss3`，按授权在沙箱外启动原测试，没有改变浏览器管理策略。
- Python 回归未通过环境入口：6 个测试模块均因缺少 `torch` 导入失败，没有运行功能测试。本轮未修改 Python 代码、编码词表或张量协议，不将缺失依赖当作验证通过，也没有启动训练。

覆盖缺口：没有穷尽任意路径、全部材料排列与所有规则状态组合，没有本机缺失的 32 份旧历史轨迹/71955 命令。有限参数族穷尽和长局一致性不能替代上述全空间证明。

纯采样倍率不能当完整训练倍率。正式训练记录指纹、TS 兼容重放、压缩写盘、数据读取/张量准备、网络训练与优化器、批量推理、并行吞吐和中断恢复均需要各自计时或验证。本轮不会启动这些后续研究，也不会叠乘历史 Rust/Node 或状态共享倍率。

本轮兼容出口验收从冻结清单写入到报告写入约 523.28 s；四次 TS/Rust 采样计时合计 368.88 s，剩余约 154.40 s 包括进程初始化、TS 多遍参照重放、正式记录指纹、压缩写盘、共享读取器审核、断言和报告等。这个差额没有进一步归因，不能全记为写盘，也不是单遍训练采样器的耗时。它说明被核心采样计时排除的成本实际存在。

墙钟预算：从首次采样 `2026-09-29 07:21:31.968 UTC` 到最后验收和证据冻结 `08:01:10.043 UTC`，保守总跨度 **39.64 分钟**；连实现、等待和中间回归都计入仍低于 60 分钟。原生计时期间不运行编译或回归。集中工程回归约 4 分钟（含环境补齐/授权等待），其中 406 项行为测试 9.92 s、冻结旧版差分进程约 20.18 s；这些回归计时不用于性能倍率。没有追加种子、第二个热点或训练任务。

## 复现与取舍

保留本地产物，不覆盖既有输出目录：

- `collect.ts`、`native-baseline-v2/`：有界两局采样、TS 正式重放和固定公开工作集；不是训练用快照轨迹。
- `diagnose.mjs`、`diagnostic.mjs`、`diagnosis.json`：隔离的预检计数探针及与无探针选招/工作量对照，未进入生产代码。
- `baseline-frozen/`、`ts-paired/`：旧/新 TS 依赖图、源文件指纹和三轮完整分项。
- `native-paired/`：冻结新二进制、全部源码哈希、预热及三轮自然局原始分项。
- `audit.ts`、`audit.json`、`node-workset.json`：冻结旧版规则/候选/编码差分、有限参数域穷尽和实际访问游标。
- `native-fixed.ts`、`native-fixed.json`：固定节点原生批次的全部轮次与输出摘要。
- `cross-encoding/`、`cross-rules/`、测试日志：当前跨语言验收与驻留契约；回归附带计时不用于性能结论。
- `complete-current/`：当前双端完整长局、正式压缩记录及读取器审核；`evidence-manifest.json` 保存驱动/输入/输出哈希、墙钟账目，并确认最终热点源码与计时冻结版相同。

复用现有工具的固定局面对照命令（输出须为新目录）：

```sh
node --import tsx scripts/training/performance/compare.ts \
  --baseline artifacts/training/sampling-20260929/baseline-frozen/api.mjs \
  --workset artifacts/training/sampling-20260929/native-baseline-v2/workset.json \
  --rounds 3 --output artifacts/training/sampling-20260929/ts-rerun
```

原生前后对照使用保存的 `native-paired.ts` 和现有 `nativeClient`，每轮只有 `sample-game` 请求；重新采集时复制驱动到新的产物根并修改其输出根目录，禁止覆盖本轮文件。规则和编码回归使用 `native/engine-prototype/README.md` 中的现有验证器。本机之外复现需保留本轮工作集/冻结产物或按同种子重新生成，仓库本身不包含历史实验数据。

收益足以保留这一切片。它降低固定准备成本，仍留下明显的动作树与前向成本；未来若推广到其他多节点编码调用者，应先测其复用次数及内存代价。本轮没有扩大推广，没有第二条优化路线，完成提交后停止。
