## 顺序与边界

1. 转正：`native/engine/`、`haojie-engine`、构建身份与能力、独立交付包和原生 CI；完成验收及无探针对照后单独提交并冻结优化基线。
2. 编码：固定区与节点追加区、身份和元数据、直接发送；保持浮点顺序与拥有权。
3. 记录：类型化规范哈希、成功提交的相邻哈希复用、写入；保留原哈希与提交语义。
4. 审核：内容及版本绑定的单遍审核编码；严格双审核与推荐流程分账。
5. 重测残余候选、属性、实体定位、预检、复制和析构，原型后差分、无探针交错计时，成立则接入。
6. 全套回归、实际模型与独立无 Node 更新/另进程恢复，交付复现入口、证据及残余成本。

模型、学习目标、搜索训练方法、Python 组批、GPU、优化器和长期训练不改。本轮不证明棋力提升，不合并 main、不发布包、不远程部署。

## 输入与基准约定

沿用 `artifacts/kernel-20261003/workset/` 的 111 局面和冻结实际模型 `model-initial.pt`；新增种子在优化前固定为经典 `731280001/731280031`、神龛 `741280001/741280037`。使用完整动作树和编码；命令、候选次序、RNG、实际工作量相等后才计时。无探针预热并交错至少三轮，波动时补测；单独保存剖析，不与编译或回归并行计时。

引擎、原生数据出口、实际模型应用三层分别报告；冷启动、导入/导出、模型等待、CPU 与峰值内存分列。严格双审核与单遍减少阶段的收益独立归因，不乘历史倍率。
