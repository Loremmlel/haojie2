## 当前实现

一个训练进程包含 PyTorch GPU 主线程、协调线程和 Rust 固定线程池。默认 **8 个线程 × 每线程 8 局**，学习 batch 16，推理批量上限 32。网络为 **5,503,366 参数**；参数、梯度、AdamW 动量和神经浮点张量均为 BF16。

先采集 8 个自然结束的简单档示范局，独立完成 512 次模仿更新，再进行 70% 当前自对弈、20% 历史模型、10% 手工对手混合采集。搜索使用完整命令边、渐进扩宽和同次搜索的局面复用；默认 64/16 次模拟、25% 深搜、深度 16。

正常采集在 50 个单方回合后截断，开局随机保留 25% 完整局，示范局全部保留；所有对局有 20,000 命令资源上限。截断胜负保持 unknown，达到校准条件后才附加独立低权重软目标。认输关闭，辅助目标预测实际未来 +2 ply 的事实变化。

回放常驻内存，默认最多 128 局、4 GiB 张量，超限按最早入池整局淘汰。普通发布权重仅驻内存，当前及在途根引用保活；只有历史池成员生成独立权重文件。历史内部按近期、对数时期锚点、挑战表现抽样，使用 256 MiB CPU 缓存和最多三个 GPU 模型缓存。

每 300 秒或正常停止时原子替换唯一 v3 恢复点，包含模型、优化器、随机数、阶段、有限回放和全部在途局。只接受 `haojie-classic-training-v3`，没有旧格式导入或迁移。

## Web 控制

`python -m training.haojie web` 启动本机控制台。支持新建、保存停止、继续和保存应用参数；搜索线程与并行局数可扩缩，多出的原局排队恢复。刷新或关闭浏览器不停止训练，服务重启后重新连接并选择保存的运行继续。

损失、吞吐、CPU/GPU 和内存图表默认使用 60 秒时间加权 EMA，提供原始线、时间范围与键盘读数。最多约 24 小时观测及 200 条日志仅留服务内存。页面为独立单文件 HTML，运行不需要 Node。

- TS 测试按游戏和训练图表分开，删去四个已有完整边界覆盖的旧用例；Rust 的 30 项核心测试保留。验证入口和按改动选择的范围见[测试范围](../maintenance/TESTING.md)。离线 `file://` 主流程覆盖 35 个场景，图鉴分类与搜索集中在专属浏览器入口。

测试及一次性对照产物按需生成。已结束的旧架构、旧格式及失败优化试验产物已清理，历史实施过程从 Git 查阅。

## 当前 8 线程瓶颈诊断

最近一次固定工作量对照使用 2,048 条命令、48,080 次主干评估、65,264 次条件解码、128 次学习更新及 2,048 次训练采样。4×16 与 8×8 的三轮中位耗时分别为 122.24 秒和 94.49 秒，8 线程约 **21.68 命令/秒**，GPU 活动率约 **33.85%**，据此选定当前默认并发。

全链路插桩显示主要限制在 GPU 主线程的前向组织与算子提交：推理路径约占主循环墙钟时间 87–88%，等待原生请求约占 0.05%，学习约占 7–8%。Rust CPU 成本主要来自几何特征及合法动作解码。CUDA Graph 和紧凑推理的完整对照未取得整体收益，相关实现已撤回。

上述数值来自该固定工作集。日常训练的命令、更新、自然终局和资源占用由控制台实时观测；可复用基准与诊断入口见[运行说明](../../training/README.md#验证和性能)。
