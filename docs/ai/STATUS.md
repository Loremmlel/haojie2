# AI / 训练当前状态

本地 Web 控制台和 Colab / Linux 服务共用训练链路：正式 Rust 引擎负责环境、公开动作树与采样，Python 常驻服务负责模型前向、MC-Q v2 终局收益学习、历史对手、评测和恢复。控制台支持开始 / 暂停、RAM 样本自动消费、持续发布行为权重，以及同一训练根内的 20GB 配额管理。

控制台的三档教师复用生产 AI，通过随包 JavaScript 和嵌入式 V8 运行；日常训练服务无需 Node。旧 Python 独立记录 CLI 已移除，已有记录保留原版本及来源，Rust 协议与 TS 独立审核继续维护。旧搜索记录使用专门的访问分布编码器。

当前神经模型处于实验阶段，网页发行版继续使用原三档教师搜索。MC-Q v2 已有功能、可控学习任务和自然局验收；自然棋力以固定权重、规则、预算及独立种子的评测为依据。既往结果见[交付记录](https://github.com/Loremmlel/haojie2/blob/d920e181dccb425c0a77d57b473fb98f45163b69/docs/ai/console/DELIVERY-2026-10-04.md)。

2026-10-22 清理已结束的空间网络、beam/MCTS/Gumbel 试验、一次性性能脚本及对应专用 CI。正式控制台、云端服务、记录兼容、规则差分与行为验收继续维护；历史实现可从[清理前版本 7fc8e85](https://github.com/Loremmlel/haojie2/tree/7fc8e85)读取，本地测量、模型、轨迹和冻结源码保留。

新实验使用 `entity-transformer-v3`：亡者与较早 MC 日志先经过两层完整交互，再作为各深层的逐项历史上下文；最近 16 条有效日志及有效候选引用保留完整深度。公开编码和 MC-Q 学习目标保持原定义，CPU、CUDA 紧凑推理和 ONNX 共用新结构。结构取舍、固定输入性能和学习验收见[性能记录](../../training/PERFORMANCE.md#pr-18-后的亡者与-mc-日志优化)。

支持硬件 BF16 的 CUDA 新实验默认采用 BF16 采样与更新，候选投影及整个评分头的矩阵也进入 BF16；损失、参数和优化器累积状态保持 FP32。采样窗口复用 PyTorch AMP 权重缓存，在排空推理后清理，再允许下一次更新。CPU 输入可使用独立进程完成收帧、校验和紧凑索引准备。旧实验保留保存的采样精度，可暂停后切换；v3 权重与优化器仍可恢复。本地学习、完整周期及自然终局吞吐结果见[性能验收](../../training/PERFORMANCE.md)。TPU 后端与 v6e 实机验收尚未实施。
