## 单进程统一性能验收

整体实现与正确性验收完成后冻结代码，基线为 `7cc4ba9` 独立导出的源码及原 DLL。AMD Ryzen 7 5800H（8 核 16 线程）、RTX 3060 Laptop 6 GiB；两端均为 4×16 局、64/16 模拟、25% 深搜和原生 BF16。固定四局轨迹中的 16 个中后期起点，连续补充 256 个窗口、每窗口 8 条命令，按旧/新、新/旧、旧/新交错三轮。

每轮完成 **2,048 条命令、48,080 次主干评估、65,264 次条件解码、128 次学习更新、2,048 次训练采样**，其中真实终局价值采样 1,318 次。实际执行神经计算，并用同一冻结反馈控制搜索路径；六轮命令、监督、回放抽样 RNG 终态和工作量全部通过一致性检查。窗口在命令边界结束并保留 unknown，吞吐按完整工作量计时。

外部采样每 0.5 秒记录线程 CPU 与 GPU，利用率仅统计预热完成、64 局在途且待分配窗口尚未耗尽的区间。旧版三轮有效稳态为 104.5/115/112 秒，新版为 96.5/104.5/95.5 秒。下表耗时和吞吐取三轮中位；利用率先求各轮稳态均值，再取三轮中位。CPU 以一个逻辑 CPU 的完整时间为 1 核当量。

| 指标                         |   上一版多进程 | 单进程 Rust 池 |
| ---------------------------- | -------------: | -------------: |
| 完整工作量耗时               |      148.20 秒 |      121.20 秒 |
| 命令/秒                      |          13.82 |          16.90 |
| 训练采样/秒                  |          13.82 |          16.90 |
| GPU 活动率                   |         33.32% |         33.63% |
| GPU 提交线程 CPU             |       0.875 核 |       0.923 核 |
| 四个搜索线程 CPU（各线程）   | 0.935–0.939 核 | 0.890–0.917 核 |
| 协调线程 CPU                 |       0.068 核 |       0.081 核 |
| 全部受测进程 CPU 合计        |       4.701 核 |       4.655 核 |
| 每个实际神经批次的平均请求数 |           5.89 |           4.61 |
| 显存峰值                     |     225.23 MiB |     212.61 MiB |

吞吐提升 **22.3%**，完整耗时减少 **18.2%**。旧版三轮耗时 139.41/150.22/148.20 秒，新版 121.20/135.56/118.78 秒。GPU 平均功耗为 31.47/30.44 W，平均 SM 时钟为 1166/1183 MHz，设备活动率没有明显提高；实际神经批次变小，保留此负结果。

这次已移除多进程通信和 Python 搜索调度开销，但尚未达到 GPU 受限。四个 Rust 搜索线程仍各消耗约九成单核时间，GPU 提交线程也接近单核上限；CPU 搜索与神经提交路径仍然繁忙。空闲 Rust 线程使用阻塞接收，采样不是空队列忙轮询。依照本轮约定，统一测量结束后没有追加线程数、批量大小或局部实现调优。

原始六轮记录、逐线程采样及汇总位于 `artifacts/classic-native-pool-20261029/benchmark/`（`results.jsonl`、各轮 `utilization.json`、`summary.json`）。基准工具曾修正满供给监测刷新遗漏与 Windows 监测文件共享冲突，两次未完成记录单独保留在 `benchmark-invalid-monitor/` 和 `benchmark-invalid-file-share/`，不纳入结果。正式重跑前，监测读写独立验证 2,000 次写入、9,028 次读取通过。生产代码始终冻结。

队列耗时口径分别保留：旧版从 GPU 收到 Pipe 请求后计时，新版从 Rust 生成请求开始计时，包含 GPU 正在执行前批的等待；不直接拿这两项总数作通信快慢比较。

## 上一版异步架构性能验收

完成全部设计实现及正确性验收后，冻结代码，再执行旧/新运行时交错三轮。基线为 `d2eb7a4` 的独立导出；测量期间没有调参或逐点优化。原始记录：`artifacts/classic-async-20261029/architecture-benchmark.jsonl`。

16 局每轮固定 128 条命令、3,002 次主干评估、3,940 次条件解码、8 次更新、128 次训练采样，其中 83 次真实价值采样。64 局重复同组起点，每轮固定 512 条命令、12,910 次主干评估、17,794 次条件解码、32 次更新、512 次训练采样，其中 341 次真实价值采样。每组旧/新轨迹、请求和学习采样全部一致。

| 在途对局   | 运行时   | 三轮中位耗时 | 命令/秒 | 平均请求/推理批次 |
| ---------- | -------- | -----------: | ------: | ----------------: |
| 16（4×4）  | 原基线   |     15.20 秒 |    8.42 |              1.75 |
| 16（4×4）  | 异步架构 |     23.87 秒 |    5.36 |              2.18 |
| 64（4×16） | 原基线   |     40.45 秒 |   12.66 |              3.73 |
| 64（4×16） | 异步架构 |     37.61 秒 |   13.61 |              5.18 |

新默认 4×16 对比原默认 4×4，吞吐提升约 **61.7%**。拆开看，原架构增加到 64 局已有约 **50.3%** 提升；同为 64 局时，异步架构本身提升约 **7.5%**。同为 16 局时，异步架构吞吐下降约 **36.3%**，保留这个负结果。

64 局下推理批次数中位数从 8,229 降至 5,924，推理路径时间从 26.59 秒降至 20.28 秒，学习时间约 2.12 / 2.19 秒；异步架构显存峰值中位约 222 MiB。整体吞吐收益远小于推理路径时间的改善，实际批次也仍小于目标 32。结果支持默认采用 64 局供给；新增架构的独立收益较小，本轮按既定范围收口，没有再追加一串局部优化。

本次重新录制的冻结反馈与原性能记录不同，因此以本节同一工作集内的交错对比为准，不直接拿新结果除以旧记录的 6.33。
