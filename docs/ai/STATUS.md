# AI / 训练当前状态

## BF16 与弹性流水线交接（2026-10-23）

当前分支为 `codex/bf16-elastic-training`，基线提交 `d5760fc`。本轮按作者要求收口，保留实现及简明证据，交由下一轮审查方向。正式网络仍为 `entity-transformer-v3`、11,695,874 参数，训练为 MC-Q v2 与补偿 BF16 AdamW；游戏规则、公开输入、候选域、终局收益及单局预算保持原定义。

| 项目            | 当前状态                                                                                                   |
| --------------- | ---------------------------------------------------------------------------------------------------------- |
| 原生 BF16       | 参数、梯度、Adam 矩、公开帧与评分均为 BF16；三种子从零学习通过，正式自然训练完成 453 次更新。              |
| 运行中伸缩      | 1–128 环境，增容异步创建、缩容在结案后退役；真实 CUDA 伸缩、状态与行为版本检查通过。                       |
| 冻结权重发布    | 同根保持快照，新根领取发布版本；当前根快照最多四份，邮箱有界合并，无引用历史回收。                         |
| 独立采样 / 学习 | CUDA 默认独立采样进程、CPU 共享输入、有界终局队列；背压仅阻止该结案槽补局，学习与保存期间继续采样。        |
| 实际吞吐        | 固定完整周期提高约 4–9%；持续采样产出增加时，学习消费和更新量下降，尚待解决。斜率为 1 的并发目标尚未达到。 |
| 候选与设备      | 单 GPU 所有者 RPC、TorchScript 已撤回；v4 根解码未晋升。Colab L4 / TPU 实机待验收。                        |

关键结果：Windows 128 环境、120 秒晚盘窗口，本地参考为 **93.486 条终局样本/秒、2,861 次更新**；逐槽背压流水线为 **181.269 条/秒、2,326 次更新**。随后分组健康检查虽然将单次检查从约 40 ms 降到 3 ms，完整窗口却降到约 **166 条/秒、1,655–1,679 次更新**。下一轮应首先核对完整学习产出和两侧 GPU 竞争；当前改动不能只凭采样数晋升。

架构图、并发曲线、最后一项组批对照、可复现诊断命令和关键原始报告路径统一放在[性能验收](../../training/PERFORMANCE.md)。一次性文档与弃用实验代码已清理，历史原文由[历史索引](HISTORY.md)指向固定提交；原始模型、优化器、轨迹和关键失败证据保留在本地 `artifacts/`。

本地 Web、cloud 和 Notebook 共用训练实现。Rust 负责正式环境与公开采样，Python 常驻服务负责 GPU、MC-Q 学习、历史对手、评测和磁盘恢复。教师通过随包 JavaScript 与嵌入式 V8 运行，日常服务无需 Node。

模型处于实验阶段，网页发行版继续使用原三档教师搜索；自然棋力按固定权重、规则、预算和独立种子的真实终局评测。控制台进程拥有 RAM 样本及在途局，页面关闭不改变其生命周期；暂停排空真实结案并取消在途局，磁盘恢复只重建已保存学习状态。
