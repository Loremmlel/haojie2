## 当前实现

一个训练进程包含 PyTorch GPU 主线程、协调线程和 Rust 固定线程池。新训练默认 **8 个线程 × 每线程 16 局**（共 128 局在途），学习 batch 16，同版本、同操作的推理批量上限 32。已有运行沿用保存的并发配置。新建网络为 **12,137,734 参数**（宽度 384）；旧模型按权重原宽度加载；参数、梯度、AdamW 动量和神经浮点张量均为 BF16。

先采集 8 个自然结束的简单档示范局，独立完成 3,072 次模仿更新，再进行 70% 当前自对弈、20% 历史模型、10% 手工对手混合采集。默认值按 12,378 个示范位置、3.06 GiB 张量和约 4 倍样本复用选定，依据见[预训练参数](TRAINING.md#预训练默认值的依据2026-10-31)。搜索使用完整命令边、渐进扩宽和同次搜索的局面复用；默认 64/16 次模拟、25% 深搜、深度 16。

正常采集在 50 个单方回合后截断，开局随机保留 25% 完整局，示范局全部保留；所有对局有 20,000 命令资源上限。截断胜负保持 unknown，达到校准条件后才附加独立低权重软目标。认输关闭，辅助目标预测实际未来 +2 ply 的事实变化。

回放只驻内存，默认最多 256 局、8 GiB 张量，超限按最早入池整局淘汰。普通发布权重仅驻内存，当前及在途根引用保活；只有历史池成员生成独立权重文件。历史内部按近期、对数时期锚点、挑战表现抽样，使用 256 MiB CPU 缓存和最多 12 个 GPU 推理模型槽位。

正常采集现在按命令序号每 16 步设一个标注位置：若轮到当前模型且有选择，简单教师从该公开局面给出建议。实际落子仍由模型搜索决定。新建和旧 v3 续训默认启用，控制台可调整间隔，分别显示采集与抽样计数。

默认每 3600 秒（1 小时）或正常停止时原子替换唯一轻量 v3 恢复点，包含模型、优化器、随机数、阶段、自对弈在途局面及小型元数据，回放和在途样本张量均不落盘。周期保存保留当前内存题库；恢复后从空回放和零消费额度继续采样。未完成预训练时重新采集示范，再补完剩余模仿更新。只接受 `haojie-classic-training-v3`，已有含回放 v3 仍可读取，下一次保存改为轻量内容。

自对弈阶段默认每 7200 秒（2 小时）启动独立手工 AI 评测：简单、普通、困难各 4 局，每档 2 个种子分别交换先后手，共 12 局；整轮冻结同一已发布版本。评测只保存小型权重与结果，不暂停采集、不复制回放、不参与学习。上一轮未结束时不重叠，停止训练后已开始的评测继续完成；结果见 Web 面板及运行目录 `evaluations/`。

首个训练后的模型存为历史基线。每个新历史检查点自动与基线及上一历史版本各对弈 32 局，同种子换边，双方使用相同完整 MCTS 次数与深度；展示胜率、得分率、按镜像对计算的保守 95% 区间和本轮进步判断。重复对手去重，轮次排队持久化，结果见 `history-evaluations/`。旧运行保留原有预训练与评测间隔配置，历史基线采用已有最早非零版本。

## Web 控制

`python -m training.haojie web` 启动本机控制台。支持新建、保存停止、继续和保存应用参数；搜索线程与并行局数可扩缩，多出的原局排队恢复。刷新或关闭浏览器不停止训练，服务重启后重新连接并选择保存的运行继续。

损失、吞吐、CPU/GPU 和内存图表默认使用 60 秒时间加权 EMA，提供原始线、时间范围与键盘读数。最多约 24 小时观测及 200 条日志仅留服务内存。页面为独立单文件 HTML，运行不需要 Node。

## 每线程并行局数（2026-11-07）

新建训练采用 **8×16**。在同一台 Ryzen 7 5800H / RTX 3060 Laptop 6 GiB 上，固定 384 宽、8 个 Rust 线程、深快搜 64/16、学习 batch 16、推理批上限 32，按 8×8 → 8×16 → 8×16 → 8×8 顺序串行测量。下表取每种配置两轮均值；专用显存列取两轮峰值的范围。

| 每线程局数（总在途） | 满载实际前向批量 | 满载训练 PID CUDA | 满载命令/秒 | 整轮命令/秒 | 整轮新监督位置/秒 | 进程专用显存峰值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 8（64） | 7.08 | 31.7% | 21.54 | 19.44 | 4.63 | 682–684 MiB |
| 16（128） | 13.22 | 32.7% | 27.74 | 24.12 | 5.75 | 748–752 MiB |

测法：只借用 64 个实战局面，各推进 8 条命令，循环补位四遍。用相同初始化的 384 宽网络在八个冻结版本标识下作真实前向，记录一次反馈并固定后续搜索分支。每轮逐条核对相同的 **2,048 条命令、121,340 个神经请求**；产生 488 个监督位置，另以相同回放批次执行 128 次真实 AdamW 更新。推理权重在单轮内冻结。满载从预热 5 秒到最后一个待分配窗口入场；整轮包含收尾，实际前向批量相应为 6.23 / 10.13。下节宽度对照中的 4.74 是单批 64 个起点直接跑到结束，计时口径不同。

CUDA 利用率只读 Windows 的训练 PID `engtype_Cuda`；显存只读同一 PID、同一适配器的专用显存。PyTorch 峰值分配分别为 485–488 / 554–556 MiB，不等于驱动记录的整个进程占用。增至 128 局后，整轮吞吐增加 24%，平均额外专用峰值约 67 MiB。运行时仍按版本、操作和等待期限分组，32 是单批上限；局数不会改变 8 局预训练示范的采集目标。

另外各新建一次临时训练，跳过示范和模仿，使用正常搜索、回放学习和权重发布，按在途局数对齐平均每局第 32–64 条命令的开局窗口。8×8 / 8×16 的实际批量为 **15.36 / 27.14**，吞吐为 **96.2 / 111.9 命令/秒**，训练 PID CUDA 均值为 **28.2% / 25.7%**，窗口专用显存峰值为 **382 / 458 MiB**。这两个窗口分别约 21 / 37 秒，棋路随学习自然变化，不能用来推算全天终局数。本机逐秒计数器和逐轮结果保存在 `artifacts/qa/training-audit-20261107/lanes-8-vs-16.json`。

## 分组推理与新训练宽度（2026-11-07）

在 RTX 3060 Laptop 6 GiB 上，从同一个 256 宽 v3 恢复点取 64 个真实在途局面（8 个冻结根版本），每局推进 8 条命令。先用旧管线录制神经反馈，再按局、步与请求顺序回放：每次仍执行真实网络与原生搜索，逐请求核对操作、版本和输出长度，逐命令核对走法。四种配置均完成同样的 512 条命令、32,446 个神经请求，不含反向传播；宽模型用于测执行开销，未把旧权重扩宽。工作末尾的在途局数逐渐变少。各列给出两轮实测范围；旧管线首次计时与编译部分重叠，单独复测为 15.20 命令/秒。

| 管线 / 宽度 | 参数量 | 实际每个前向批的请求数 | 结果回传次数 | 命令/秒 | 训练 PID 的 CUDA 引擎均值 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 旧 / 256 | 550 万 | 3.47 | 9,338–9,347 | 12.81–15.20 | 29.4%–31.2% |
| 新 / 256 | 550 万 | 4.75–4.81 | 3,481–3,522 | 17.02–21.51 | 24.7%–28.3% |
| **新 / 384** | **1,214 万** | **4.74** | **3,511–3,514** | **15.61–16.55** | **26.9%–30.9%** |
| 新 / 512 | 2,136 万 | 4.72–4.73 | 3,542–3,544 | 16.00–16.67 | 30.9%–31.1% |

CUDA 数据使用 Windows 每进程 `engtype_Cuda`，不含浏览器/桌面的整卡 3D 利用率。独立真机跟踪确认：旧档副本恢复后的 32 个循环执行 64 个前向批，输出只触发 32 次 CUDA 流同步。同设备开启确定性计算，以八个原版冻结网络对相同分组的 128 个 encode/decode 请求单独对照，923 个 BF16 输出数值逐位相同。改变组批形状仍可能产生 BF16 舍入差异。

从上述实际采集的 128 个监督位置按正式回放抽出 24 个固定 batch（每批 16 个位置），每个宽度预热后做三轮完整更新。宽度 256 / 384 / 512 的每次更新耗时中位数为 82.6 / 81.3 / 93.6 ms；混合版本推理中的 PyTorch 峰值分配约为 183 / 308 / 496 MiB。选 384 是因为容量约为原来的 2.21 倍，在这组中局下保持了原管线吞吐，且学习成本与 256 相近。长期棋力和全天自然终局产量由正式训练后的直接对局与运行记录衡量。

## 当前 8 线程瓶颈诊断

以下是 2026-10-31 的固定工作量；正式运行中的多版本瓶颈与缓存修复依据见[实机调查](TRAINING-AUDIT-2026-11-07.md)。

最近一次固定工作量对照使用 2,048 条命令、48,080 次主干评估、65,264 次条件解码、128 次学习更新及 2,048 次训练采样。4×16 与 8×8 的三轮中位耗时分别为 122.24 秒和 94.49 秒，8 线程约 **21.68 命令/秒**，GPU 活动率约 **33.85%**，当时据此选用 8 个线程；新模型每线程的并行局数见上文对照。

全链路插桩显示主要限制在 GPU 主线程的前向组织与算子提交：推理路径约占主循环墙钟时间 87–88%，等待原生请求约占 0.05%，学习约占 7–8%。Rust CPU 成本主要来自几何特征及合法动作解码。CUDA Graph 和紧凑推理的完整对照未取得整体收益，相关实现已撤回。

上述数值来自该固定工作集。日常训练的命令、更新、自然终局和资源占用由控制台实时观测；可复用基准与诊断入口见[运行说明](../../training/README.md#验证和性能)。
