# 普通局训练

2026-10-29，分支 `codex/classic-training-rewrite`，当前为分层解码 v2。只训练 classic，包含终极召唤、合成、老千、反应与随机机制。运行命令见 [training/README.md](../../training/README.md)，实际验收见[状态入口](STATUS.md)。

## 方法与依据

采用 5.50M 实体 Transformer、完整命令级随机 PUCT、搜索策略监督与终局价值学习。先完成独立手工示范预训练，再启动当前模型、跨时期历史模型和少量手工对手混合采集。

- [KataGo](https://arxiv.org/html/1902.10565v5)：借鉴搜索预算随机化、只监督深搜步和事实辅助目标。约 50 倍计算效率提升是论文中具体系统的整体比较。
- [ELF OpenGo](https://arxiv.org/html/1902.04522v5)：借鉴策略与终局监督、固定参照和跨时期评测。
- [Time Limits in Reinforcement Learning](https://proceedings.mlr.press/v80/pardo18a.html)：资源截断与游戏终局分开，截断时可以在继续任务的意义下自举。
- [Monte-Carlo Graph Search for AlphaZero](https://arxiv.org/abs/2012.11045)：参考共享局面与父边统计的区分。本实现采用下文明确的节点复用与回传语义。

不从博弈树数量级外推训练局数。对话中的 20–40 层、300–600 子动作和单卡 3–8 秒一局是估算；程序分别记录 ply、完整命令、主干评估、条件解码、自然终局和训练采样次数。

## 进程与 IPC

常驻 Python CPU worker，每个交替推进多局；Rust 动态库通过 ctypes 在 worker 内执行规则、合法解码与三档手工 AI。单个 Python 主进程持有 GPU，合批推理并穿插短学习批次。CPU worker 不导入 PyTorch，不逐局新建进程，也不另开引擎进程。

当前默认 **4 worker × 每 worker 4 局**，CLI 会按可用 CPU 数下调 worker。此分配由本机 RTX 3060 Laptop 上的正式预算、中后期局面和学习混合测量选定；其他设备可用同一基准复测并显式调整。

每个 worker 独占可复用的 16 MiB `multiprocessing.shared_memory` 槽，Pipe 只传形状、模型版本、事件和所有权交接。超过容量时显式扩容。大张量不经 Queue/pickle，不跨进程共享 CUDA 张量。GPU 输出按 BF16 原始 16 位传输。依据：[Python SharedMemory](https://docs.python.org/3/library/multiprocessing.shared_memory.html)、[PyTorch 多进程说明](https://docs.pytorch.org/docs/stable/notes/multiprocessing.html)。

主进程按模型版本、encode/decode 类型与长度分桶，推理模型缓存最多 3 个版本。单次搜索绑定同一发布版本，历史对手整局固定。实体主干结果按 worker、局、搜索起点和版本缓存；换命令时释放该局旧搜索上下文。

本机选共享内存。`training/tests/bench_ipc.py` 可复测。`bench_pipeline.py` 从四局真实轨迹各取 25%、50%、75%、90% 处的非终局状态，形成 16 个中后期起点。使用正式 64/16 搜索、25% 深搜，每个起点推进 8 条命令，同时固定执行 8 次 BF16 学习更新、消费 128 个回放样本。

基准先录制搜索反馈，随后让 1×16、2×8、4×4 对同一工作集执行真实 Rust 搜索、GPU 推理与学习，以录制反馈控制批大小舍入造成的路径分歧。核对已有公开状态键、请求形状、逐条命令、主干/解码次数、学习采样 RNG 及消费数量。推理权重冻结，学习使用独立模型及相同优化器初态。计时包含进程启动、规则、推理、IPC、轨迹落盘、回放读取和学习；源轨迹重放准备在计时前完成。当前测量见状态入口。

## 模型和精度

宽度 256、6 层 Pre-LN Transformer、8 头、FFN 1024，实际 **5,503,366 参数**。状态行 128 维，条件动作行 704 维。新增局部记录编码和几何/条件策略输入；主干宽度、层数保持不变。

主干 token 包括全局、基地、单位、手牌及待处理反应的单位快照。装备、效果、已攻击/受伤记录、死亡历史、延迟事件、光环等原有记录完整保留，通过共享嵌入和非线性局部编码汇总到所属实体或全局，不再各自进入全局注意力。选择死亡对象时，策略头另外读取该对象的记录描述。只接收公开观察，正式 RNG 留在权威环境。

每对实体有 8 维规则几何特征：横纵位移、占地间最小曼哈顿距离、来源射程、几何可达、占位阻挡、同 owner、当前完整攻击合法性。几何来自共用规则查询，包含大单位、穿透和路径语义。线性投影为每个注意力头的加性偏置。

每个搜索局面只计算一次状态主干。轻量条件头读取参数前缀、来源、目标、当前选中对象与全局表示，逐段解码；同局面的后续前缀复用缓存。价值头和 4 维未来事实辅助头共用主干，注意力采用 PyTorch SDPA。

训练、当前/历史推理、校准器和评测统一原生 **BF16**：参数、梯度、AdamW 动量、神经浮点输入/输出与损失均为 BF16，没有 FP32 主权重或 autocast。来源/目标/当前对象行号及类别索引在转换前提取为整数；AdamW 步数为 int64，矩估计为 BF16。CUDA 算子内部使用 PyTorch 标准累加实现。CPU 规则事实、搜索统计和重放引用使用各自的数据类型，避免低精度破坏规则与回放。

## 动作与搜索

合法解码顺序为来源 → 动作类型 → 必要参数（目标、材料、路径、方向、自选召唤等）。每级列出当前前缀可继续完成的全部合法选项，采用确定性回溯排除没有合法后继的空分支，不使用手工评分 Top-k 或固定随机 32 命令集合。完整命令先验是各条件概率的乘积。TS/Rust 共用对应的无评分参数域，并逐前缀差分验证。

一条搜索边始终是一条完整引擎命令，参数前缀不消耗游戏搜索深度。play 阶段可选择任何合法的未完成行动，保留行动顺序意义。

节点采用渐进扩宽：访问数 N 对应最多 `ceil(2 × sqrt(N + 1))` 条已发现命令；新命令按网络条件分布无放回抽取。它随预算增长，不设固定 32 命令上限。同一完整命令的多条解码路径合并先验。搜索访问分布按路径质量回投为每一级条件策略标签，并以该前缀的访问概率加权。

PUCT 每次独立采样规则随机后继，用实际访问回报估计期望。同方连续操作不翻号，依实际决策方转换价值视角。一次搜索内按完整公开状态键共享局面节点、编码、条件分布及后续搜索；不同父边各自保留访问和回报。当前模拟路径再次遇到同一键时用该节点价值结束，防止循环回传。真实落子后释放旧图；不把时钟或历史不同的局面强行视作同一状态。

默认 25% 决策做 **64 次模拟**，其余 **16 次**，平均 28 次；搜索深度上限 **16 条完整命令**。唯一合法命令直接执行。通常每次模拟最多新增一个主干评估；条件解码头另计次数。深搜步和示范步写策略监督，快搜只记实际轨迹。根来源分布混合 25% Dirichlet 噪声；训练按访问分布及温度采样，评测关闭噪声并选择最大访问项。

## 独立预训练与对手池

三档手工 AI 保持原有 Rust 完整移植：评价、候选、束搜索、概率展开、回应搜索、回合预算与计划缓存对应 TS。网页继续使用 TS，训练与评测不需 Node。

预训练有明确的持久化阶段：

1. `collect`：默认采集 **8 个自然结束的简单档示范局**；截断示范另记 unknown 并补采。此时不更新模型，不启动神经自对弈。
2. `imitation`：worker 暂停派局，完成 **512 次独立模仿更新**；完整示范命令转为条件 one-hot 标签，辅助目标沿用未来事实。
3. `self`：发布预训练模型后开始正常对局。`--warmup-games 0` 可明确跳过预训练；`--warmup-updates` 调整模仿次数。

正常阶段默认 70% 当前自对弈、20% 历史、10% 手工简单档。历史为空或选中当前版本时转回自对弈。示范随近期回放自然淘汰。每 64 个真实终局存历史版本；历史内部按最近 8 个／对数时期锚点／最具挑战的 8 个 = 40/40/20 抽样，保留早期文件，GPU 按需加载。

主价值学习当前对当前的终局或合格截断软目标。历史/手工对战只学习当前席位的搜索策略与未来事实；示范用于策略和辅助目标。

## 奖励与截断

真实胜 +1、负 -1、规则平局 0，折扣 1。没有伤害、击杀、存活或每步奖励；认输保持关闭。每 64 条命令采集一个不可变片段，继续同一局。

正常采集默认完成 **50 个单方回合**后，在进入第 51 回合时截断。开局随机抽取 **25% 完整局**免除此回合上限，保留真实终局供价值学习和校准；示范局全部免除，以完成独立预训练。完整局分配不看局势，保存在每局 `ply_limit` 中，暂停恢复后不重抽。`--max-ply` 调整回合上限（0 为关闭），`--full-game-fraction` 调整保留比例。它与搜索预算的 `--full-fraction` 是两个独立参数。

所有对局仍有 **20,000 条命令**资源硬上限，避免无法推进回合的异常长局耗尽资源。真实终局优先于任何截断。对局和结果记录区分 `ply_limit` 与 `command_limit`，状态统计分别累计 `ply_truncated`、`command_truncated`。这些都是采集边界，不修改游戏胜负规则。

截断局保存 `environment.json`，状态为 truncated，`winner` 仍为 null/unknown。仅自对弈可以附加独立的 `soft_target`：

- 尚无可用校准器：价值损失屏蔽，继续使用策略和已有未来事实。
- 至少 **16 个真实自对弈终局**后，以完整局为单位分训练/留出集，每局最多 16 个均匀位置，用基地血差、单位数差、总生命差、人头差拟合换边对称的逻辑回归。只有留出 Brier 优于常数 0.5 才启用。
- 达到 **128 个真实自对弈终局**后，改用冻结的当前发布模型估计实际截断边界的价值。
- 软值限定在 ±0.98、损失权重 **0.25**，记录来源类型、视角、模型版本和真实终局数量；真实终局仍使用原始 ±1/0 标签。`--calibration-games`、`--bootstrap-after-games`、`--bootstrap-weight` 可调整。

这是有权重区分的价值估计，不将截断补成获胜。软标签取值小于 1 本身不能保证策略严格偏好更早的真实胜利；硬上限也不承担血量判胜或规则衰减功能。

回放保存近期 128 局，先抽局再抽片段/位置；已有真实自对弈终局时半批次优先取这类数据。每个新策略样本提供 4 次采样额度；终局/合格软目标到来另提供一批额度。辅助目标继续是实际未来 +2 ply 的基地血差、单位数差、总生命差、人头差变化，缺失后续时屏蔽。损失为条件策略交叉熵 + 加权价值 MSE + 0.1 × 辅助 SmoothL1；AdamW 学习率 0.0003，梯度范数上限 1。
