# 普通局训练

2026-10-29，分支 `codex/classic-training-rewrite`。范围为 classic，包含终极召唤、合成、老千、反应与随机机制。运行命令见 [training/README.md](../../training/README.md)，验收结果见[状态入口](STATUS.md)。

## 决策与研究依据

采用 5.34M 实体 Transformer、完整命令级随机 PUCT、搜索策略监督与真实终局价值学习。手工 AI 做短期策略预热、少量固定对手与独立评测；历史池保留早期模型。通过连续分段采集控制内存，不改变规则或按基地血量补胜负。

- [KataGo](https://arxiv.org/html/1902.10565v5)：约 420 万局、不到 30 块 GPU、19 天超过 ELF 最终模型。借鉴搜索预算随机化、只监督深搜步、短期事实辅助目标。论文中的约 50 倍是特定系统间的整体计算效率比较。
- [ELF OpenGo](https://arxiv.org/html/1902.04522v5)：完整训练约 16 天、2000 块自对弈 GPU 和 8 块训练 GPU；9 天是达到超人表现的阶段。其策略与终局监督，以及固定参照和跨时期评测，适用于本项目。
- [Gumbel AlphaZero](https://openreview.net/pdf?id=bERaNdoegnO) 和 [Sampled MuZero](https://proceedings.mlr.press/v139/hubert21a.html)：低搜索预算与大动作域的后续比较对象。当前实现是有限候选集上的 PUCT，没有实现这两篇的策略改进算法或采样修正。
- [Time Limits in Reinforcement Learning](https://proceedings.mlr.press/v80/pardo18a.html)：资源上限与游戏终局分开处理。

博弈树数量级不能直接换算训练局数。给定对话中的 20–40 层、300–600 子动作和单卡 3–8 秒一局属于估算；本项目分别记录 ply、完整命令、搜索评估、自然终局和训练复用次数。

## 进程与 IPC

常驻 Python CPU worker，每个交替推进多局；Rust 动态库通过 ctypes 在 worker 内执行规则、合法候选与三档手工 AI。GPU 由一个 Python 主进程持有，统一批量推理和学习。CPU worker 不导入 PyTorch，不逐局新建进程，也不另开引擎进程。

每个 worker 独占可复用的 16 MiB `multiprocessing.shared_memory` 槽，Pipe 只传形状、模型版本、事件和所有权交接。超过容量时显式扩容，完整保留数组。GPU 输出按 BF16 原始 16 位传输。大张量不通过 Queue/pickle，不做跨进程 CUDA 张量共享。依据：[Python SharedMemory](https://docs.python.org/3/library/multiprocessing.shared_memory.html)、[PyTorch 多进程说明](https://docs.pytorch.org/docs/stable/notes/multiprocessing.html)。

主进程按模型版本与实体长度分桶合批，推理缓存最多 3 个版本。单次搜索绑定同一发布版本，历史对手整局固定。GPU 推理后穿插短学习批次；模型发布、历史入池与恢复检查点分别管理。

2026-10-29 Windows 本机 IPC 测量，3 轮交错、每轮 150 次完整往返，包含负载写入/读取/修改：

| 单次负载 | Queue 中位 µs | Pipe 中位 µs | 共享内存 + Pipe 中位 µs |
| -------- | ------------: | -----------: | ----------------------: |
| 4 KiB    |        176.20 |       110.95 |                   33.30 |
| 64 KiB   |        248.20 |       150.55 |                   40.60 |
| 256 KiB  |        802.65 |       289.60 |                  122.50 |
| 1 MiB    |       2990.45 |      2767.25 |                  346.35 |

本机单机张量交换选择共享内存。`training/tests/bench_ipc.py` 可复测。

原生 BF16 固定工作集测试：RTX 3060 Laptop，8 局，每局 64 命令，每步 4 次模拟，32 候选；每轮均 512 命令、1400 次网络评估。三轮交错中位吞吐为 1 worker × 8 局 **95.91**、2 × 4 **137.89**、4 × 2 **167.53** 命令/秒。包含进程启动、Rust 规则/搜索、GPU 推理、共享内存与轨迹落盘；不包含学习。

批大小会改变 BF16 舍入及后续抽样轨迹，因此基准先录制未计时的搜索反馈工作集，再让各拓扑执行相同输入的真实 GPU 推理，使用录制反馈控制搜索路径。逐项核对输入、命令轨迹和搜索数量。它测量相同工作量的并发收益；自然训练吞吐另记在 `status.json`。入口为 `training/tests/bench_pipeline.py`。

## 模型和精度

宽度 256、6 层 Pre-LN Transformer、8 头、FFN 1024，实际 **5,338,950** 参数。状态行 128 维，动作行 576 维。实体包括全局、基地、单位、手牌、装备、反应来源、死亡/延迟状态和老千光环等公开规则信息；不截去超长局面中的实体。模型只接收公开观察编码，环境 RNG 留在权威环境。

状态主干一次服务全部候选；策略头联合完整命令、来源实体、目标实体和全局表示打分。另有价值头与 4 维未来事实辅助头。注意力使用 PyTorch SDPA。

训练、当前/历史推理和评测统一原生 **BF16**：参数、梯度、AdamW 动量、浮点输入、输出及损失均为 BF16；没有 FP32 主权重或 autocast。动作来源/目标行号在转换前提取为 int64，避免 257 等行号发生舍入；角色与种类嵌入索引也保留整数。AdamW 使用标准逐张量更新，步数为 int64；矩估计为 BF16。CUDA 算子内部采用 PyTorch 标准累加实现。

CPU 规则编码与搜索统计保持各自的数据类型。GPU 输出以 16 位原始数据传输，在 CPU 搜索入口无损解码；原始轨迹保存规则事实和精确引用，不以低精度破坏重放信息。

## 动作与搜索

一条搜索边是一条完整引擎命令，不将来源、类型、目标、材料和路径各算一层。play 阶段可选择任何合法的未完成行动，保留顺序意义。

候选生成使用完整的无评分合法参数域和有界随机回溯，默认每个局面采样 32 个不同完整命令；不调用手工评分做 Top-k 裁剪。存在空参数分支时回溯，随机边界的预检 uncertain 依照引擎语义处理。TS 与 Rust 有对应实现及差分。

当前策略归一化和交叉熵定义在实际采样候选集上，训练记录保存该候选集。不同候选集会影响策略分布；当前没有全动作域自回归先验、渐进扩宽或 Sampled MuZero 提议分布修正。这是首版算法边界，后续改进须单独验证收益。

PUCT 对每条命令独立采样规则随机后继，按访问回报估计期望，不选最幸运后继；模拟 RNG 与正式 RNG 分离。同方连续操作不翻号，按真实决策方转换价值视角。新命令清空旧树，无跨步转置表。深度上限用网络叶子值，仅作为搜索估计。

默认 25% 决策做 64 次模拟，其余 16 次；仅深搜步写策略监督，快搜仍记录实际命令和终局。根先验混合 25% Dirichlet 噪声。评测关闭噪声，以访问分布最大项落子。训练按访问分布和温度采样。

## 手工 AI 与历史池

三档手工 AI 完整移植为 Rust：原评价、候选、束搜索、概率展开、回应搜索、回合预算和计划缓存均对应 TS。训练和评测无需 Node；网页继续使用 TS 版本。普通局老千合成光环仍在范围内，神龛训练不在范围内。

默认先采集 8 局手工简单档示范，用明确标记的 one-hot 策略标签预热。随后 70% 当前自对弈、20% 历史、10% 手工简单档；空历史份额转回当前自对弈。示范随近期回放自然淘汰。中等/困难档可独立评测。

每 64 个真实终局保存一次历史推理版本。历史份额内部按最近 8 个／对数时期锚点／最具挑战的 8 个 = 40/40/20 抽样。时期锚点覆盖初期；已存历史文件保留，GPU 按需加载。按实际历史对战成绩更新挑战记录。

主价值只学习当前对当前的真实终局。历史/手工对战仅学习当前席位的搜索策略和实际未来事实；示范仅用于策略和辅助目标。固定对手胜率通过配对换边评测记录。

## 奖励、采集与恢复

真实胜 +1、负 -1、规则平局 0，折扣 1。没有基地伤害、击杀、存活或每步惩罚。认输关闭。

| 边界                   | 处理                                         |
| ---------------------- | -------------------------------------------- |
| 每 64 命令采集段       | 记录不可变命令/样本片段，继续同一局          |
| 搜索预算/深度          | 使用叶子估值，不写成终局                     |
| 20,000 命令硬上限      | 保存环境，标记 truncated/unknown，主价值屏蔽 |
| 定时保存、Ctrl+C、STOP | 在命令边界保存，续训继续原局                 |

终局通过 game id 元数据关联已落盘片段，不重写原始样本。回放保留近期 128 局，先抽局再抽片段/位置；已有终局时半个批次优先取真实自对弈终局。每个新策略样本默认提供 4 次采样额度；终局到来另提供一批更新额度。

辅助目标是实际未来 +2 ply 的基地血差、单位数量差、单位总生命差、人头差变化，按操作者视角表达；缺少后续数据时屏蔽。总损失为策略交叉熵 + 终局价值 MSE + 0.1 × 辅助 SmoothL1。AdamW 学习率 0.0003，梯度范数上限 1。

检查点保存模型、优化器、Python/搜索/Torch/CUDA RNG、对手池、回放进度、发布版本与在途环境；手工 AI 同时保存预算和计划。未完成搜索从原命令起点及原绑定模型重算。失败保存原始错误和可恢复状态。恢复保持 worker 数、局数、候选数；每次启动的时间/更新/局数上限单独计数。

## 后续训练判断

先观察自然终局率、独立终局/小时、终局价值覆盖和搜索样本/小时。按相同预算比较搜索对直接策略、当前对早期模型及三档固定 AI，unknown 单列。损失用于诊断学习过程，棋力由完整对局评测。

运行闭环验收使用低搜索预算降低等待成本；正式默认预算仍为 64/16。没有将单次短验收外推为所需总训练局数或达到高水平的时间。
