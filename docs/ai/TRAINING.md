# 普通局训练

当前使用分层解码 v2，只训练 classic，包含终极召唤、合成、老千、反应与随机机制。运行命令见 [training/README.md](../../training/README.md)，实际验收见[状态入口](STATUS.md)。

## 方法与依据

采用 5.50M 实体 Transformer、完整命令级随机 PUCT、搜索策略监督与终局价值学习。先完成独立手工示范预训练，再启动当前模型、跨时期历史模型和少量手工对手混合采集。

- [KataGo](https://arxiv.org/html/1902.10565v5)：借鉴搜索预算随机化、只监督深搜步和事实辅助目标。约 50 倍计算效率提升是论文中具体系统的整体比较。
- [ELF OpenGo](https://arxiv.org/html/1902.04522v5)：借鉴策略与终局监督、固定参照和跨时期评测。
- [Time Limits in Reinforcement Learning](https://proceedings.mlr.press/v80/pardo18a.html)：资源截断与游戏终局分开，截断时可以在继续任务的意义下自举。
- [Monte-Carlo Graph Search for AlphaZero](https://arxiv.org/abs/2012.11045)：参考共享局面与父边统计的区分。本实现采用下文明确的节点复用与回传语义。

程序分别记录 ply、完整命令、主干评估、条件解码、自然终局和训练采样次数；性能比较使用固定工作量实测。

## 单进程运行时

一个 Python 进程包含 GPU 主线程、协调/I/O 线程和 Rust 固定工作线程池。GPU 主线程独占 CUDA、模型、优化器及编码缓存；协调线程顺序处理对局分配、阶段、回放抽样、历史池与落盘，保持协调 RNG 的原有所有权。Rust 执行规则、三档手工 AI、完整搜索状态机与神经请求组织。完整职责、协议和恢复设计见[运行时架构](TRAINING-RUNTIME.md)。

默认 **8 个 Rust 线程 × 每线程 8 局**，CLI 会按可用 CPU 数下调线程数。每局固定归属一个线程，局面内的 `Rc` 不跨线程移动。每个 lane 最多等待一个神经请求或一个正式命令记录确认；等待时线程推进其他就绪局。`--workers` 表示 Rust 线程数。学习 batch 保持 16；本机线程数比较结果见状态入口。

进程内批量 C ABI 传递请求元数据和连续数组指针。Python 在请求批次释放前只读借用 Rust 数组，GPU 输出按 BF16 原始 16 位整批回填；搜索节点不往返 JSON，也不回调 Python。正式命令记录使用整批 JSON 元数据加类型化数组，协调线程复制为 Python 拥有的样本，交给 GameBuffer 后确认 lane 继续。学习批次与低频控制走进程内队列，不使用 Pipe 或共享内存 IPC。

GPU 跨 lane 收集请求，达到 32 个请求或最老请求等待 2 ms 时执行；按模型版本、encode/decode 分组，组内按长度排序。空队列阻塞在原生 Condvar，学习或控制任务会主动唤醒。每轮推理后可执行一个已准备的学习批次。GPU 推理模型缓存最多 12 个版本，CPU 历史权重缓存预算 256 MiB；当前和在途引用版本在内存保活，临时发布不写独立文件。首次响应固定本次搜索的发布版本，历史对手整局固定。实体主干结果按 lane、根命令、节点和版本缓存，换根时释放。

Rust 持有每局可复制的 PCG64 状态，并直接调用 NumPy 的原生 gamma、bounded uint64 和无 GIL f32 exp 内核，保持随机消耗及接近平手时的搜索顺序。NumPy 固定 **2.5.3** 并在启动时检查版本：`_generator` 分布符号和 `numpy_1.24_ufunc_call_info` capsule 都是私有 C ABI，不提供另一套数学实现作为回退。此次功能验收使用 NumPy 2.5.3、PyTorch 2.14.0+cu130。

## 统一性能验收

先整体完成架构和功能验收，再统一测量。`training/tests/bench_pipeline.py` 从四局真实轨迹各取 25%、50%、75%、90% 处的非终局状态，形成 16 个中后期起点。默认分配 256 个窗口，每个推进 8 条命令，完成后补入下一窗口，持续维持 64 局供给。使用正式 64/16 搜索、25% 深搜；固定执行 128 次 BF16 学习更新、消费 2,048 个回放样本。

基准先录制搜索反馈，以录制反馈控制批大小舍入造成的路径分歧；每次仍执行真实搜索、GPU 推理和学习。基准需要已有的含回放 v3 检查点，日常轻量恢复点不提供这份基准数据，支持当前运行时的线程数和插桩开关对照。

核对已有公开状态键、请求形状、逐条命令、主干/解码次数、学习采样 RNG 及消费数量。推理权重冻结，学习使用独立模型及相同优化器初态。吞吐使用整个固定工作量的总耗时；模型准备与源轨迹重放在计时前完成。外部采样记录 Rust 系统线程、GPU 主线程 CPU 时间和 GPU 活动率、功耗、时钟，只统计预热后仍保持 64 局且有待分配窗口的区间，并记录实际批次与请求等待。采样另需 `psutil` 和 `nvidia-smi`，运行命令见训练入口，实测结果统一写入状态入口。

## 模型和精度

宽度 256、6 层 Pre-LN Transformer、8 头、FFN 1024，实际 **5,503,366 参数**。状态行 128 维，条件动作行 704 维。新增局部记录编码和几何/条件策略输入；主干宽度、层数保持不变。

主干 token 包括全局、基地、单位、手牌及待处理反应的单位快照。装备、效果、已攻击/受伤记录、死亡历史、延迟事件、光环等原有记录完整保留，通过共享嵌入和非线性局部编码汇总到所属实体或全局，不再各自进入全局注意力。选择死亡对象时，策略头另外读取该对象的记录描述。只接收公开观察，正式 RNG 留在权威环境。

每对实体有 8 维规则几何特征：横纵位移、占地间最小曼哈顿距离、来源射程、几何可达、占位阻挡、同 owner、当前完整攻击合法性。几何来自共用规则查询，包含大单位、穿透和路径语义。线性投影为每个注意力头的加性偏置。

每个搜索局面只计算一次状态主干。轻量条件头读取参数前缀、来源、目标、当前选中对象与全局表示，逐段解码；同局面的后续前缀复用缓存。价值头和 4 维未来事实辅助头共用主干，注意力采用 PyTorch SDPA。

训练、当前/历史推理、校准器和评测统一原生 **BF16**：参数、梯度、AdamW 动量、神经浮点输入/输出与损失均为 BF16，没有 FP32 主权重或 autocast。来源/目标/当前对象行号及类别索引在转换前提取为整数；AdamW 步数为 int64，矩估计为 BF16。CUDA 算子内部使用 PyTorch 标准累加实现。CPU 规则事实、搜索统计和重放引用使用各自的数据类型，避免低精度破坏规则与回放。

## 动作与搜索

合法解码顺序为来源 → 动作类型 → 必要参数（目标、材料、路径、方向、自选召唤等）。每级列出当前前缀可继续完成的全部合法选项，采用确定性回溯排除没有合法后继的空分支，不使用手工评分 Top-k 或固定随机 32 命令集合。完整命令先验是各条件概率的乘积。TS/Rust 共用对应的无评分参数域，并逐前缀差分验证。

一条搜索边始终是一条完整引擎命令，参数前缀不消耗游戏搜索深度。play 阶段可选择任何合法的未完成行动，保留行动顺序意义。

节点采用渐进扩宽：访问数 N 对应最多 `ceil(2 × sqrt(N + 1))` 条已发现命令；新命令按网络条件分布无放回抽取。它随预算增长，不设固定 32 命令上限。同一完整命令的多条解码路径合并先验。搜索访问分布按路径质量回投为每一级条件策略标签，并以该前缀的访问概率加权。

PUCT 每次独立采样规则随机后继，用实际访问回报估计期望。同方连续操作不翻号，依实际决策方转换价值视角。一次搜索内按完整公开状态键共享局面节点、编码、条件分布及后续搜索；不同父边各自保留访问和回报。当前模拟路径再次遇到同一键时用该节点价值结束，防止循环回传。真实落子后释放旧图；不把时钟或历史不同的局面强行视作同一状态。

默认 25% 决策做 **64 次模拟**，其余 **16 次**，平均 28 次；搜索深度上限 **16 条完整命令**。唯一合法命令直接执行。通常每次模拟最多新增一个主干评估；条件解码头另计次数。深搜步写搜索策略监督，快搜不写搜索分布；两者都可接受下述教师标注。根来源分布混合 25% Dirichlet 噪声；训练按访问分布及温度采样，评测关闭噪声并选择最大访问项。

## 独立预训练与对手池

三档手工 AI 保持原有 Rust 完整移植：评价、候选、束搜索、概率展开、回应搜索、回合预算与计划缓存对应 TS。网页继续使用 TS，训练与评测不需 Node。

预训练有明确的持久化阶段：

1. `collect`：默认采集 **8 个自然结束的简单档示范局**；截断示范另记 unknown 并补采。此时不更新模型，不启动神经自对弈。
2. `imitation`：暂停派局，完成 **3,072 次独立模仿更新**；完整示范命令转为条件 one-hot 标签，辅助目标沿用未来事实。
3. `self`：发布预训练模型后开始正常对局。`--warmup-games 0` 可明确跳过预训练；`--warmup-updates` 调整模仿次数。

正常阶段默认 70% 当前自对弈、20% 历史、10% 手工简单档。历史为空或选中当前版本时转回自对弈。示范随近期回放自然淘汰。每 64 个真实终局存历史版本；历史内部按最近 8 个／对数时期锚点／最具挑战的 8 个 = 40/40/20 抽样，保留早期文件，GPU 按需加载。

模仿结束后的首个发布额外存为历史基线；显式跳过模仿时使用首个训练后的发布。采集示范期间不归档版本 0。已有运行沿用最早的非零历史版本作为基线，不把旧权重标成模仿完成时的权重。每个新历史版本自动对比基线及上一历史版本，重合时去重；评测安排见下文。

**在模型走到的局面上请教师标注。** 在正常采集的非强制模型决策上，默认间隔为 16：按 `(局号 + 已执行命令数) % 间隔 == 0` 选位，0 关闭。自对弈覆盖双方，历史/手工对战只覆盖当前席位；评测不标注。模型先按原搜索选定命令，简单教师从同一公开局面、独立的空计划给建议，不执行建议。用其完整命令生成非强制前缀的 one-hot 标签，每个教师前缀的交叉熵权重为 0.5；原深搜前缀的访问目标与权重均保留。两类监督共用同一份状态、只计一个位置，价值与未来事实从实际轨迹取。间隔和权重是这一版的训练起点，棋力效果留待实际对弈测量。

主价值仍学习当前对当前的终局或合格截断软目标；预训练示范用于策略和辅助目标。累计 `teacher_labeled_positions` 表示已收集的在线教师位置，`trained_teacher_positions` 表示实际学习批次抽到它们的次数。旧回放无这类标签，旧计数从零起。

### 预训练默认值的依据（2026-10-31）

当前预训练起点为 **8 局示范、3,072 次更新、batch 16**，按已有示范样本量选定，网络为 5.50M。随后容量复核将内存回放提高为 256 局 / 8 GiB，并取消回放落盘；示范局数和模仿次数的进一步调整使用新的数据覆盖与模型对弈结果。

下文真实训练回放的统计在轻量转换之前完成；正式运行 `训练-20261030215625/checkpoint.pt` 现已转换为轻量恢复点，其原回放张量按本次保存策略丢弃。

- [DAgger / Ross 等，2011](https://proceedings.mlr.press/v15/ross11a.html) 分析了行为克隆的状态分布偏移：长序列中，单步错误可累积为随决策长度平方增长的最坏情况损失。因此预训练先学基本行动分布，然后转入现有自对弈；反复模仿少量简单档轨迹不能代替新状态探索。
- [AlphaGo Zero / Silver 等，2017](https://doi.org/10.1038/nature24270) 通过网络引导 MCTS 产生更好的策略目标；其模型评测采用 400 局、每步 1,600 次模拟并选择最大访问动作。[KataGo / Wu，2019](https://arxiv.org/abs/1902.10565) 用深/快搜索随机化平衡策略样本和终局样本。这些论文支持方法选择，没有给出浩劫的示范局数或梯度更新次数。

实测口径：从本机 `artifacts/training/webgui-修复验收-20261030/checkpoint.pt` 只读提取完整保留的 8 局示范。种子依次为 3003105693、976400781、3387213022、1360466709、876933081、3424658562、2760304912、2904491694。总计 **14,329 条命令、12,378 个有效监督位置、3.059 GiB 回放张量**；单局 719–3,846 条命令、43–147 个单方回合。条件解码中有选择的前缀选项数中位数 3，P90 为 27，P99 为 60，最大 99。该示范集属于保存当时的规则轨迹；当前原生库额外自然结束的四个教师局为 719、1,048、906、899 条命令，用于核对局长量级；其余补采在本次调查结束时停止。

`512 × 16 / 12,378 ≈ 0.66`，原默认只消费不到一份数据量；`3,072 × 16 / 12,378 ≈ 3.97`，新默认约为 4 倍样本复用，与正常训练 `sample_reuse=4` 的资源尺度一致。回放先均匀抽局、再抽片段与位置，因此这里是总消费比，不是逐条遍历的 epoch。原 4 GiB 预算约被这 8 局占用 76.5%；该内存限制只描述容纳能力，示范多样性应独立评估。当前预算已提高到 8 GiB，题库只驻内存；继续扩大示范集时同时观察有效位置数、完整终局数和保留时间。

复杂度测量另取 `artifacts/training/训练-20261030215625/checkpoint.pt` 保存的 64 个在途局，按命令数排序，每隔 8 个取一个，在当前原生引擎内恢复并遍历全部合法解码前缀，按完整命令去重。8 个局面 `(已执行命令, ply, 合法命令数)` 为 `(22,4,171)`、`(214,17,42)`、`(386,30,95)`、`(500,34,141)`、`(685,47,259)`、`(849,48,79)`、`(1318,69,245)`、`(2096,105,178)`，均完成全量枚举；几何平均约 **131**。同一恢复点近期四个自然结束的自对弈轨迹为 **997 / 1,881 / 2,380 / 4,609 条命令**，对应 **60 / 94 / 121 / 203 个单方回合**。

若把上述稀疏分支样本当作整局恒定分支，`log10(b^D)=D×log10(b)` 给出约 `10^2100–10^9800` 的命令历史树代理量级。它只是帮助理解搜索规模的外推：真实分支随局面变化，有转置、强制命令和随机后继；规则也没有总回合上限。预训练次数按有效数据量和内存定，不按这个指数放大。当前深度 **16 条完整命令**是战术上限，样本整局平均每回合约 17–26 条命令；64 次模拟的渐进扩宽通常至多发现约 17 条根命令，实际到达的深度还受访问分布限制。本次保持训练 64/16 次模拟和深度 16，评测双方统一采用完整预算，先建立可比的棋力证据。

### 历史模型评测

每次新历史权重归档后冻结该版本，分别对比首个训练后版本与上一历史版本。默认每个对手 **32 局 / 16 个种子换边**，两者重合只测一次；`--history-evaluation-games` 可调，须为偶数，0 关闭新轮次。双方使用相同完整 MCTS 预算和深度（默认 64 / 16），无根噪声、温度 0、最大访问动作，无训练回合截断；命令上限仍保留，超限记 unknown。评测与训练使用独立 RNG，结果不进入回放，也不改变训练历史对手的挑战统计。

胜负只统计完整镜像对，纯胜率为 `胜 / 有效局数`，得分率为 `(胜 + 0.5×平) / 有效局数`。同种子的两局按一个独立样本处理，用 [Hoeffding，1963](https://doi.org/10.1080/01621459.1963.10500830) 的有界变量不等式构造保守 95% 得分区间：`均值 ± sqrt(log(40)/(2×完整镜像对数))`，截到 `[0,1]`。整轮样本齐全且区间完全在 50% 上方/下方时分别标“本轮领先”/“本轮落后”，其余为“差异未明”或“样本未齐”。32 局适合持续粗筛，想分辨几个百分点的细小差异需要调高局数；区间按每轮每个对手单独计算。

`history-evaluations/round-*` 保存冻结的双方小型权重、配置、进度、逐局 JSONL 和日志。归档频率高于评测速度时按顺序排队，不丢轮次、不并发启动多轮历史评测。训练停止后已启动的一轮继续，尚未开始的轮次在续训后启动；新一次启动会识别仍存活的评测进程。手工 AI 的定时评测独立保留，默认改为 **7,200 秒 / 2 小时**。

## 奖励与截断

真实胜 +1、负 -1、规则平局 0，折扣 1。没有伤害、击杀、存活或每步奖励；认输保持关闭。每 64 条命令将一个监督片段直接送入内存回放，继续同一局。

正常采集默认完成 **50 个单方回合**后，在进入第 51 回合时截断。开局随机抽取 **25% 完整局**免除此回合上限，保留真实终局供价值学习和校准；示范局全部免除，以完成独立预训练。完整局分配不看局势，保存在每局 `ply_limit` 中，暂停恢复后不重抽。`--max-ply` 调整回合上限（0 为关闭），`--full-game-fraction` 调整保留比例。它与搜索预算的 `--full-fraction` 是两个独立参数。

所有对局仍有 **20,000 条命令**资源硬上限，避免无法推进回合的异常长局耗尽资源。真实终局优先于任何截断。对局和结果记录区分 `ply_limit` 与 `command_limit`，状态统计分别累计 `ply_truncated`、`command_truncated`。这些都是采集边界，不修改游戏胜负规则。

截断局状态为 truncated，`winner` 仍为 null/unknown；边界环境只在内存用于自举。仅自对弈可以附加独立的 `soft_target`：

- 尚无可用校准器：价值损失屏蔽，继续使用策略和已有未来事实。
- 至少 **16 个真实自对弈终局**后，以完整局为单位分训练/留出集，每局最多 16 个均匀位置，用基地血差、单位数差、总生命差、人头差拟合换边对称的逻辑回归。只有留出 Brier 优于常数 0.5 才启用。
- 达到 **128 个真实自对弈终局**后，改用冻结的当前发布模型估计实际截断边界的价值。
- 软值限定在 ±0.98、损失权重 **0.25**，记录来源类型、视角、模型版本和真实终局数量；真实终局仍使用原始 ±1/0 标签。`--calibration-games`、`--bootstrap-after-games`、`--bootstrap-weight` 可调整。

这是有权重区分的价值估计，不将截断补成获胜。软标签取值小于 1 本身不能保证策略严格偏好更早的真实胜利；硬上限也不承担血量判胜或规则衰减功能。

回放只在内存保存近期最多 256 局、8 GiB 张量，超限按最早入池整局淘汰；先抽局再抽片段/位置，已有真实自对弈终局时半批次优先取这类数据。每个新策略样本提供 4 次采样额度；终局/合格软目标到来另提供一批额度。辅助目标继续是实际未来 +2 ply 的基地血差、单位数差、总生命差、人头差变化，缺失后续时屏蔽。损失为条件策略交叉熵 + 加权价值 MSE + 0.1 × 辅助 SmoothL1；AdamW 学习率 0.0003，梯度范数上限 1。

## 保存与格式

默认每 3600 秒（1 小时）、Ctrl+C 或 STOP 保存：先停止分配和新学习、暂停原生推进，再收回神经响应、排空正式记录，通过屏障取得权威根状态。检查点保存模型、优化器、随机数、阶段/模仿进度、校准器、对手池、数据进度、发布版本、在途环境、每局回合上限以及手工 AI 预算与计划。未完成搜索从原命令起点及原绑定模型重算。改变并发时重分配原局，超出容量的局快照排队并随检查点保存；每次启动的时间/更新/局数限制独立计数。修改默认回合上限只影响新分配对局。Web 控制方式及独立定时对弈见[训练控制台](TRAINING-WEB.md)。

恢复只接受 `haojie-classic-training-v3`，模型/监督仍为当前的分层解码 v2。滚动恢复点保留必要临时权重、自对弈在途局面及小型元数据，回放张量不落盘。重启自对弈时从空题库、零消费额度开始，沿用棋局继续采样；未完成预训练时重新采集完整示范，再补完剩余模仿更新。累计训练/示范计数保留，当前示范采集进度单列。周期保存不影响进程内题库。旧的含回放 v3 文件仍可读取。日常只在历史模型入池时归档独立权重，不写逐局目录、NPZ 或累计结果日志。具体预算与恢复边界见[运行说明](../../training/README.md)。

本次保留原辅助目标、固定网络容量和关闭认输；不做网络扩容/容量试验或数千局长度基线。功能验收与吞吐记录见状态入口。
