# 训练调查：一张 RTX 3060 能否把《浩劫》训练到赢熟练玩家？

2026-11-07。调查对象为 classic、代码版本 `9d83905`、正式运行 `训练-20261030215625`。目标是对熟练真人有可重复的胜算。本文区分正式存档、临时性能对照、棋力测量和待验证方案。原存档保持停止，未调整生产参数。

**判断：值得继续研究这套规则引擎和搜索框架，不值得按原配置直接长跑。** 有一个已在这台机器上复现的性能问题：在途搜索同时需要 8 个冻结版本，GPU 只缓存 3 个，主线程反复重建网络。另一个问题是棋力：从 1,584 到 30,976 更新的定时评测，对简单档也没有赢过。两件事要分别解决；加速能让实验便宜，搜索产生的教材是否有用，要用对局检验。

## 推理慢在哪：同一起点的两次真实恢复

在 Windows / RTX 3060 Laptop 6 GiB 上，分别从**同一份正式存档**复制到两个临时目录。两轮均恢复 64 个在途局、空回放，启用分段诊断，使用 8×8、推理批上限 32、学习 batch 16、64/16 次模拟、深度 16。两类旁路评测和周期保存关闭；各运行 150 秒并正常保存。对照只在临时进程中把模型查找和发布两处的 GPU 缓存上限从 3 调到 12，未改变模型权重、搜索预算或对手比例。

| 指标 | 原配置：3 个槽 | 对照：12 个槽 |
| --- | ---: | ---: |
| 实际耗时，含最终保存 | 151.78 s | 151.31 s |
| 命令 / 命令每秒 | 135 / 0.89 | 3,447 / 22.78 |
| 主干 + 解码请求 | 9,712 | 198,491 |
| 新监督位置 / 学习更新 | 11 / 0 | 631 / 78 |
| 新增自然终局 / 截断 | 0 / 0 | 0 / 2 |
| 查找及装载推理模型的主线程墙钟时间 | 135.22 s | 0.79 s |
| 等待原生请求的墙钟时间 | 0.11 s | 0.17 s |
| 平均取批 / 按版本及操作拆成的组数 | 31.84 / 11.34 | 31.41 / 5.42 |
| 实际主干批 / 解码批均值 | 2.59 / 3.01 | 5.31 / 6.24 |
| PyTorch 峰值分配 / 峰值预留 | 125 / 136 MiB | 223 / 286 MiB |
| 运行中整卡活动率 / 功耗均值，各 40 次采样 | 31.9% / 24.0 W | 34.1% / 30.8 W |

原存档的 64 个根分别引用 8 个版本；34,234 次对照组查找只有 8 次未命中，同时最多驻留 8 个模型。代码在未命中时新建完整网络、转到设备并加载冻结权重；即使权重在 CPU 缓存里，重建仍要付费。原组约 89% 总墙钟花在这个入口，其中 134.22 秒是主线程自身 CPU 时间。**恢复窗口的命令吞吐提高约 25.6 倍**；两次都是固定墙钟、变化局面，且均无自然终局。长期每小时终局的收益需另测。

**固定工作量复核。** 从上述 8 个真实版本各取一个在途根，固定每个根的状态和一个非强制条件前缀，按版本顺序轮流调用 8 次 encode、8 次 decode，重复 4 轮，共 64 个请求。先预热，再用空 GPU 模型缓存开始计时。3 槽每遍均未命中 64 次，12 槽均为 8 次。普通 CUDA 模式各跑两遍，分别 **2.99/3.01 秒**和 **0.55/0.56 秒**；相同缓存配置重复前向也可有 BF16 数值波动。为核对正确性，另以 PyTorch 确定性算法及确定性 cuBLAS 设置按 12→3→3→12 的顺序复跑：**0.76→4.08→4.00→0.82 秒**，全部 496 个 BF16 输出数值逐位相同。这个轮换工作集专门检验缓存机制，和上表的端到端吞吐是两个分母。

旧的固定工作量基准是另一个有价值的参照：在冻结反馈、固定学习量及持续供给下，8×8 为 21.68 命令/秒、33.85% GPU 活动率；其主要开销是组织推理和提交算子。它和这次正式存档的区别在于模型版本工作集。修掉换模后，本次对照也回到这个吞吐量级：仅主干前向的主机提交段就占 65.74 秒。输入批量已接近 32，继续加 Rust 线程或单提批量上限不是首选。其次才值得比较同版本组批、条件头上下文的逐行拷贝、每组的 GPU→CPU 同步，及主干注意力 padding。此前 CUDA Graph / 紧凑推理的全链路对照无整体收益。

## 棋力证据：能输给谁，究竟测了什么

正式目录有 20 轮手工评测，19 轮完整、1 轮中途失败。按项目“同种子且双方换边均完成”的口径，简单 **0 胜 78 负**，普通 **0 胜 76 负**，困难 **0 胜 76 负**。未成对的另 1 局也是负。20 个冻结版本总共反复用了 **6 个不同种子**（每档 2 个）；这是固定题回归，不能把 230 局当作最新模型面对 230 个新开局。最近受评版 30,976 的三档分别为 0/4；正式最终权重为 31,195。正式目录有 16,544 和 27,168 的历史权重，但没有独立历史模型评测目录。对手池有 4 局训练期历史对战记账（旧版本胜 0 局），对阵时当前席位可跨发布版本，也不是双方同预算、冻结版本的独立换边评测。

**失败集中在对强一点的对手应对不及。** 全部 231 条原始手工对局在第 13–48 个单方回合内自然输了，简单档中位数是第 23 回合。相比之下，仓库此前抽到的四个自然自对弈要 60、94、121、203 回合才结束。延长训练对局能增加真实价值标签，但当前对手甚至不用等到 50 回合就能赢；优先复盘前几十回合的攻防更直接。简单教师已经有规则启发式、进攻目标和行动顺序，和随机对手相距甚远。

**本次新种子实战。** 冻结正式最终权重 31,195，用现有 `evaluate` 入口，简单档、64 次模拟、深度 16、无搜索噪声、无训练回合截断。评测主种子 20261107 抽得未在上述评测出现的开局种子 708486795，同种子双方换边。模型执先在第 32 个单方回合、433 条命令后负；执后在第 21 个单方回合、252 条命令后负。两局模型分别执行 19、10 条普通攻击命令，教师分别 104、82 条；第二局教师前几个攻击就连续指向模型基地。这是一组值得复盘的实战，攻击次数会受场面和可用兵力影响，不应直接用作奖励。这个新种子只有一个独立换边对。

另做了一项策略诊断：按对局 ID 排序，取正式存档的全部 64 个在途位置，从各自环境重新请求简单教师的下一步；固定该步的合法解码路径，在 CPU 上比较两个冻结网络的原始条件策略。64 个位置有 194 个非强制前缀。16,544 与 31,195 两版逐级贪心均只有 **4/64** 个位置走出教师的整条命令；前缀首选分别匹配 80/194 和 76/194。教师选择的平均负对数概率分别为 **1.62、1.74**，在每个合法前缀上均匀分配为 **1.49**（越低表示分给教师的概率越高）。位置来自同一恢复点、含 48 局自对弈和 16 局历史对手，没有使用 MCTS；教师选择也未必唯一正确。这项诊断指出一个具体可测的问题：当前策略在自己走到的局面上给教师走法多少概率、搜索能否把这些走法找到。不能把教师一致率当棋力分。

## 架构里哪些地方影响棋力

1. **系统有可以保留的基础。** Rust 执行真实规则、手工 AI 和随机 PUCT；搜索边是完整命令，依实际决策方转换价值，同一搜索内复用局面。Python 主线程在单卡上用 BF16 运行 550 万参数实体 Transformer；状态主干、分层策略、价值和未来事实预测共享编码。协调线程组织对局和回放，评测权重冻结。模拟随机数与正式推进分开。现在的证据不指向重写引擎或扩大网络。
2. **胜负监督很薄。** 只有当前对当前的自然终局提供主价值头的硬标签。对手/教师对局保留当前席位的深搜策略和辅助事实，输给教师并不会直接变成主价值头的败局标签；正常阶段教师自己走的动作也不是模仿标签。318 个截断全部保留 unknown。自对弈自然终局达到 128 局后，截断会改用当前网络在边界的预测（权重 0.25）；现有 83 局尚未到门槛。建议对独立整局按早中晚阶段验证价值预测，开关自举以前看它是否超过常数及已有简易校准器。
3. **搜索可能只会反复教自己已经偏爱的动作。** 已测 8 个在途局面有 42–259 个不同合法完整命令，几何均值约 131。按渐进扩宽，16/64 次模拟根通常至多发现约 8–9 / 16–17 个完整命令。深度上限是 16 条命令，而已测自然局平均每个单方回合约 17–26 条，弱网可能来不及看到对方反击。只有 25% 的深搜决策和示范决策产生策略监督，强制操作不提供策略选择。先在有已知斩杀、解围或必须应对的局面测“候选找到了吗、最终选了吗、搜索比裸策略好吗”，再决定扩大预算、改根分配或改动作表示。
4. **预训练和持续纠偏是两件事。** 正式存档做的是 8 局简单教师、512 次模仿更新。新建默认是相同 8 局、3,072 次；按已有示范的 12,378 个位置，约从 0.66 倍消费增至 3.97 倍。新默认没有完整棋力对照；重复同八局也没有增加开局和应对的多样性。优先对比按不同种子收集的示范、在模型自己走到的局面请求教师标注，条件允许时再加入熟练玩家棋谱。
5. **评测本身也在抢预算。** 正式运行保存的间隔为 1,800 秒，新建默认 7,200 秒。完整手工轮次的墙钟中位数为 32 分钟，20 轮总存活时间约 10.83 小时。每轮子进程在同卡开一条对局通道，每次单请求推理，逐局串行；手工及历史评测有各自的调度器。这是占用机器的时间，不是从训练吞吐直接扣除的 GPU 小时。优先减少重复固定题的频次，并在充足新种子上批量做有决策价值的比较。
6. **权重有在动，价值准确度仍要独立验证。** 比较版本 31,184 和再做 11 次更新的正式权重，5,503,366 个 BF16 参数里有 1,533,123 个数值变化，包括策略头和价值头。83 个独立真终局的胜方为玩家一 49 局、玩家二 34 局。面板上的 Brier 0.186（17 局留出、常数基线 0.25）是四项公开局势特征的独立校准器成绩，不是神经网络价值头的分数。该留出集也来自自对弈；检验真人目标时，还需要模型对多种打法的评价能力。

## 论文支持什么

| 原始研究 | 与本项目直接相关的结论 |
| --- | --- |
| Wu，[Accelerating Self-Play Learning in Go](https://arxiv.org/abs/1902.10565) | 深快搜索随机化、策略监督和辅助任务能显著改善围棋的自对弈效率。论文超过 ELF 最终网络的运行用了不到 30 张 GPU、19 天；50 倍是其围棋系统整套改进的比较，不能换算成本机天数。 |
| Danihelka 等，[Policy Improvement by Planning with Gumbel](https://openreview.net/pdf?id=bERaNdoegnO)，ICLR 2022 | 小预算下根动作覆盖不足时，普通访问分布可能不给出更好的策略。论文把无放回抽样、根预算分配与改进策略目标结合；《浩劫》已有按先验无放回抽候选，单有这一步并不等于论文算法。 |
| Ross 等，[A Reduction of Imitation Learning and Structured Prediction to No-Regret Online Learning](https://proceedings.mlr.press/v15/ross11a.html)，AISTATS 2011 | 学习者一旦偏离教师轨迹，就遇到训练里少见的状态。让教师标注学习者实际访问的位置，是比单纯增加模仿次数更有依据的对照。 |
| Pardo 等，[Time Limits in Reinforcement Learning](https://proceedings.mlr.press/v80/pardo18a.html)，ICML 2018 | 采集时限不属于游戏规则时，应区分截断与终局，可以在边界自举。它支持保留 unknown；哪一个估值器、何时启用、给多大权重需要本游戏的数据。 |
| Vinyals 等，[Grandmaster level in StarCraft II using multi-agent reinforcement learning](https://www.nature.com/articles/s41586-019-1724-z)，Nature 2019 | 复杂策略游戏达到高手水平有先例：人类数据初始化、多类对手训练，最终面对真实玩家评价。它支持使用真人基准及对手多样性，没有提供一张 3060 在《浩劫》成功的概率。 |

## 如何决定下一笔算力值不值得花

| 顺序 | 实验及验收 |
| --- | --- |
| 1. 修复推理模型缓存 | 保持每个根的冻结版本、公开信息和随机语义；给两处缓存策略同一上限或按活跃版本与显存预算保留。用含真实混合版本的恢复点验收。长跑至少覆盖多轮发布、新历史归档、回放填充，单列评测开关，比较相同墙钟的请求、命令、样本、真终局和显存峰值。 |
| 2. 建立进步判据 | 留下固定回归种子，再冻结一组未参与训练/调参的种子。相同版本的引擎、双方相同完整 64 次搜索/深度 16，先后手交换。新对旧直接打，同时对简单档找出第一次有重复性的胜利。按镜像对计分，报告胜/和/负/unknown，预定样本数。现有 32 局只有 16 对，保守 95% 区间半宽约 34 个百分点；适合筛选大差距，接近五五开时另安排更大固定样本。 |
| 3. 只买有信息的训练实验 | 同一墙钟预算比较：现有配方；更广或在策略状态上标注的教师监督；前者中表现较好的方案再单独检验终局比例或根搜索分配。记录新增独立终局和每小时真值监督，给每个候选相同实战搜索预算。先用一小段固定预算筛选，领先方案换训练种子复验；战术题与直接对局都无改善就换假设。 |
| 4. 直接验收熟练真人 | 在测试前约定“熟练”（有足够实战、熟悉合成/反应/胜利条件），固定模型、规则、思考时间与是否可悔棋，并隔离用过的训练棋谱。多位不同风格玩家、双方轮换、保留完整棋谱；分别报告对每人和整体的成绩及不确定性。首次赢一盘是里程碑；若目标是稳定占优，则需在预定测试中得分率区间下界超过 50%，并说明结论对应的玩家群体。 |

建议首轮把算力写成一张能执行的预算表：在性能修复通过后，先给原配方和单一改动各 **6 个单卡墙钟小时**（建议的筛选预算，不是预计达标时间）；数据采集、教师标注和学习均入账，评测另列。用相同起点和搜索预算对比，记录每小时新增真终局及对局成绩。先用 16 对未见种子直接交手筛选大差距；只有出现实战改善才用独立训练种子和新评测种子加码。按不确定性和可用真人数决定最终测试规模。现在只有一条正式训练轨迹、没有对真人的比赛，也没有不同算力下对真人的学习曲线；从这些记录推导“成功率百分比”或“预计训练多少天”都没有统计依据。
