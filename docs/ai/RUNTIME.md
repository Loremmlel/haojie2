# 运行内核与双端对应

本文记录当前 TS / Rust 状态表示、执行与采样的对应关系。运行性能的阶段报告和冻结版本见[历史索引](HISTORY.md)。

## 表示与生命周期

运行局面与外部快照分开。外部进入 TS 拥有型运行器时复制一次，之后直接持有规则数据；Rust 的 State 从入口解析一次，连续采样不再经过 Observation Value → State。外部 applyCommand 成功仍导出独立快照：入口已整图隔离的数据直接移交并删除运行标记，共享分支则复制后导出，避免重复复制。非法或未知随机结果丢弃工作分支。

| 责任           | TS                                           | Rust                                        | 共同约束                                                |
| -------------- | -------------------------------------------- | ------------------------------------------- | ------------------------------------------------------- |
| 实体定位       | runtime/position 的 EntityHandle、槽与身份表 | core/entities 的 EntityHandle、EntityIndex  | 有序数组决定遍历；槽记录当前位置，不能缓存过期实体对象  |
| 热实体字段     | Unit 的已知类型与 copyUnit                   | UnitData、Charge、AbilityUsage、Effect      | 不把实体重新解析成 JSON；可选字段缺失保留原义           |
| 命令及节点     | Command、ActionSpec、类型化 Prefix/Choice    | CommandKind、Command、Action、Prefix/Choice | 内部构造直接进规则，外部未知输入仍校验                  |
| 图鉴与特征编号 | CATALOG、预编译种类/角色映射                 | Catalog::by_kind、kind_codes、vocab_codes   | Rust 数值来自同一嵌入规则包，不能复制另一份规则常量     |
| 公开只读视图   | publicPositionView / viewPosition            | public_view / PublicPosition                | 显式白名单与观察方；无权威根、正式 RNG 或未揭示对方暗选 |
| 类型化分支     | forkRuntimePosition、own                     | State::fork、Rc::make_mut、SharedFields     | 分支内写入隔离；成功由拥有型运行器接续，失败不提交      |
| 独立外部快照   | exportOwnedPosition / clonePosition          | State::clone                                | 调用者修改返回数据不能污染输入或其他分支                |
| 策略正式步进   | TrainingEnvironment::stepTyped               | boundary::step_typed                        | 跳过内部重复解析，仍检查操作者权限与完整规则            |
| 同步编码       | createSamplingEncoder                        | encode_sampling                             | 直接读公开类型；存在掩码、实体次序、模型维度不变        |

TS 使用普通对象的紧凑实体复制及冷字段的明确写入前分离，删除通用 Proxy 图。Rust 以每个类型化实体为 Rc 复制单元，首次可变借用再分离。两端均保留有序实体列表、独立工作分支和相同提交边界；提前复制与可变借用时复制是所有权机制的差别，不改变规则或查询流程。

手牌、亡者、反应、光环、延迟效果和时钟属于冷数据或历史数据，读取不应触发复制。TS 的 own 必须在修改这些集合及其内容前调用；直接替换整个集合已获得新所有权。时钟帧中的实体快照不被后续结算原位修改。Rust 反应源和时钟帧已直接保存类型化快照，不再序列化/反序列化 Unit。新字段必须明确属于热实体、冷可变集合、历史快照或外部信息，不能默认为可共享可变对象。

JS 外部调用者可能提供别名、环或非普通对象。TS 在导入边界识别后走明确的整图复制兼容路径，保持已有别名语义；正常运行内核不会每步重测整图。公开 JSON 和 Rust 入口不具有 JS 对象身份。

实体表按分支共享布局，结构变化时重建；同长度替换和时钟原位替换还核对槽中的实际 ID。缺失身份只在数组中确实出现时触发修复，不能因基地或死亡来源查询反复分配整张表。句柄只属于当前运行环境，不写入存档或跨对局复用。

## 查询、分支与结算

一次决策的公开视图、动作树、来源准备、属性与空间查询共同存活；下一局面必须创建新的决策上下文。缓存不跨状态失效边界。动作树仍按原顺序惰性展开，选择失败后的回溯、4096 节点预算、策略随机源以及正式 RNG 相互独立。

无参数动作在建立动作列表时已经完成公开预检；展开根叶子时复用该次结果，参数展开后仍重新检查，权威提交不复用预检。TS 用私有命令身份表保存结果及预检时的 JSON 签名；规范化后的副本与该签名相同时才复用，公开动作被原地改写（包括数组参数）后重新预检，返回的根叶子仍保持命令副本，避免给公开动作协议增加字段。Rust 的私有动作列表不暴露可写命令，内部 `Action.initial_inspection` 保存相同结果；`start` 只复制命令，`prepare` 只移除没有路线的方向参数，不改命令，因此根叶子直接复用。两端都只在同一个只读局面和原始动作命令上复用，新增参数、另一操作者或下一局面均不命中；局面及其子对象在树存活期间不得原位修改，沿用批次预检器的既有约定。

动作列表、逐动作资格和树内路线查询共用原实体属性缓存。TS 以这次只读局面的实体对象为键，Rust 以局面中原实体的稳定借用地址为键，只比较身份、不解引用缓存键；缓存与只读局面共同结束，不跨状态保存。借用能力会建立不同种类/次数的投影，TS 使用投影对象的独立键，Rust直接计算投影属性。攻击操作投影、后续规则分支与变化后的状态继续按各自实际数据求值，不沿用原实体结果。

移动与部署的最后一个落点参数按整族准备：TS `createCommandInspector.points` / `createMoveQuery.points` 与 Rust `Queries::points` / `actions::points` 共用原阶段资格、移动来源和部署卡牌准备，再按原 `ALL_CELLS` / `all_cells` 顺序查询精确占位和可达场。部署虚拟实体每张卡只建立一次，部署行与占位索引只属于当前只读局面；普通移动和 2×2 移动的成功准备直接形成可用叶子，冲撞候选继续完整预检死亡、弹出和返回空地。TS 用空值筛除失败落点，Rust 用规则失败结果筛除；两端不为不合法点重复建立叶子、操作者检查和公共阶段预检。其他参数仍走原检查，权威提交始终重新验证。

施法选择在复制前共用 TS `prepareCast` / Rust `spells::prepare` 校验，仍先检查卡牌、目标、坐标和献祭，再进入反制随机边界。TS `prepareCastInspection` / Rust `spells::prepare_inspection` 与正式施法共用反制来源、区域覆盖和全栈目标计算：有可反制来源时返回 uncertain；爆弹或烈焰风暴没有敌方覆盖时直接 available；其他后果继续原有完整模拟。沉默、万法真君冻结、继承反制、当前阵营和 2×2 逐格覆盖使用原规则，候选顺序与权威施法随机消耗不变。

合法性预检只消费错误或第一个未知随机边界，不返回模拟局面。TS `transition(preview)` 与 Rust `preparation::apply`、`combat::apply_prepared`、`reactions::move_runner` 在完整动作后省去最后的旗帜、虹吸、部署行和终局派生同步；这些尾部操作没有规则拒绝或随机请求，结果随预检分支丢弃。动作内部会影响后续合法性、死亡、反应或回合切换的同步仍照常执行，正式提交保留全部后处理。

移动用单来源可达场保存深度和前驱，多个落点直接读同一结果；需要真实路径时才重建。攻击广搜用棋盘数字索引、深度、前驱及访问位，保留向下、向上、向右、向左的搜索次序、最短路径和正面优先规则。方向/落点候选不因重写而排序、裁剪或换成近似几何判断。显式穿透路径和复杂技能仍进行原有精确检查。

攻击预检产生的准备结果直接进入同次模拟结算，避免再算一次属性和攻击路径。准备结果不可跨正式状态复用。随机攻击、伤害、死亡、反伤、反应、复活、生成实体、召唤、部署、法术、合成、神龛和个人/全局时钟都由同一个工作分支继续处理；没有切换回旧 JSON State 的适配层。

TS 搜索在建立初始想象局面时导入一次运行状态；内部概率分布通过 `applyRuntimeCommand` 推进独立分支，并可注入独立随机源，中间分支无需逐次导出快照再导入。外部 `distribution` 默认仍调用 `applyCommand` 返回独立快照。控制台三档教师运行同一 TS 静态包；Rust 原生训练的规则分支继续使用类型化运行状态，正式 RNG、搜索随机源和外部快照所有权保持各自边界。

| ------------------------ | --------------------------------------- | ----------------------------------- |
| 移动、冲撞与反应         | commands/movement、combat               | commands/movement、reactions        |
| 攻击、逐份伤害、死亡连锁 | commands/combat                         | commands/combat、damage             |
| 召唤、部署、装备、资源   | commands/game、abilities、setup/shrines | commands/preparation、setup/shrines |
| 技能、复活、法术与反制   | commands/abilities                      | commands/abilities、spells          |

| 回合时钟与持续状态       | commands/lifecycle、core/state          | commands/lifecycle、core/resolution |

## 编码与外部边界

热实体、效果、反应源、时钟快照和候选命令直接写数值行；避免临时字段数组、全实体 Value 和线性类别搜索。少量低频记录字段继续无损保留在动态扩展数据中，它们不是每步权威状态与公开 JSON 往返。固定行与 TinyPolicy 投影在同一次决策内复用。

TS decoder、教师编码、教师检查与原生记录审核在单次观察内复用 `createDecisionEncoder` 的固定基表；候选、日志及每次返回的张量保持独立所有权。Rust 的树内 `BaseEncoding` 与采样编码使用同一生命周期，实体顺序、候选顺序、掩码和数值不因复用而改变。

传输仍是现有二进制张量协议。原生宿主复用发送字节缓冲，完成同步写入才允许下一次覆盖；Python 解码继续拥有独立张量。状态/记录哈希仍使用既有规范编码；类型化序列化改变 JSON 键的书写顺序时，规范哈希必须相等。TS 旧存档指纹和历史轨迹不改写。

## MC-Q v2 分解采样对应

控制台新增的方法不改变旧记录采样或正式规则。TS `src/ai/training/sampling/mc.ts` 的 `mcSearch/sampleMc` 与 Rust `training/sampler.rs` 的 `mc_search/external_mc` 共用相同流程：剩余候选评分、独立随机源的Gumbel选择、逐选择实际输入回调、惰性子节点、权威提交、公开拒绝日志与回溯。掩码和类别250日志随搜索推进；成功/Pass返回，空分支排除再选择，预算耗尽保持unknown。完整参数域不缩减，不预枚举完整命令。

Rust编码的固定实体区用Rc共享，只复制候选及日志尾部；TS参照复制输入避免回调别名污染，这是语言所有权差异，不是算法分叉。`tests/runtime/mc-context.differential.ts` 调用真实原生host，逐张量、选择、前缀、Pass核对两端；Python同时断言样本就是此前推理输入。强制节点不要求一次不存在的网络推理。正式命令随机数与采样随机流继续独立。

## 诊断与维护

`kernel-profile` 是独立 Cargo feature；默认构建没有这些计时或分配探针。它记录嵌套独占/包含时间，以及分配次数、累计申请字节、释放次数、累计释放字节。18 个分项包括状态导入/导出、公开视图、候选、规则准备、属性、路径、分支、实体复制、预检模拟、正式结算、编码、哈希、协议和固定策略计算。累计申请量不等于驻留峰值或实际拷贝字节；包含时间也不能相加。正式倍率只来自无探针的预热、交错测量。

引擎工作层仍执行真实候选树、预检、正式结算和编码，固定 TinyPolicy 计算另有计时。完整应用层固定实际 PyTorch 检查点、种子、预算与并发，测量采样、更新及恢复点保存。独立记录审核按实际工作量另记；模型等待与前向时间有重叠，不重复累计为总成本。

新增规则或状态字段后须更新对应类型、分离策略、公开白名单和编码覆盖；至少检查非法失败、概率边界、反应顺序、同长度实体替换、快照独立性与连续运行。开发验证入口见[原生引擎](../../native/engine/README.md)；既往实测结果见[历史索引](HISTORY.md)。
