# 运行内核与双端对应

本文记录 TS / Rust 状态表示、正式执行、公开动作树与编码的对应关系。既往采样优化和冻结版本见[历史索引](HISTORY.md)；新训练架构与测量见[验收记录](../../training/native/VALIDATION.md)。

## 表示与生命周期

运行局面与外部快照分开。外部进入 TS 拥有型运行器时复制一次，之后直接持有规则数据；Rust 的 State 从入口解析一次，连续采样不再经过 Observation Value → State。外部 applyCommand 成功仍导出独立快照：入口已整图隔离的数据直接移交并删除运行标记，共享分支则复制后导出，避免重复复制。非法或未知随机结果丢弃工作分支。

| 责任           | TS                                           | Rust                                        | 共同约束                                                |
| -------------- | -------------------------------------------- | ------------------------------------------- | ------------------------------------------------------- |
| 实体定位       | runtime/position 的 EntityHandle、槽与身份表 | core/entities 的 EntityHandle、EntityIndex  | 有序数组决定遍历；槽记录当前位置，不能缓存过期实体对象  |
| 热实体字段     | Unit 的已知类型与 copyUnit                   | UnitData、Charge、AbilityUsage、Effect      | 不把实体重新解析成 JSON；可选字段缺失保留原义           |
| 命令及节点     | Command、ActionSpec、类型化 Prefix/Choice    | CommandKind、Command、Action、Prefix/Choice | 内部构造直接进规则，外部未知输入仍校验                  |
| 图鉴与特征编号 | CATALOG、预编译种类/角色映射                 | Catalog::by_kind、kind_codes、vocab_codes   | Rust 数值来自同一嵌入规则包，不能复制另一份规则常量     |
| 公开只读视图   | publicPositionView / viewPosition            | public_view / PublicPosition                | 显式白名单与观察方；无权威根、正式 RNG 或未揭示对方暗选 |
| 类型化分支     | forkRuntimePosition、own                     | State::fork、Rc::make_mut、SharedFields     | 分支内写入隔离；成功由拥有型运行器接续，失败不提交      |
| 独立外部快照   | exportOwnedPosition / clonePosition          | State::clone                                | 调用者修改返回数据不能污染输入或其他分支                |
| 策略正式步进   | TrainingEnvironment::stepTyped               | boundary::step_typed                        | 跳过内部重复解析，仍检查操作者权限与完整规则            |
| 同步编码       | createSamplingEncoder                        | encode_sampling                             | 直接读公开类型；存在掩码、实体次序、模型维度不变        |

TS 使用普通对象的紧凑实体复制及冷字段的明确写入前分离，删除通用 Proxy 图。Rust 以每个类型化实体为 Rc 复制单元，首次可变借用再分离。两端均保留有序实体列表、独立工作分支和相同提交边界；提前复制与可变借用时复制是所有权机制的差别，不改变规则或查询流程。

击退占位排除与合成材料移除只建立内部几何视图。TS 使用占位忽略列表或过滤单位的浅视图，Rust 使用 `State::fork` 后过滤独立的单位数组，避免复制只读扩展 JSON；共享实体不在视图中写入，几何结果只返回布尔值或坐标，不作为外部快照交付。过滤改变数组长度时，实体索引在查询前分离并重建布局，原分支不受影响。

命令总是开启新的事件列表。TS 分支先共享旧引用再直接替换，Rust 的 `State::fork_command` 在共用分支构造中直接建立空列表，避免深复制后立即清空；普通 `fork` 仍保留旧事件。旧守护标记的来源列表只在存在缺少 `guardSourceIds` 的已使用守护时补全，保留已有 null 与原阵营、能力判定。

死亡历史追加只复制外层有序数组，复活写入前只分离对应条目；TS 的整图别名兼容入口仍保留原引用关系。Rust 使用 `Rc<Vec<Rc<Value>>>` 保留未知记录字段与原序列化内容，公开视图、编码和规范哈希直接读取同一份只读历史。

TS 命令对象本来只保存实际参数；Rust 的 `Command` 内联常用种类、来源、目标、坐标和方向，三个热 ID 使用 `Rc<str>`，方向的四个已知值借用静态字符串，未知输入保留拥有型字符串。其他参数由 `Rc<CommandExtras>` 共享并在写入前分离，展开方向不再复制冷参数。平面 JSON 的字段顺序、缺失、false、空数组和解析语义保持原样。树内的参数前缀及剩余步骤只读共享：TS 使用对象和数组引用，Rust 把完整步骤保存在私有动作表，固定步骤借用静态切片，仅需要材料、自选或方向扩展的动作一次分配完整步骤；`Rc<Prefix>` 仅保留动作索引、命令和偏移，叶子无需为不存在的后续前缀内联预留整份命令。Rust 坐标选择键在输出协议时才格式化字符串，内部编码直接读取相同的提交路径标志，目标选择键和引用共用 ID。

Rust 文本种类编号使用 `Rc<str>`，热点只读查找借用原键；需要拥有型键的旧入口仍返回独立字符串。静态动作 ID 使用借用字符串，继承、配方和带来源的改判 ID 继续拥有动态内容，根选择键到协议输出时才格式化。TS 使用原不可变字符串引用；两端的文本内容、顺序、序列化与哈希不变。

手牌、亡者、反应、光环、延迟效果和时钟属于冷数据或历史数据，读取不应触发复制。TS 的 own 必须在修改这些集合及其内容前调用；直接替换整个集合已获得新所有权。时钟帧中的实体快照不被后续结算原位修改。Rust 反应源和时钟帧已直接保存类型化快照，不再序列化/反序列化 Unit。新字段必须明确属于热实体、冷可变集合、历史快照或外部信息，不能默认为可共享可变对象。

JS 外部调用者可能提供别名、环或非普通对象。TS 在导入边界识别后走明确的整图复制兼容路径，保持已有别名语义；正常运行内核不会每步重测整图。公开 JSON 和 Rust 入口不具有 JS 对象身份。

实体表按分支共享布局，结构变化时重建；同长度替换和时钟原位替换还核对槽中的实际 ID。缺失身份只在数组中确实出现时触发修复，不能因基地或死亡来源查询反复分配整张表。句柄只属于当前运行环境，不写入存档或跨对局复用。

Rust 扩展映射的键和值分别用 `Rc<str>` 与 `Rc<Value>` 保存。分支首写复制映射时只增加不可变键的引用，白名单视图复用选中键和值，不持有完整权威映射；普通快照克隆仍深复制值。外层仍为有序 `IndexMap`，底层键查找使用 `FxBuildHasher`，遍历和序列化继续读取原条目顺序。键内容、插入与删除顺序、Unicode 和数字字符串键的协议保持原样。TS 对象的属性键由运行时共享。Rust 内部属性结果的固定模式字符串也使用只读字面量，其他兼容输入仍拥有原字符串，输出模式字段不变。

Rust 的基地和部署行 JSON 使用 `SharedValue(Rc<Value>)`，读取及分支只共享这两份独立子树，首次可变访问才分离；整字段替换直接接收新值。普通快照、运行分支和公开根随后写入均不能影响彼此，原 JSON 顺序、未知字段和规范哈希保留。TS 的这两种小容器直接浅复制，部署行中的只读数组继续共享；两端只采用各自语言的轻量表示。

Rust 的实体索引、空间查询、预检和动作树中的十二处纯查找缓存使用固定版本的 [FxHashMap](https://docs.rs/rustc-hash/2.1.3/rustc_hash/)。这些缓存只做键查询，不通过哈希桶次序生成候选或协议；有序实体、候选和扩展字段仍使用原有顺序容器。TS 对应缓存继续使用 `Map`，缓存内容和生命周期相同。

战斗规则数值始终来自同一规则包。TS 直接读取 `COMBAT_RULES` 的数值属性；Rust 在原加载校验循环中同时建立已校验路径的数值索引，`Catalog::rule` 不再逐次解析同一 JSON pointer。原 `combat` 数据、加载校验顺序和错误内容保留，未索引路径仍使用原 pointer 解析；图鉴加载后只读，不在局中改写这些规则。

## 查询、分支与结算

一次决策的公开视图、动作树、来源准备、属性与空间查询共同存活；下一局面必须创建新的决策上下文。缓存不跨状态失效边界。动作树仍按原顺序惰性展开，选择失败后的回溯、4096 节点预算、策略随机源以及正式 RNG 相互独立。

冲撞中的强制继续移动由 TS `commands/game.ts::transitUnit` 与 Rust `commands/movement.rs::transit` 同步识别，只选当前行动方的 BW/SZF。对方上回合留下的 `move` 模式，在被当前方 BW 穿过时不能抢占这项约束。AI 候选也按同一行动方筛选；重叠期间仍先完成当前方的脱离，之后才允许结束移动或回合。双端夹具 `complete-transit-opponent-mode-*` 和双方行动权回归覆盖这一边界。

无参数动作在建立动作列表时已经完成公开预检；展开根叶子时复用该次结果，参数展开后仍重新检查，权威提交不复用预检。TS 用私有命令身份表保存结果及预检时的 JSON 签名；规范化后的副本与该签名相同时才复用，公开动作被原地改写（包括数组参数）后重新预检，返回的根叶子仍保持命令副本，避免给公开动作协议增加字段。Rust 的私有动作列表不暴露可写命令，内部 `Action.initial_inspection` 保存相同结果；`start` 只复制命令，`prepare` 只移除没有路线的方向参数，不改命令，因此根叶子直接复用。两端都只在同一个只读局面和原始动作命令上复用，新增参数、另一操作者或下一局面均不命中；局面及其子对象在树存活期间不得原位修改，沿用批次预检器的既有约定。

动作列表、逐动作资格、树内路线查询和攻击来源预检共用原实体属性缓存。TS 以这次只读局面的实体对象为键，Rust 在 `Queries` 中以局面中原实体的稳定借用地址保存 `Rc<Stats>`，只比较身份、不解引用缓存键；缓存与只读局面共同结束，不跨状态保存。攻击资格在原属性计算时点读取缓存，模式投影直接接收这份结果，不再以临时副本重复查询。借用能力会建立不同种类/次数的投影，TS 使用投影对象的独立键，Rust直接计算投影属性。只改变攻击预算的投影按下文复用不变字段；不同种类、蓄力和后续状态变化继续按各自实际数据求值。

移动与部署的最后一个落点参数按整族准备：TS `createCommandInspector.points` / `createMoveQuery.points` 与 Rust `Queries::points` / `actions::points` 共用原阶段资格、移动来源和部署卡牌准备，再按原 `ALL_CELLS` / `all_cells` 顺序查询精确占位和可达场。部署虚拟实体每张卡只建立一次，部署行与占位索引只属于当前只读局面；普通移动和 2×2 移动的成功准备直接形成可用叶子，冲撞候选继续完整预检死亡、弹出和返回空地。TS 用空值筛除失败落点，Rust 用规则失败结果筛除；两端不为不合法点重复建立叶子、操作者检查和公共阶段预检。其他参数仍走原检查，权威提交始终重新验证。

路障、冰痕和复活的最后落点也使用同一批查询：亡者参数节点仍完整保留，无效亡者前缀一次验证后形成空落点节点；路障和复活在同一来源内共用占位索引与纯落点可达场，每个点域只建一个模板，地标模板逐候选同步原坐标。广搜保留分数射程、多格起点、原格可达、敌方占位只能作终点及敌基地封锁。复活费用后生命上限不足以确保存活时，继续完整模拟死亡与随机边界。无反制的爆弹只准备一次共同施法条件，空区域形成确定叶子，受击区域仍完整预检；存在反制时沿用原路径。普通移动点域直接查询可达性，实际执行才展开精确路径。

预检在共用完整资格检查之后，省略纯阶段切换、附魔、装备、造墙、鼓舞和冰痕的确定性后果。正式结算仍执行全部效果；会死亡、产生随机或继续检查后续合法性的分支保留完整模拟。动作列表在生成前先排除没有普通预算的单位，巨大化、连续攻击、结束操作和手牌改判保留原入口。

继承能力直接追加技能与蓄力动作，保持原 traits 顺序及重复项；不再递归生成随后丢弃的移动、攻击、玉碎等动作，也不为这些废弃动作计算完整属性。技能实际资格、独立蓄力及使用次数仍由原能力命令检查。

未自选的常驻召唤、额外召唤和改判在完整只读资格后直接停在第一次随机边界；有自选参数时继续原模拟，保留老千K先随机组数再检查自选的顺序。改判候选按同一来源资格和实际部署时刻生成，正式结算复用相同准备函数。

树内方向候选与攻击叶子预检共用只读攻击路径查询；同一来源只建立一次非穿透阻挡场，逐目标独立复制格位、清除终点并封锁敌基地，再执行原广搜。方向节点只请求同一内部路线缓存的方向投影，不先复制随后丢弃的完整路径；公开完整路线查询仍返回独立路径。方向来自同一次精确广搜，自动路线仍按原算法惰性计算一次，保留最短深度、正面偏好和重叠起点行为。缓存只接受当前实体身份和相同位置、尺寸、阵营的预算投影，几何投影及基地 ID 与实体冲突的导入态回到原查询；返回的路径保持独立所有权。只读攻击者投影的属性也按投影身份惰性复用，正式结算、反击和连锁仍读取各自当时的局面。

施法选择在复制前共用 TS `prepareCast` / Rust `spells::prepare` 校验，仍先检查卡牌、目标、坐标和献祭，再进入反制随机边界。TS `prepareCastInspection` / Rust `spells::prepare_inspection` 与正式施法共用反制来源、区域覆盖和全栈目标计算：有可反制来源时返回 uncertain；爆弹或烈焰风暴没有敌方覆盖时直接 available；其他后果继续原有完整模拟。沉默、万法真君冻结、继承反制、当前阵营和 2×2 逐格覆盖使用原规则，候选顺序与权威施法随机消耗不变。

合法性预检只消费错误或第一个未知随机边界，不返回模拟局面。TS `transition(preview)` 与 Rust `preparation::apply`、`combat::apply_prepared`、`reactions::move_runner` 在完整动作后省去最后的旗帜、虹吸、部署行和终局派生同步；这些尾部操作没有规则拒绝或随机请求，结果随预检分支丢弃。动作内部会影响后续合法性、死亡、反应或回合切换的同步仍照常执行，正式提交保留全部后处理。

预检省去展示事实工厂；训练正式步进也省略随后会清空的展示事实和日志。TS `withoutRulePresentation` 嵌套 `withoutEventFacts`，Rust `without_presentation` 使用同步线程局部范围；两者均保留原始事件、序号及事件后处理。训练仍使用正式随机流、全部资源记账、尾部同步与终局判定，成功后才按原协议清空事件和日志，再记录哈希。普通游戏入口继续构造完整 actor、subject、area 和因果上下文。工厂外保留冰痕坐标、蓄力来源等原时点校验，异常和嵌套退出均恢复原作用域；抑制展示与 preview 随机边界相互独立。

移动用单来源可达场保存深度和前驱，多个落点直接读同一结果；需要真实路径时才重建。攻击广搜用棋盘数字索引、深度、前驱及访问位，保留向下、向上、向右、向左的搜索次序、最短路径和正面优先规则。方向/落点候选不因重写而排序、裁剪或换成近似几何判断。显式穿透路径和复杂技能仍进行原有精确检查。

攻击预检产生的准备结果直接进入同次模拟结算，避免再算一次属性和攻击路径。模式选择原时点的属性由同一只读投影保存，攻击准备只复用不受模式重置影响的攻击力和射程，模拟入口的第二次模式选择复用原状态属性；正式结算和状态变化后重新计算。反击在自身当前状态完成准备，随后直接把结果传给同次反击结算；两者之间只登记反击对，不重复准备，也不扩大捕获规则拒绝的范围。完整攻击后果返回后，预检省去只服务后续局面的命中列表和预算记账。

完整攻击准备通过后先检查两种窄预检：友方治疗没有有效标记，且攻击者不会触发未沉默的 s3/s12 随机后被动时，直接 available；非穿透伤害攻击没有有效处决，且正式攻击分布必先请求随机数时，直接 uncertain，包括 u8 暴击概率为 1 的情形。

另一个保守确定性判定在同批只读查询中惰性缓存：全部单位和地标的本体与继承能力均没有 `s3/s12/17p/20/u18`，当前攻击者还没有 `1/u1/u8`，且本次不穿透时，完整准备后的死亡、治疗、反射、标记和继承链不再请求随机或执行子攻击准备，可直接 available。其他单位的 `1/u1/u8` 只在自身攻击时掷骰；全局排除 u18 后没有自动反击入口，强夺也在本次掷骰遍历结束后才发生。沉默和休眠不放宽排除，防止击杀继承重新启用相关能力。新增攻击随机入口或自动攻击链时必须同步更新双端阻断判定及聚焦用例。其余攻击继续同一分支模拟，穿透的逐目标重新校验保留。准备结果不可跨正式状态复用。

动作树的完整几何目标域只在展开目标参数时构造。方向查询先按实体数组的原顺序取首个有效同 ID 目标，未命中才回退基地，仅包装当前目标；路线缓存按来源身份和目标 ID 内容区分，保留重复项、休眠过滤和基地同名语义。TS 树直接消费共享的 `trainingActions`，不再构造随后丢弃的完整参数元数据；公开 `trainingActionSpace` 仍立即生成原元数据快照。编码索引保持独立，其基地优先顺序不与几何目标域混用。

确定空前缀使用两端相同的候选掩码提前跳过，原候选数组、重复项和路径下标不变。对只剩最后一个固定参数的前缀，调用原参数展开及公开预检；没有任何 available 或 uncertain 叶子时置零。TS 用前缀身份 WeakMap、Rust 用前缀内部 OnceCell 缓存布尔结果，只属于当前不可变局面。多参数未补齐、材料组合和可反复延伸的路径保守保留，继续按原流程展开；不递归穷举整棵动作树。新掩码与实际排除 frontier 取交集，非零质量只分配给剩余候选，强制节点不消耗采样 RNG。合法友方治疗、概率未知、方向、路径和材料的完整叶子仍保留。

TS 搜索在建立初始想象局面时导入一次运行状态；内部概率分布通过 `applyRuntimeCommand` 推进独立分支，并可注入独立随机源，中间分支无需逐次导出快照再导入。外部 `distribution` 默认仍调用 `applyCommand` 返回独立快照。Rust 原生训练的规则分支继续使用类型化运行状态，正式 RNG、搜索随机源和外部快照所有权保持各自边界。

## 编码与外部边界

热实体、效果、反应源、时钟快照和候选命令直接写规范数值行及类型化行；避免临时字段数组、全实体 Value 和线性类别搜索。少量低频记录字段继续无损保留在动态扩展数据中。新模型根编码只读取固定公开根；候选、前缀、路径与 frontier 单独形成节点上下文。

TS 编码差分与历史记录审核在单次观察内复用 `createDecisionEncoder` 的固定基表；候选、日志及每次返回的张量保持独立所有权。Rust 的树内 `BaseEncoding` 与采样编码使用同一生命周期，实体顺序、候选顺序、掩码和数值不因复用而改变。

新训练协议身份为 `haojie-native-actor-v1`。逐局 FFI 传递 BF16 连续数、精确整数、存在位、参数路径和每层排除事实；正式规则保持原数值及 RNG 语义。C++ 根输入按引用去重，换根才传根表；状态和历史记录哈希继续使用既有规范编码。规范数值行仍用于 TS/Rust 差分；生产模型直接接收编码源头记录的类型化原始值，不将身份或存在位压入 BF16。

## 原生显式动作状态机

`online/runtime.rs` 用可序列化的前缀、每层精确排除集合和独立采样 RNG 推进惰性动作树。失败节点被精确排除；子树耗尽后在父层排除该子树。当前路径与完整 frontier 决定剩余尝试域，不保存或重放事件序列。每个随机选择交付实际行为概率，强制节点直接推进。完整参数域不缩减，不预枚举完整命令。

空前缀掩码不改变原候选下标，因此已有检查点的 cursor、excluded 和历史行为节点仍可读取。恢复或解除停放时，C++ 丢弃尚未采样的当前节点缓存，由 Rust 在同一规则局面重新交付当前节点及掩码；不改写已记录的输入、概率和历史掩码，规则状态及两类 RNG 原样接续。

规则与候选继续进行 TS/Rust 差分；原生检查和 `training/native/validate.ps1` 核对保存恢复、概率与连续轨迹。正式命令随机数与采样流独立。根缓存随当前参数发布失效，长根不持有权重租约；训练用当前参数一次前向重新编码原始公开输入，推理缓存不参与梯度计算。

## 诊断与维护

`kernel-profile` 是独立 Cargo feature，记录嵌套独占/包含时间、分配次数和累计申请/释放字节。默认构建仅保留内存预算所需的活动分配字节计数。累计申请量、活动容量和进程驻留峰值分别报告；包含时间不能直接相加。正式倍率来自默认构建的预热、交错测量。

Rust 默认使用 `allocator-mimalloc`，`--no-default-features` 可构建 System 对照。两者只切换底层内存分配，规则与采样共用同一源码；构建身份的 `allocator` 字段声明实际后端。开启 `kernel-profile` 时唯一全局探针也透传当前后端，不把 System 探针数据冒充 MiMalloc 分项。依赖随 Cargo 静态构建，不增加运行时服务或动态库下载。

引擎工作层执行真实候选树、预检、正式结算和编码。应用层固定实际消费量、模型规模、种子、学习预算与并发，测量采样、更新及恢复点保存。独立记录审核按实际工作量另记；模型等待与前向区间有重叠，整体成本使用管线墙钟。

新增规则或状态字段后须更新对应类型、分离策略、公开白名单和编码覆盖；至少检查非法失败、概率边界、反应顺序、同长度实体替换、快照独立性与连续运行。开发验证入口见[原生引擎](../../native/engine/README.md)；既往实测结果见[历史索引](HISTORY.md)。
