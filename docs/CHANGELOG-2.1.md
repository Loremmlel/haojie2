# 浩劫 2.1 · AI对战与宽屏布局

## 游戏玩法保持不变

保留26普通、28终极编号、59图鉴条目及2.x确定性规则；不实现3.0神龛模式，不修改人头收入、抽牌概率或棋子数值。冲锋号令继续储存8个己方回合。此版本新增的是本地对手和布局，不更换原规则含义。

## AI与存档

新增简单/中等/困难、选择先后手、暂停/继续、AI思考状态、内联Worker和分片降级。AI只读取公开Observation，复用引擎结算假想命令，不接触真实随机种子。人类和AI所属的临终行动、弹出和小屋效果按同一决策归属接口协调。

存储键和局面schema继续v2；Session可选match字段保存人机设置，没有字段的2.0/2.0.1旧存档仍按双人局打开。人机撤销回到人类决策边界，同时保留最近人类决策锚点应对超长AI操作序列；新建、载入和悔棋立即使旧搜索失效。旧号令期限迁移也覆盖这个锚点。

## 初版宽屏修改（已被下文2.1布局修正取代）

旧1091px以上布局用窗口高度决定棋盘栏宽，造成900px高桌面只有340px棋盘栏；切到三栏后还会比中等宽度更小。移除该高度计算，让宽度优先决定棋盘尺寸。

821–1279px使用两栏，手牌/战报在下方；1280px起使用三栏，中央列620–740px优先，两侧分别设合理最小宽度，最大容器1500px。较宽侧栏可独立滚动，棋盘本身不为“必须一屏放完”缩成小格。原CSS职责划分保留，状态与媒体查询归属于对应功能。

浏览器行为验收在同一高度检查900、1090、1100、1279、1280、1440、1680px，要求每个断点跨越后棋盘不缩小且不产生横向页面溢出；不把固定截图像素作为长期测试基线。实际测量在CI的layout-report.json中。

## 发布与验证

`npm run deploy`仍只生成完整单HTML并复制为根发布入口，`npm run deploy:check`保证根index与源码逐字节一致。内联Worker使发行包增大，但无新增运行时依赖、外部资源或API请求；主线程与Worker两份引擎是为离线与降级可用性付出的体积成本。

测试仍按core/ultimate/session/ai及browser分类，既有能力测试保持。新增AI和布局验收见docs/AI.md，默认完整file://与HTTP验收在GitHub Actions运行；受管理沙箱的辅助渲染测试不替代它们。

## 布局修正：宽屏一屏棋局

作者澄清“宽屏不滚动”是必要条件。之前移除高度限制、强制棋盘≥620px，虽然增大了格子，但让13行棋盘整体超出视口，是错误的取舍。不能把那版的“不缩小/最低宽度”断言当成不可变需求。

现改为1100px以上的全宽桌面工作区：56px紧凑顶栏，左边放双方基地、回合、棋子情报和固定操作栏；右边放AI状态、手牌、战报与固定存档工具。中央棋盘利用剩余高度，按照9:13保持正方形格子，不旋转、不拉伸、不依靠隐藏页面溢出。只有两侧长内容可独立滚动。

棋盘尺寸由实际分配的容器宽高决定。36px横向/74px纵向装饰空间只用于明确的边框、坐标和图例，不再预留几百像素的整行比分与状态。容器宽度低于1100px时继续自然流式布局；没有修改全局body的滚动行为。嵌入宿主可通过CSS变量--haojie-height提供可用高度。

验收覆盖1100×600、1366×768、1440×900、1920×1080、2560×1440及超宽屏等，检查全部117格可见且可命中、格子正方形、操作与存档按钮不出屏、页面无横纵滚动、长侧栏滚动不移动棋盘；包含展开技能说明、召唤、人机、死亡反应和胜负状态。游戏规则、AI参数和存档格式保持不变。

## 体验修正：AI行动节奏

按作者反馈，将AI原先约100毫秒的连续操作改为可读的逐步节奏：接手决策约1.5秒，通常每步约1.1～1.5秒，连续移动/部署适度加快；根据上一招的伤害数字、召唤揭示保留必要的展示时间。真实搜索与等待重叠，不重复加整段思考时间；缓存连招同样逐步执行。AI算法、三档预算、游戏规则、宽屏不滚动布局和存档格式不变。

独立测试节奏与取消机制，浏览器验收直接记录敌方生命标签的变化间隔，并验证计划已就绪、正在等待时的暂停、继续、弹窗、新局、读档和悔棋。等待结束后仍要校验当前局面，不允许旧计时器向新局面落子。
