## 一、开局把爆弹砸基地：已复现，主要是资源估值问题

构造首回合行动阶段：双方基地300血，场上无随从，手中一张剩4回合的爆弹。

| 局面                                   | 简单         | 中等         | 困难         |
| -------------------------------------- | ------------ | ------------ | ------------ |
| 空场，基地300血，新爆弹                | 炸基地       | 炸基地       | 炸基地       |
| 敌方已有20血投石机                     | 炸投石机     | 炸投石机     | 炸投石机     |
| 敌方基地20血                           | 炸基地获胜   | 炸基地获胜   | 炸基地获胜   |
| 空场，爆弹剩1回合                      | 炸基地       | 炸基地       | 炸基地       |
| 己方基地20血、敌方20攻随从已可攻击基地 | 炸掉进攻随从 | 炸掉进攻随从 | 炸掉进攻随从 |

因此不能笼统说“AI不懂用直伤解后排”。它在目标已经出现时会解掉投石机；问题在于目标尚未出现时，保留应对手段的价值太低。

`src/ai/evaluate.ts`中的计算可以直接解释开局行为：

- 爆弹固定基础价值22，剩4回合时实际留牌价值为`22 × (0.4 + 3 × 0.17) = 20.02`。
- 基地每点血价值3.1。爆弹造成20点基地伤害，得到62分。
- 空场丢牌的静态净收益为`62 - 20.02 = 41.98`，对比保留显著占优。

构造开局中，简单/中等/困难分别只用了4/8/69次模拟，均正常完成而非耗尽预算。困难还执行了对手回应。这个例子不能归咎于超时或没有神经网络；当前目标函数就在鼓励立即兑换基地伤害。

### 隔离敏感性实验

只在独立工作树把上述基础价值从22改为80，其余算法、概率和预算不动，重跑四个爆弹局面。三个难度均变为：空场保留；出现投石机则解掉；基地可斩杀则斩杀；将过期则仍炸基地。困难开局用了68次模拟。

这说明改善该行为不必先搜索未来好几个完整回合。**80只是诊断用扰动，不是已验证的平衡参数，没有提交到产品。** 正式实现应结合剩余期限、同类解牌数量、己方能否处理后排、当前战场收益和斩杀情况评价保留价值，避免从“逢牌就丢”变成“抱牌过期”。直接提高所有法术价值也会误伤及时保命、打组合和抢节奏。

## 二、大军压境仍偷家：有明确盲区，但不能把原局根因说死

当前实现并非没有防守：

- `src/ai/threats.ts::baseThreat`估计对方下一个可用行动窗口中实际能命中基地的攻击压力。
- `src/ai/evaluate.ts::explainEvaluation`在压力达到基地生命时给出很大的惩罚。
- `baseCoverValue`会保留能阻断真实攻击路径的部署、移动和造墙候选；不是只按走向敌方基地打分。

上表的即时威胁局面中，三个难度都选择解掉来犯随从。因此“所有时候都不防守”不成立。

可确认的边界是：`actionWindow`是可用性投影，不会移动敌方棋子，也不会凭空增加蓄力或抽牌。`baseThreat`由当前坐标直接计算命中路径，没有独立的逼近波次或双方攻破基地所需回合数评估。

诊断中，敌方20攻、4射程随从在`(5,6)`时，对己方`(5,1)`基地的威胁为0。让它合法移动到`(5,5)`并结束行动后，下一攻击窗口的威胁变为20。这里“移动回合不能同时攻击”的计算是正确的；缺少的是提前判断下一波压力，而不是把现在的0强行算成即时20。这个检查证明估计范围有限，**不等于重现了反馈中整场偷家失利**。

困难模式现有束宽2、深度7、对手回应根数2。深度计的是命令展开，不是未来7个完整回合。在大军、多操作或需要多步防守的局面里，搜索与候选裁剪可能无法弥补这个战略盲区。需要原局才能进一步区分威胁估计、候选缺失和预算耗尽各占多少。

### 建议实现顺序

1. 保留即时斩杀/保命判断，并确保真正能阻挡、解场、保护基地的候选不会被进攻排序全部挤掉；仍在相同完整回合边界比较收益。
2. 增加轻量的双方进攻时钟：到达可攻击位置需要的操作、后续实际攻击次数、基地剩余血量、路径遮挡、冻结/休眠等。先比较谁更早可能打穿，而不是比较面板总攻击。
3. 对危险波次做有限的一至两个相关行动窗口验证，并给防守候选预留预算。不要全局无差别加深搜索，也不要把“离基地很近”误当成“这个回合能移动加攻击”。

总攻击更高并不总意味着应该防守：自己本回合可斩杀，或对方大军更晚才能抵达时，偷家可能正确。目标应是减少明显败速更快的对攻，同时保留真正有利的抢杀。

## 三、规则修复后仍需同步一个AI估计捷径

精确引擎现在已经禁止0直接伤害触发策反，但`analyzePayload`仍通过`hitPackets`估计策反机会。后者为了普通攻击预估，会把投石机对满血目标的标记爆炸记作5伤害。于是一个构造局面中，估计器仍给出策反成功概率1，而实际引擎只扣5血、目标依旧属于敌方。

诊断脚本也记录了这个差异。它不会绕过已经修正的引擎规则，但可能让AI浪费策反牌或高估组合收益。下一轮AI工作应先把“攻击本体正伤害”机会估计与新规则对齐，再讨论战略调参，不能为了让AI估计成立而放松规则。

## 工作量判断与验收

留牌估值：较低至中等复杂度，不需要新算法框架。显著改善攻守切换：中等复杂度，重点是时间、候选和评价边界。要让各种诱饵、绕路和复合技能都应对稳健：持续的中高复杂度工作，不能靠一条“有人靠近就回防”规则保证。

正式改动至少覆盖：空场保留、有高价值目标及时解场、到期及时兑现、己方可斩杀不误回防、己方将被斩杀不无意义偷家、逼近压力下提前布防，以及新策反门槛。沿用少量稳定行为测试和命令行局面记录，核对原有工作量预算、真实胜负/局面收益，不用“增加搜索层数”冒充棋力提升。本次没有修改生产AI，也不声称胜率提升。
