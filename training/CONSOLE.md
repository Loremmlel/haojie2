# 本地训练室：收益驱动自对弈

控制台使用 MC-Q v2 收益驱动训练。现有默认模型、正式 Rust 引擎、PyTorch 学习器和嵌入式 V8 教师组成一个常驻服务；训练运行不依赖 Node。可直接从 WebUI 新建、学习、暂停、继续、评测和保存。**训练功能验证与自然棋力结论分开**；参数更新、loss 下降或自对弈胜率不作为棋力提升证据。

## 安装与启动

维护者构建正式引擎与随包教师：`npm run native:build`、`npm run train:teacher:build`。安装包须带同版本教师静态资源；`npm run train:teacher:check` 检查是否过期。源码修改时才需要构建工具，训练进程不启动 Node。Python 3.12、PyTorch 和设备安装见 [训练包说明](README.md)。已有本仓库环境直接启动：

```powershell
& .\training\.venv\Scripts\python.exe -m haojie_training.console
```

默认引擎 `artifacts/native-target/release/haojie-engine.exe`，受管根 `~/.haojie-training`，浏览器打开 `http://127.0.0.1:8765`。其他位置可在这一次启动指定 `--engine <正式引擎>`；`--root` 迁移整个受管根，不能为每个实验另领20GB。服务仅监听回环地址，写请求校验来源和会话令牌，同一根有进程锁。

- 首次使用：**新建训练**，保留“两种规则各半 / 自动设备 / 默认模型随机初始化”，建立实验后 **开始 / 继续**。GUI、Colab 和 cloud 使用同一套硬件自动配置，环境数、每轮局数、推理批量和样本池无需逐项填写。
- 同服务暂停后：**开始 / 继续** 使用内存最新参数、优化器和 RAM 样本。刷新、关闭页面、多标签页不改变服务。
- 重启后：**开始 / 继续** 自动找当前实验最新有效恢复点，损坏时尝试前一个；显示实际恢复更新数、保存时间及可能丢失的进度。
- 评测页：**立即评测 / 取消评测 / 确认冻结候选**。确认绑定原权重及原配置，不拿后续学习器凑局数。
- 保存：顶部 **保存恢复点**；资源页 **导出模型到受管目录**，仅保留最新导出并计入配额。
- 新实验：可仅继承当前内存或最新兼容恢复点权重，新建优化器和曲线；普通继续保持原优化器。资源页可打开已有实验，或明确删除所选非当前实验以释放配额。旧根和未纳管文件不走删除入口。
- 出错：页面保留原因；可减少环境数/批量、回收可替换权重，或 **从恢复点重新加载**。旧方法/协议用新实验继承兼容权重，不要求改 JSON 或删目录。

新建切换前保存原实验未保存更新；初始恢复点与活动清单均写成功才切换，失败保留原状态。引擎、设备、恢复位置、教师就绪及空间各自显示。教师缺失不换成随机教师；安装 `mini-racer==0.14.1` 和随包资源，训练与教师就绪分开。

导出文件采用 `haojie-stream-weights-v1`，包含模型参数、网络配置、版本及规则元数据；恢复点另含完整优化器和学习状态。已有实验恢复点的受管根禁止通过启动参数导入覆盖；在页面选择新实验继承权重。

## 自动资源配置与执行选项

首次启动和每次新建实验按所选设备、有效 CPU 配额和可用 RAM 生成相同初值。CPU 按有效核数、CUDA/XPU 按有效核数的两倍选择环境，向上取整且最多 128；先扣除样本池和 512 MiB 的模型等起步空间，再按每环境 256 MiB 限制进程数。每轮局数为环境数的两倍，推理批量为 `min(32, 环境数)`；训练 batch 保持 8。参数、采样与更新统一使用 BF16，CUDA 须有原生 BF16 支持。设置页显示实际结果，手动设置优先。

MC-Q 的 `environments` 独立控制常驻对局进程数。CUDA 使用独立采样/推理进程，通过四项有界队列交接真实终局轨迹；学习器更新和保存时采样继续，队列满时结案槽保留自身轨迹，交接后独立补局，已有对局继续推理。`games_per_round` 是无可消费样本窗口的完成任务上限，最多 4096。终局和预算截断均计入完成任务数，只有真实终局生成训练样本。继续时先消费 RAM 中已有的终局样本。`inference_batch_size`、`batch_size` 和 `batch_wait_ms` 分别控制推理上限、梯度更新批量及组批等待。当前模型和历史模型共享数字统计。线程数默认为自动，CPU 至多四线程、CUDA/XPU 一线程；CUDA 按有效配额分配多个 Python 输入进程，详见 [COLAB.md](COLAB.md)。GUI 新实验切换设备时重新选择，`--torch-threads` 的正整数覆盖持续有效。

这些初值在创建实验时确定；继续已有实验保留保存的训练设置、模型和优化器。阶段监控、服务器启动和备份见 [COLAB.md](COLAB.md)。

## 方法与样本语义

方法 `decomposed-mc-q-v2`，内存协议 `mc-context-v2`，恢复协议 `haojie-stream-recovery-v2`。模型为 `entity-transformer-v3`，默认11,695,874参数；亡者与 MC 日志采用两层完整交互、深层保留逐项历史读取的结构，详情见 [模型说明](README.md#模型与维护职责)。网络维度及正式游戏记录协议不变。新建实验直接使用 v3；权重继承和恢复要求同网络版本及兼容规则/编码，旧 v2 权重不自动迁移。旧记录仍按原方法与来源读取。

预测对象是**公开观察所属行动者**的真实终局收益。输入为公开局面、当前分解前缀、剩余候选掩码和本次公开搜索日志；动作 Q 回归选择该候选后，沿实际随机分解、回溯及双方后续自对弈轨迹得到的 MC 收益。状态价值同样按该输入/行动者监督。当前方可在跨轮续局时使用更新后的权重，同一次命令分解的模型推理使用同一权重；历史对手整局固定。双方为当前方时各学各自收益，历史方样本不进入当前池。每条样本保存实际行为版本和采样代数，网络不读私有信息、正式 seed/rng 或 Session。网络未显式条件化对手权重，估计近期匹配分布的混合收益，故限制样本复用与入池后的保留时间。

每个真实选择立即记录**推理时的同一张量**，包括后来被回溯的尝试、强制选择和合法 Pass。Pass 是可选根最后一个候选，特征63为1；没有任何可选动作的必然跳过不制造样本。记录不执行命令、不增加落子数、不消耗正式 RNG。命令仍由权威引擎提交，非法试探没有人为负奖励。

v2 不只保留最终接受路径：失败后重新对剩余候选评分/抽样。日志包含此前选择、空分支和公开拒绝，按顺序编码成类别250的附加实体；掩码标识排除项。网络不会用缺少已知拒绝信息的同一输入拟合首次尝试和回溯后的两种含义。所有尝试仅在真实终局后按所属方回归最终收益；暂停、取消、截断不补标签。详见 [ENCODING.md](ENCODING.md) 和 [TS/Rust 对应](../docs/ai/RUNTIME.md)。

候选头预测 `tanh(score)`，以实际终局收益做均方误差回归；后续采样用 `Q / temperature` 的 Gumbel 选择。状态价值头也回归终局收益。没有策略梯度，不把 softmax 概率乘积当作回溯行为概率，不引入 PPO、MCTS、奖励塑形或完整命令穷举。搜索上限4096节点、深度256、64次权威拒绝，耗尽是未完成，不是平局。

这是非平稳、自采样、有限样本的 MC 控制实现，不承诺收敛或自然棋力提升。多个相关分解选择共享单局收益，蓄水池及大样本拒收会改变学习分布；页面报告覆盖。可控任务验证自采样学习方向，自然棋力只看固定条件的真实对战。

## 默认循环与对手

| 项目                      | 默认值 / 行为                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------ |
| 环境 / 无样本窗口完成上限 | 按硬件自动选择 / 环境数 × 2；有终局样本即学习，长局跨轮继续                          |
| 规则 / 历史 / 当前方先手  | 各50%；独立配置，每8任务覆盖全部组合                                                 |
| 随机流                    | 稳定训练编号的独立 game / policy / 比例散列；评测另计数和种子族                      |
| 更新预算                  | 自动：剩余合法复用次数 ÷ batch 向上取整，上限 `max(256, 环境数 × 64)` 步；可手动覆盖 |
| batch / 复用 / 年龄       | 8 / 每条最多2次 / 入池后最多跨4轮更新                                                |
| 采样 / 更新               | BF16 参数、计算及补偿 AdamW；整数更新步数                                            |
| 行为温度                  | 0.25                                                                                 |
| 单局命令 / ply            | 20,000 / 1,000；超出不补终局                                                         |
| 历史池                    | 默认4份，可4—8；每200次更新稀疏保存、去重、保留首尾及时间跨度                        |
| 恢复点                    | 每600秒且有新更新才保存，保留最近2份                                                 |
| 周期趋势                  | 新增 `max(64, 环境数 × 4)` 个有效训练终局且有新更新触发                              |

每局固定双方角色，按实际行动者路由。持续局使用稳定路由身份，权重版本另外记录；当前方在新根领取最新已发布快照，历史对手保持开局时的冻结权重。仍被在途对局引用的历史模型保留，最多同时驻留 `history_size` 个；到达上限时，新开局选择已有历史模型，已有长局结束后释放空闲版本。历史池空或只有相同权重时计入自对弈/回退。槽位、并发、完成顺序、评测不改变编号定义的训练种子分布；并发和窗口边界会改变各局使用的行为版本。

默认 MC-Q 使用持续对局池。CUDA 采样侧独立拥有冻结推理模型和环境，学习侧拥有可变模型与优化器；终局队列和权重邮箱均有界。模型更新不要求采样排空，原进程、局面、随机状态和轨迹持续保留。同根继续使用原快照，新根使用最新已发布快照；当前策略最多四份快照，旧根释放后回收无引用版本，达到上限时合并尚未发布的更新。监控记录已发布权重、快照数及最老根的更新滞后。评测绑定冻结权重，学习器按时间片参与；采样侧继续服务在途局，并按终局队列容量接纳新局。CPU 参考执行及旧 `sampled-action-imitation` 方法沿用本地执行层；固定任务集诊断可显式选择流水线或本地对照。

学习器和优化器跨轮保留；行为发布只更新内存，不每轮存模型。页面显示保留待续局数、上一轮跨轮保留局数和平均活跃环境数。暂停及退出取消在途局，在短计算边界停算，将学习状态移至CPU，不等待长局、不强制写 checkpoint。恢复点保存学习状态，RAM 样本与在途对局不落盘；跨轮继续适用于同一次服务运行。兼容旧检查点的参数与 Adam 矩在恢复边界统一转换为 BF16，并补齐舍入余量；原恢复文件保持只读。

设置页的“应用并发量”可运行中单独提交，保留在途局及其计算进度。扩容异步增加环境，缩容停止给多余环境补局并等待其正常结束；连续调整以最新目标为准。页面显示实际数量、目标与过渡状态，其他设置仍先暂停后应用。

## 内存、消费与20GB配额

普通样本不先落盘。每局最多128条，其中最多8个名额保护稀少的Pass，剩余用于普通选择；Pass与普通组内分别均匀蓄水，没有Pass时普通组可用全部名额。该分层会提高稀少Pass的学习权重，不声称仍是所有决策的均匀抽样。每条保守512KiB，总共约64MiB/局；超大样本只计覆盖，不裁剪实体。真实终局后进入 RAM 池，默认取创建实验时可用 RAM 的四分之一，最小64MiB、最大32GiB，并与进程预算一起计算。容量不足淘汰最旧项，入池后超过4轮更新淘汰，每条消费2次释放。无可消费样本预算为0，不空转。

元数据共享局和初始模型身份，每条附行动者、阶段、Pass、决策号、时间、实际行为版本 `behavior_version`、采样代数 `behavior_generation`、入池代数和使用次数。长局的采样代数与终局入池代数分别保留，入池年龄不会冒充策略年龄。页面分别显示生成、合格、保留、消费、用尽、年龄/容量淘汰、超大拒收，以及规则/阶段/Pass消费和实际对战组合。没有新loss时显示等待终局，不填零。

512KiB保留阈值与帧传输分开。先按维度核对精确长度，合法帧按可用RAM和并发限制为4—32MiB/槽，评测32MiB。合法超限是资源拒收，只取消该局并释放；维度损坏另报错。不因旧2MiB固定门槛停整个服务，不裁剪或伪造标签。未全面共享跨前缀实体张量，按保守额度计账。模型/优化器/批次/历史网络/V8/进程另占内存；RAM低于256MiB停算，页面显示进程树与显存。

所有实验、恢复点、历史、初始化基准、确认最佳、最新导出、指标和原子临时副本共享根目录的 **20,000,000,000字节**。各实验保留2个恢复点、4—8历史、1基准、1最佳、1导出；不重新领取额度。写入先预留完整新文件，旧副本仍计入，写后校验/原子替换成功才轮换。空间不足拒写并保护有效恢复点；可从页面明确删除非当前实验。

指标最多每60秒或评测结束合并写，每实验最多2MB；日志100条，曲线最多256点并降采样，仅最近两批保留逐局小摘要。没有样本数据库、WAL、逐命令fsync或每次评测的全模型副本。轮询只读内存计账，目录每60秒核对。恢复点含优化器、精度、随机源、方法、累计更新/任务数和小摘要，不含RAM池；未保存进度允许丢失。

旧产物启动时只读单列；`--legacy` 增加盘点，`--adopt` 显式纳管且保护原件。未跟踪/忽略不代表可删。20GB不意味着整台机器旧文件总共小于20GB。正式构建和已安装运行库不属于训练产物。

## 冻结趋势、确认与最佳

初始化先保存独立基准。趋势批次：三档教师分别经典/神龛换座4局，共12局；另对基准4局，总计16局。按简单→中等→困难→基准轮转，每局独立默认180秒，前面的简单档不能耗尽整轮预算。每次最多四局的一组时间片，然后可训练一轮，再接原冻结任务；避免长采样轮把80局确认稀释成无限等待。训练暂停后单独发起评测则连续执行有界时间片。最多一个待评测/确认任务，触发合并，暂停取消。

教师使用原 `TrainingTeacher`、难度和 planning/search/cache 依赖，由 mini-racer 0.14.1 嵌入V8执行。保留原节点预算，**没有固定2秒或10秒的单次调用超时**，只受整局评测预算和主动取消约束。V8调用可取消，不开失控进程；每局256MiB堆限额，资源失败单列。

双方均经过权威回合外窗口：模型介入/Pass，教师调用原 `decide`。生产教师非 decisionOwner 时返回 Pass，未自制更强或更弱教师。系列名 `production-owner-offturn-pass-v2` 明示限制，不声称完整利用真人窗口的能力。

三档取得真实结果后保留一个 RAM 趋势候选，可一键确认；候选/任务最多保留24小时。确认固定权重、原配置、教师指纹、种子族和温度；默认每档20局加基准20局，共80局。不同更新版本绝不累计凑20局。每档20有效局且完成率100%后，按同系列三档平均得分保存最佳，首个合格结果登记系列最佳。未确认仍是趋势候选；最佳不是统计显著晋级证明，不回滚学习器。

胜、负、规则平局、未完成、错误分开，平局半分计算得分率，无样本显示未评测。种子、预算、调度、温度、模型和对手身份明确，曲线仅连同系列。基准比较可观察早期相对变化，但超时仍是 unknown，不转成平局或胜负。

- Python：显式 `HAOJIE_NATIVE` 后执行 `python -m unittest discover -s training/tests -p 'test_*.py'`，缺引擎失败。
- 差分：`tests/runtime/mc-context.differential.ts`，原生CI显式运行，逐张量/选择核对 Pass、空分支、拒绝、回溯、强制节点；另保留引擎与离线浏览器测试。
- 可控任务：`training/tests/console/learn_exercise.py`，同生产分解、回溯、样本、Trainer，自采样、随机终局、解析期望和三个初始化；保留失败短试验。
- 廉价WebUI：`tests/browser/console/run.mjs`，小模型/晚盘夹具验证生命周期、恢复、配额、布局，结果不作自然棋力。
