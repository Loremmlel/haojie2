# 公开状态与分步动作编码 v1

版本：`haojie-entities-factorized-v1`。实现唯一来源是`src/ai/training/encoding`与`src/ai/training/action-tree.ts`；Node数据准备与将来的浏览器推理共用此代码，Python不复制规则。编码含义、顺序或词表改变时升级版本并重新准备数据。数据同时保存完整schema、当前规则ID、TypeScript源码SHA256和原始记录SHA256。

## 输入边界

编码器只接收按操作者脱敏的Observation，不接收Session、seed、rng、战报或历史。双方公开手牌可见；神龛未揭示的另一方选择和玉碎奇偶不可见。局内serial不作为特征。局面不被修改，编码和公开预检不消耗正式随机数。

原始ID只用于建立局内引用，不能读取ID中的序列号。单纯重命名ID不改变输入。数组顺序保留叠放、来源消耗、手牌与反应队列等语义。未知字段与未支持的种类报错，禁止悄悄忽略新规则；不裁掉实体、死亡记录、长路径或时钟快照。

## 实体与全局特征

每行64个float32、一个类别索引。基地、棋子、地标、手牌、死亡记录各有主记录；效果、装备、继承能力独立使用次数/蓄力、已攻击目标、名刀来源、受伤记录、延迟区域、连接、冰印、反应源快照、时钟快照、光环、暗选候选和召唤候选另有附属记录。快照与场上同ID棋子的附属状态分开关联。

| 通道  | 含义                                                                                                            |
| ----- | --------------------------------------------------------------------------------------------------------------- |
| 0     | 记录角色，顺序见schema.roles                                                                                    |
| 1     | 相对所属方：己方1、对方-1、无所属0                                                                              |
| 2–6   | 身份、父记录、来源、目标、克隆组的局内引用，除以256；0为缺失                                                    |
| 7     | 语义数组中的顺序，除以128                                                                                       |
| 8–59  | 按记录类型排列的数值/布尔字段，具体映射见state.ts；单位前38项见schema.unit_fields，随后是共享getStats的派生属性 |
| 60–63 | 数值字段是否存在，每13项一组位图，除以8191；区分缺失与零/false                                                  |

数值统一为`sign(x) * log1p(abs(x)) / 8`，布尔为0/1，不截断数值；分类值由版本化词表定义。类别1起按catalog ID排列，普通记录角色从128起，0保留给填充。这里的引用是关系提示，模型仍需从数据学习关系，不等于执行符号规则。

32维全局特征含观察席位、当前行动方、5种阶段、规则模式、实际回合、召唤余量、双方个人时钟/基地/人头/额外召唤、终局、反应数、手牌数、神龛设置与公开提交标志、召唤候选及是否存在动作前缀。

## 动作分解与解码边界

根节点复用共享ActionSpec；随后逐项选目标、坐标、材料、死亡对象、行列、方向或召唤种类。三材料合成保留完整材料池；路径从起点逐格延伸，再显式确认，复用引擎路径校验。动作前缀及已经选过的材料/路径点作为附加实体，避免下一次选择忘记此前参数。

每个候选有64维特征及来源/目标实体指针；-1指全局token。特征含命令/模式、坐标、方向、能力/配方/选择、当前分解阶段、完整/随机边界标记、材料与路径长度、第二目标引用等。参数候选与完整命令不同：

- `parameter`：公开选择域中的中间参数，可能没有合法补全；网络解码器须回溯空分支。
- `available`：完整命令通过公开预检。
- `uncertain`：完整命令在预检中到达规则随机边界；实际结果交给权威引擎或独立模拟源。

candidate_mask只表示当前节点存在的候选与填充，不承诺中间参数一定可补全。预算耗尽须明确暂停，不能静默结束回合。正式提交仍通过引擎。`src/ai/training/decoder.ts`已接入纯网络贪心解码及空分支回溯，单候选免推理、同分按稳定下标选择；它不是MCTS或全路径联合概率搜索。

教师命令只用来定位树中的分支，不添加或重排候选。旧craft统一为对应合成命令，省略字段仅补引擎已有默认值；回放测试验证结算结果不变。一个实际命令可产生多个分步策略样本。当前使用one-hot教师标签，不伪装成MCTS访问分布；长路径会产生更多策略样本，后续扩量需评估每命令计权。

## 数据、标签与限制

`prepare`通过Node子进程流式取得编码，分开保存轨迹身份`game_id`与划分种子族`group`（规则版本/模式/种子）。同种子换边、不同教师配置可以是不同轨迹，但不能跨训练/验证集合；重复轨迹拒收，旧记录仍回退到原有规则/种子身份。种子、教师配置、席位只在元数据中用于复现和分组，不进入网络特征。

每个已执行命令有策略标签；价值只在根节点、且有真实终局时启用，按该决策操作者计算。反应所属方可以不同于active。截断/中断局不充当平局，文件缺失outcome或显式取消/故障均保留中断，后者另保存原因。至少有两个不同种子族才能划分训练/验证。prepare可用`--teacher-difficulty hard`筛选来源，逐局记录selected/excluded_decisions；整条命令的所有分步一起保留或排除，不改变种子族。默认混合文件不能全部视为强教师示范。

学生公开局面重标使用`haojie-teacher-corrections-v1`引用原轨迹及位置，重放原轨迹后再定位教师命令在动作树中的分支。它只增加独立策略标签，不修改学生实际轨迹；所有标签价值遮罩为False，不继承学生终局。元数据标明`source: correction`与`origin.policyOnly`，沿用原种子族；这类标注组不是新增独立对局。编码特征及schema没有改变。

旧填充张量继续读取；扩量可选择带逐分片SHA256的`haojie-training-shards-v1`索引、只读mmap和训练长度分桶，保持特征及标签语义不变。分片在自己的样本上限内填充，批次取样时再裁剪/填充，不截断较大局面。预处理目前仍保留变长样本，实际实体量包含附属状态、死亡记录和快照，不能用场上棋子数代替网络序列长度。

v1是可验证的起点。网络CLI支持完整命令和对局，但不能因此推断已覆盖所有罕见能力、部署延迟达标或棋力达标。增量验收和实验结果见[训练进度](../docs/ai/TRAINING-PROGRESS.md)。
