## 交付实现

生产只有 Rust 原生线程运行时、256×3 dense 根编码器、128 维根内 GRU、分层动作解码、BF16 AdamW 与连续 V-trace。一进程拥有 CUDA，采用有界双 stream；根内冻结权重、双槽发布、同席位短块、原始根重新编码及历史重建贯通训练和正式推理。

已删除 119 个旧实现、测试和文档文件，共 26,449 行；移除旧 Python 模型/训练器/采样池、MC-Q、Web 控制台、云服务、C++ dispatcher、Rust 子进程训练宿主、TS 教师采样链、旧 Colab 和 ONNX 依赖。新生产路径不保留 MC 辅助训练、stream 切换和旧权重兼容入口。旧 v3 只通过外部冻结目录参与测量，未安装回生产包。

控制入口支持启动、状态、在线并发及内存预算调整、手动/定时保存、停止和恢复。默认每 300 秒后台原子保存；停止先冻结窗口指标，再保存未完成局。Colab Notebook 使用独立 Drive 运行目录，同一入口恢复。冻结策略通过 `online.policy` 导出、加载和正式对局运行。

## 正确性与实际控制

Windows 当前构建通过 30 项 Rust 测试、严格 clippy、19 项 Python 测试（含 3 项实际 CUDA 测试）。覆盖：

- 小动作树完整掩码、失败、重试、回溯及实际行为概率；失败不消耗正式规则 RNG。
- 同策略 BF16 重要性比、真实终局与短块 bootstrap、非交替行动/反应/同席位后继。
- 根去重反传、微批一致归一化、真实历史因果重建；8,192 事件长根使用完整默认 128 维 GRU，反传有限，额外 CUDA 分配峰值低于 256 MiB。
- 非有限梯度在优化器提交前拒绝；BF16 参数与优化器保存边界逐位一致。
- CUDA 双 worker 恢复后正式状态、正式与采样 RNG、消费确认一致；继续更新因缓存重建产生的 BF16 舍入使用测试中的明确容差。
- 实际内存预算检查、冻结模型发布及旧根继续推进；错误预算不会继续抽样。按作者要求移除人为注入内存压力的专项测试。
- 真实控制子进程自动保存、2→4→1→4→1 在线调整、停止和从磁盘恢复，未完成局保留且累计训练计数不倒退。

Linux Ubuntu 24.04 隔离目录中重新构建同一 Rust 源码，将新 wheel 安装到独立目录后验证控制、自动保存和恢复。最终 19 项测试中 16 项成功，3 项 CUDA 测试因 CPU 环境跳过。未依赖 `fork`。
