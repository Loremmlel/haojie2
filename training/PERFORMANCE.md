# 完整训练周期测量

## 验收口径

优化前后使用固定源码、引擎、模型、种子、任务起点、命令/回合预算、训练批量和更新次数。主指标是 **采样 + 梯度更新 + 恢复点保存** 的总墙钟及有效保留样本/秒。安装、初始化和用于核对样本的哈希耗时单独报告。截断、丢弃、真实终局分开统计。

当前报告格式为 `haojie-cycle-benchmark-v2`。每轮所有计划任务必须各有一份结案记录和末态哈希，终局与截断之和须等于计划数，且没有丢弃任务；同时须有真实终局并完成指定更新量。自然运行达到命令、回合或解码预算后的截断保持未知结果，按实际数量报告。超时、中断或异常保留错误、阶段、累计计数、已结案任务以及最近一次活动采样快照，整次测量标记为未完成。

脚本直接调用生产控制器的采样、学习、存储实现；只关闭后台自动循环，使测量线程独占控制器。没有模拟推理、伪造终局或修改真实规则。配对比较必须使用 `--ordered-updates`：将同一份已保留样本按任务及决策排序后再抽取训练批次，消除进程完成次序造成的训练负载差异；生产抽样顺序不变。仅有样本集合相同而未固定消费顺序的报告不进入吞吐对照。

## 运行

从仓库根目录执行；每份结果保存设备、环境、选项、源文件/引擎/起点哈希、任务末态、样本摘要、阶段耗时、更新和消费次数。

```bash
python scripts/training/benchmarks/cycle.py \
  --source /path/to/frozen-source \
  --engine /path/to/haojie-engine \
  --starts tests/fixtures/native/late-starts.json.gz --start-indices 0 2 \
  --environments 2 --games 2 --updates 16 --ordered-updates \
  --device cpu --output artifacts/cycle-before.json
```

再对另一份固定源码执行相同命令，输出 `artifacts/cycle-after.json`，然后：

```bash
python scripts/training/benchmarks/compare.py \
  --before artifacts/cycle-before.json \
  --after artifacts/cycle-after.json \
  --output artifacts/cycle-comparison.json
```

`--before` 和 `--after` 均可接收多份配对结果。两侧均使用当前 `cycle.py`，通过 `--source` 加载各自冻结的生产源码。比较程序逐项核对模型配置及初始权重、Python/Torch、CPU/GPU 型号和有效核配额、实际设备、精度、优化器选项、线程数、采样配置及每轮任务/样本/消费量。动态可用内存和利用率只作诊断。旧 v1 报告保留原始证据，新比较器要求两侧重新生成 v2 报告。

默认使用正式大小的模型和原始每局预算。去掉 `--starts` 从新局开始，`--rounds` 可执行多个连续学习周期，`--state-output` 额外保存优化器和权重以便容差检查。GPU 使用 `--device cuda`；每个阶段收尾都会同步设备再读墙钟。`--sampling-precision bf16` 显式选择 BF16 采样，前后须使用相同精度。`--tiny` 只用于小模型的功能或并发对照，报告明确记录参数量。

大并发对照使用两侧相同的 `--pool-mib 1024`，并检查 `sample_pool_before_updates.capacity_evicted` 为零；否则有容量上限的生产样本池可能因进程完成顺序不同而保留不同样本。调大对照池不改变每局保留预算，生产池仍遵守用户配置的内存上限。

CPU 线程调优需要显式给比较器添加 `--allow-thread-change`。它只允许 CPU 的线程数差异，报告列出前后线程数并令 `same_execution=false`；其他设备、精度、模型、任务和样本核对仍全部执行。纯代码收益保持两侧 `--threads` 相同，执行配置调优单独报告。

每组正式计时独占设备，安装、编译和其他训练结束后再运行；交替执行前后版本并重复测量。4/8/16/32 环境各自形成一组固定配置的前后对照。线程数或并发数调优先作为不同执行配置的探索测量，确定配置后再冻结正式对照。

## 捕获固定推理输入

在额外的一次运行中添加 `--requests-output artifacts/requests.pt`，可收集实际推理的公开输入供固定请求微基准复用。输出格式为 `haojie-inference-requests-v1`，`requests` 只含 `INPUT_KEYS` 张量，另存源码与引擎哈希。按实体数、候选数的二次幂区间分桶，每桶最多四条，总计最多 128 条、256 MiB；这是形状覆盖样本，不是自然请求频率的抽样估计。

捕获过程会复制输入，因此该运行报告的 `measurement_eligible` 为 `false`，比较器拒绝将它用于完整周期收益。捕获文件在主计时结束后写出并计算 SHA256。普通计时省略此选项。

## 2026-10-20 实现与固定精度结果

本轮冻结基线为 `da0722490002f42bd2279fcbecc82eab36bcd40e`。主机是 Ryzen 7 5800H（16 逻辑核）、RTX 3060 Laptop 6 GiB；Windows 与 WSL Ubuntu 24.04 使用各自 Python 3.12 / Torch 2.14.0+cu130 环境。每组只在同一操作系统和硬件上配对，原始源码、引擎和数据身份随 JSON 保存。BF16 采样、稀疏最后一层、已选候选训练头和融合 AdamW 均已存在于基线，本轮收益不包含切换这些选项。

实际改动：

- 引擎动作树复用无参数根动作的预检和只读实体属性。移动、部署的最后一个落点参数一次准备公共条件，然后按原顺序查询完整合法域；冲撞继续完整预检。TS 验证方案后迁移 Rust，没有缩减候选、预算或随机边界。
- TS 教师搜索在内部运行状态上连续分支，省去每次概率展开的快照导出/导入；解码、教师记录编码及审核复用同一观察的固定编码基表。
- 常驻模型推理将实体长度上限从组内最短的 2 倍收紧到 1.25 倍，减少注意力与线性层的填充计算；保留同一排序、连续前缀、批量上限和每槽一个在途请求。
- 模型身份、权重发布和恢复点统一在独占边界传回 CPU，排队复制后同步设备；检查点格式、Adam 状态和恢复数学保持。
- CPU 入口按实际配额自动选择至多四个算子线程，CUDA/XPU 保持一个；显式线程设置继续生效。记录审核改为共享流式读取，支持 gzip 并保留损坏记录的硬错误。

## PR #16 优化及边界

- 原网络最后一层仅计算最终会读取的全局、来源和目标查询；每个实体的 K/V 保留，前面所有层仍完整计算。稠密查询及研究网络回退到原路径。
- MC-Q 只监督已选候选，更新时仅为该候选构造评分头；教师软策略损失仍计算完整候选分布。网络参数名称、维度、优化器格式保持兼容。
- 已抽定的同一步样本在预计填充开销可降低至少四分之一时按长度分组，最多四组；按整步有效标签数归一化，逐组反向、只做一次梯度裁剪和优化器更新。分组不消耗随机数，不增加或减少消费次数。
- MC 推理池排空消息时为 example 和 infer 分别留下容量，控制帧不再过早消耗推理收集预算；实际额外等待时间不变。

输出、梯度以及恢复的回归测试在 `training/tests/compute/`。浮点加法和矩阵形状变化可能带来舍入差异，测试采用显式容差；同一优化路径保存恢复后的下一步要求逐张量一致。GPU 回归按硬件条件运行并报告跳过。

## PR #16 对照结果

基线为合并 PR #15 后的 `732329f0f699c5e7462e8aef05728971a01d6c20`。本地 CPU 测量使用 Python 3.13 / Torch 2.10；正式依赖 Python 3.12 / Torch 2.14 的配对测量由 `Training cycle performance` CI 运行，原始 JSON 随该任务归档。

默认模型、两份真实晚盘起点（经典与神龛）、两进程、16 次 batch=8 更新及保存：本地两次重复对照的总耗时为 **150.76 → 130.97 秒**、**153.62 → 136.13 秒**。两次中位数为 **152.19 → 133.55 秒**，时间减少 **12.25%**，同负载吞吐提高 **13.96%**。每次均完成两个真实终局、零截断，保留 256 条样本并消费 128 次；样本集合和对局末态一致。先导测量另为 148.51 → 130.50 秒。

另一个独立负载使用 tiny 模型、8 个并发进程、8 个真实晚盘终局及 16 次更新：完整周期 **46.81 → 30.89 秒**，时间减少 **34.00%**，吞吐提高 **51.53%**。前后均保留 942 条样本，消费 128 次，零截断、相同末态及样本摘要；这是一次配对而非重复中位数。

这些是晚盘继续采样至真实终局的完整学习周期，而非从初始新局开始的长期训练。CPU 与 GPU、低并发与高并发各自报告，微基准和功能测试用例数不代替此表。CI 计时不设硬性速度阈值，以免共享宿主波动误杀；正确性和匹配负载仍是硬检查。
