# 原生 Transformer 验收

2026-10-24。当前主干恢复为与 `main` 相同的宽 384、6 层、6 头、FFN 1536 的 Pre-LN Transformer。模型、激活、梯度、优化器浮点张量保持 BF16。

## 模型与边界

当前模型有 **15,048,578 参数**；`main` 的 `d5760fc` 为 **11,695,874 参数**。增加的参数主要来自保留精确整数身份的输入位投影及有序路径上下文融合层。六层均执行公开实体和全局 token 的自注意力；无实体裁剪。根按长度分桶，只在桶内补齐、遮罩 padding，不在根之间进行注意力交互。

策略头恢复为两层 GELU 隐藏层，使节点上下文能影响候选相对评分；价值头也包含非线性隐藏层。保留根缓存、根/候选投影去重、一次前向学习、补偿 BF16 AdamW、逐局 Rust actor、全局就绪合批、独立回送、弹性停放及保存恢复。

此前主动缩成 1,139,458 参数 MLP 的主干已撤回。[MLP 历史记录](history/MLP-VALIDATION.md)及其原始结果保留。历史 6.12 倍比较的是 `8449f5d` 与该 MLP，既不适用于当前 Transformer，也不是相对 main 的实测。最新 [main 对照](MAIN-COMPARISON.md)采用 16 并发、各一次 60 秒，分别记录正式命令、实际训练消费、更新次数、资源和完整墙钟；两种训练方法的消费单位单列。

## 必要检查

- Windows CPU/CUDA 原生检查通过：六层 Transformer 的 BF16 前后向、候选相对评分对上下文和注意力的非零梯度、不同根及 padding 隔离、掩码与规范行为概率、根缓存命中和发布失效、非有限/溢出更新拒绝、模型及优化器恢复后继续更新逐位相同。
- 默认 384 维模型实际消费 256 微步、保存，再从检查点恢复配置并消费 128 微步通过。
- 同一默认 Transformer 的真实控制子进程通过 `16→1→0→16`、手动保存、停止、磁盘恢复与继续消费 128 微步。在途局没有重开，累计数据满足守恒，保存状态的累计速率为 `null`。
- Linux GCC 13.3 / LibTorch 2.14.0+cpu 独立构建通过。清空环境及 PATH 后，原生数值检查、默认 384 维模型消费 256 微步、保存并恢复后继续消费 128 微步通过；恢复累计消费为 384，累计速率为 `null`。
- 规则、编码、actor 协议与 Rust 源码未改变，沿用上一提交已通过的 TS/Rust 差分、规则 RNG/公开边界及停放连续性检查。

## 当前固定消费量短测

Windows、Ryzen 7 5800H（8 核 / 16 线程）、RTX 3060 Laptop 6 GiB、Torch C++ 库 2.14.0+cu130。每次新进程、种子 1、8 个规则 worker、批量 512、块长 16，精确消费 **4096 个训练微步、8 次更新**。64 / 256 并发交错各跑两次。

| 并发 | 窗口秒（两次）  | 完整进程秒（两次） | 窗口消费吞吐 |
| ---: | --------------- | ------------------ | -----------: |
|   64 | 4.6186 / 4.1588 | 6.1168 / 5.6250    |  933 微步/秒 |
|  256 | 3.0458 / 3.0058 | 4.7338 / 4.6650    | 1354 微步/秒 |

窗口和完整进程耗时中位数分别为 **4.3887 / 5.8709 秒**（64 并发）、**3.0258 / 4.6994 秒**（256 并发）。窗口在退出排空前冻结；完整进程计时包含进程启动、初始化、保存和退出。窗口内消费只有 4096，退出新增工作及未完成轨迹另记。

64 并发实际产生 4511 / 4556 微步，窗口末 partial 415 / 428、ready 0 / 32；256 并发产生 6137 / 6148，partial 1929 / 1892、ready 112 / 160。四次短跑均无自然终局，在途局均保存在检查点。周期 RSS 观察峰值约 1484–1513 MiB / 1581–1585 MiB。

当前 4 倍并发带来 **1.45 倍消费吞吐**，双对数斜率约 **0.268**。该区间未达到近线性扩展；GPU 饱和拐点尚未定位。推理和学习的区间计时包含主机组表、传输、同步和提交等待，继续按实际消费与完整管线墙钟判断收益。

当前原始测量及源码哈希位于 [results/transformer](results/transformer/)。同名历史结果未覆盖。复现入口：

```powershell
pwsh -File training/native/validate.ps1 -Output artifacts/native/transformer-control -Device cuda
pwsh -File training/native/benchmark.ps1 -Output artifacts/native/transformer-fixed -Samples 4096 -Repeats 2
```

剩余主要开销是多轮分解动作请求、设备概率回到 CPU 的同步、组表与注意力计算；CPU actor 可与加速器工作重叠，推理和学习仍在单加速器提交锁下协调。
