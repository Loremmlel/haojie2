# 原生训练架构约束

## 规则与模型

- 所有规则变化经正式命令执行；非法命令不部分支付资源或消耗正式 RNG。预览与模型不能读取正式 RNG。
- 模型只接收 `observe` 白名单，禁止 seed/rng、整份 Session 和暗选私有信息。TS/Rust 的规则与 AI 算法对应关系保持一致。
- 保留 384 宽、6 层、6 头、FFN 1536 的 Pre-LN Transformer。完整公开实体与全局 token 参与注意力；模型结构调整先提交数据和建议。
- 类型化行保留完整 int64 身份、存在/类型掩码及 BF16 连续值。公开状态、有序参数路径和逐层排除事实作为决策输入；不恢复 GRU 或完整历史重放。
- query/key GELU 评分保留完整合法支持集，排除动作质量为零。Rust 按真实 BF16 质量精确归一化、抽样并记录实际行为概率，learner 使用相同规范概率。
- TS/Rust 动作树共用最后一个固定参数的精确空前缀判断，用候选掩码跳过没有任何合法或 uncertain 叶子的分支；原始候选及下标保留。未补齐的多参数、重复路径及材料组合保守保留，不用启发式或教师评分裁剪合法动作。恢复时只刷新尚未采样的节点，已记录的行为输入和概率原样保留。

## 轨迹与更新

决策默认直接使用策略网络，模拟数为 0 时不创建搜索分支或访问标签；历史对手使用同一直接策略路径。显式正数预算启用完整命令级随机 MCTS，深度默认 64 个决策边。参数树只生成完整命令；随后执行独立公开规则分支，继续本方、对手与反应。PUCT 的价值符号按真实决策方切换，不按树层数盲目取反。机会后继按独立场景采样并分别累计；未终局的深度／空分支截止只使用网络价值估计。神龛暗选保持公开策略采样，不补造未知对手选择。

同一命令固定模型，完整命令访问数按已选参数前缀条件化；每层混合 95% 访问分布、5% 原策略，使用真实 BF16 行为质量并记录概率。只有真实完整终局进入学习，损失在原 V-trace、价值和熵项上增加搜索访问分布的策略交叉熵；旧轨迹没有标签时此项为零。

同席位连续轨迹保留到真实终局；对手行动期间保留未决转换。折扣为 1，奖励仅来自真实终局：胜 +1、负 -1、平 0。截断、停放与未结束局不进入 ready、不补造胜负。`chunk=0` 标识完整终局训练。

采用完整对局的 [V-trace](https://proceedings.mlr.press/v80/espeholt18a.html)：固定本次更新的参数，分计算小批取得价值与规范行为概率，从真实终局反向递推整条轨迹，跨小批保留递推状态；再逐小批反向，以 BF16 补偿累加梯度，完整对局批只提交一次更新。`batch` 仅控制显存，零质量旧动作的修正与策略项严格为零。完整对局、反向分块的组织参考 [DeepNash 补充材料 Infrastructure for learning](https://arxiv.org/pdf/2206.15378)；不引入该文的额外判和规则或整套 R-NaD 算法。[DouZero](https://proceedings.mlr.press/v139/zha21a.html) 的终局 Monte Carlo 作为反馈链对照，不替换当前策略头为 Q 网络。

参数、激活、梯度、跨前后向保存的归一化统计和注意力 LSE、五组补偿 AdamW 状态保持 BF16。算子寄存器与临时工作区可用 FP32 累加。离散索引为整数；规范行为概率的标量计算为 double。

每批完整前向、反向、验证后执行一次原子更新。CUDA 先验证全部参数与状态提案，再复算提交；非有限值拒绝整批，不能部分提交。分段策略归一化在反向归约中消去共同项；价值 tanh 保存 BF16 输入计算导数，避免 BF16 输出提前舍入为 ±1 后错误清零梯度。旧短块学习器及其专属诊断已移除。

## 调度与持久化

当前自对弈／历史对手默认按新局编号分层安排 80/20，历史池默认 8 份、每 64 次更新保留一份。历史对手必须早于当前模型，开局选定、整局固定；被活动或停放对局引用的退池模型继续存活。池、退池引用、对手绑定、搜索配置和策略标签都随检查点保存，不能在恢复时重新抽签。搜索预算和对手比例可显式覆盖，已有对局的历史对手保持不变。临时搜索树与命令缓存在保存边界两侧统一清空，恢复从相同公开前缀和已保存参数重建。

空根异常 `no legal action at root` 在 lane 保存并移出单局，宿主保存故障局面、删除其未结束轨迹、累计独立错误淘汰计数并补局。不补造终局、奖励或训练标签；其他未识别规则错误、设备和协议错误仍交宿主失败保存。历史池、搜索输入、访问标签和暂存分支均纳入管理内存所有权计费，沿用长局／内存回收边界。

独立 C++ / LibTorch 宿主负责初始化、模型、优化器、调度与保存。Rust actor 固定属于 CPU lane，其规则对象与 Rc 不跨线程。运行不启动 Python 或 Node。发布不绑定长根租约；已经开始的 CPU 决策可以持旧快照完成。

正式策略服务使用两个有界编码槽，按推理上限捕获图，冻结模型之间只在空闲边界切换权重；CPU 解码在各 lane 并行，保留 BF16。每槽图池只在其流上顺序使用。图均在并行工作前捕获，根输出归各根所有，迟到结果绑定实际编码版本。Worker 调整在一致边界序列化、释放并重新分配规则状态，不跨线程共享 Rust Rc。完整终局学习与已有局采样可并行，只有一个优化更新在途，每次提交后发布。

终局按完成顺序异步消费，不设更新轮次或全局排空。默认最多合 4 局更新一次，目标并发不足时取较小值；首个 ready 等待最多 30 秒，并发为 0 或内存背压时立即消费。更新局数与计算小批独立，每局 V-trace 反向递推独立，整批梯度按转换数加权后只提交一次优化器更新。保存保留未消费终局，恢复重新开始等待。学习期间照常补局；ready 对局数达到目标并发时只限制新局，已有局继续行动。

默认单局己方已完成转换上限为 262144，可用 `--max-game-steps` 调整；达到上限仍未终局或真实终局长度超限时整局淘汰。未结束轨迹的最早行为版本超过 K=64 时提前整局淘汰。管理内存达到预算 75% 后先收回 lane 和设备槽的所有权，回收最长的未结束局直至回到半预算；完整终局及在学习数据保留，必要时暂停采样等待学习释放。活动与停放局遵循相同边界，淘汰后补开新局；不因截断补奖励、计胜负或学习剩余部分。淘汰原因及转换数独立计数并随检查点保存。

实际消费保持 K=64：取批时逐条核对行为版本，任一转换过期则该完整对局不进入学习，计入 `stale_games/stale_steps`，继续处理后面的新鲜对局。未结束局提前淘汰计入独立的 `discarded_stale_games`，不冒充真实终局。长局和停放局不阻塞其他局，超期轨迹不伪造收益、不拆掉过期前缀后学习剩余部分。过期及淘汰计数随检查点保存；短局学习不等待未完成局恢复或结束。

检查点在一致边界冻结模型、优化器、配置、规则状态、正式及采样 RNG、路径、frontier、未决转换与未消费轨迹，后台原子写入。v3 共享表恢复原始关系；长度上限和淘汰计数新增为可选字段，不改旧状态与配置布局。正式恢复只接受 `chunk=0` 的完整轨迹，旧短轨迹档无法补回已丢弃的前半局，保留供测评并提示新训练。构建身份不作为加载条件，格式、模型尺寸与 BF16 类型仍检查。缩容先停放，仍符合上限与预算的轨迹保留；扩容先续旧局。

性能验证只在相同工作量、学习 batch 与语义下比较，actor 决策/秒、正式命令/秒和 K 内实际消费转换/秒分开报告。GPU 利用率不作为算力饱和判据。性能、功能与棋力分别判断；诊断参考行为不能进入生产训练。
