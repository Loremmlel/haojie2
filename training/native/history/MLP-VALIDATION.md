2026-10-24。起点 `codex/bf16-elastic-training` 的 `8449f5d1d663b93bc10381830884119f5e175f1a`。本轮验证功能、数值、状态连续性和固定实际消费量吞吐。

## 交付路径

生产路径为独立 `haojie-train` C++ / LibTorch 进程及 Rust 规则共享库。初始化、模型、推理、学习、优化器、调度与保存恢复均在原生宿主中完成。旧 Python 包、学习器、控制入口、历史 GRU、长根版本租约、旧 Notebook、相关测试和安装验收已移除；已有模型、轨迹、优化器和原始实验文件保留。

贯通机制包括类型化公开根、节点及 ragged 候选表，根/候选投影去重，一次前向学习、粗粒度补偿 BF16 AdamW，全局就绪 FIFO、独立回送和唯一在途学习工作。每局 actor 固定由一个 CPU lane 拥有；零并发停放会序列化并移除规则对象及其缓存。检查点保留在途状态、两类 RNG、路径/frontier、未决转换、部分轨迹与未消费块。

前缀顺序、身份、索引和存在位以整数/布尔保留，连续输入及全部模型浮点张量为 BF16。当前公开状态、有序参数路径和每层精确排除事实取代完整尝试历史。actor 与 learner 共用分段策略概率定义，真实行为概率由 Rust 的实际抽样分布记录。候选未裁剪，非终局转换使用真实后继 bootstrap。

独立宿主、一次前向、全局合批等机制已在本系统贯通。验收以当前源码和以下本机实际运行结果为准。

## 固定实际消费量

本节对照为本分支重构前的 `8449f5d`，不是 `main`。核对时本地和远端 `main` 均为 `d5760fc25d1283f8ada68abbe22becad9e1cdae4`，使用 11,695,874 参数的终局 MC-Q 系统；新版使用连续 V-trace，学习转换的定义不同。目前未完成 main 与新版的同口径完整管线对照，以下 6.12 倍仅适用于 `8449f5d` 与本次原生重构版本。

硬件为 Windows、Ryzen 7 5800H（8 核 / 16 逻辑处理器）、RTX 3060 Laptop 6 GiB、驱动 610.88、LibTorch 2.14.0+cu130。每次从新进程、零参数初始化开始，种子 1、8 个规则 worker；64 并发的新旧正式初始种子与席位一致。每次精确消费 **4096 个学习席位随机微步**，各配置重复两次。

窗口从运行时初始化完成后开始，在退出排空前冻结；完整进程墙钟从创建进程前计至保存、退出完成。保存期间增加的工作另在 `saved.json` 中记录，窗口产出始终使用冻结的 4096。

| 实现               | 并发 | 学习批 / 块长 | 更新次数 | 窗口秒（两次）    | 完整进程秒（两次） |
| ------------------ | ---: | ------------: | -------: | ----------------- | ------------------ |
| 分支前版 `8449f5d` |   64 |      128 / 64 |       32 | 31.2403 / 34.7336 | 38.0323 / 42.0157  |
| 原生，相同批量预算 |   64 |      128 / 64 |       32 | 5.4754 / 5.2565   | 6.5743 / 6.5092    |
| 原生默认           |   64 |      512 / 16 |        8 | 3.1931 / 3.3772   | 4.2370 / 4.2740    |
| 原生默认           |  256 |      512 / 16 |        8 | 2.3813 / 2.5162   | 3.5640 / 3.5497    |

相同 4096 微步、32 次更新预算下，完整进程墙钟中位数 **40.0240 → 6.5417 秒，直接实测为 6.12 倍**。默认配置 64 / 256 并发的窗口中位数为 **3.2852 / 2.4487 秒**；完整进程中位数为 **4.2555 / 3.5568 秒**。

模型和方法变化单列：分支前版模型为 256×3 Transformer 根编码及 128 维 GRU，2,307,074 参数；新模型为 128 维类型化 MLP 混合及节点/候选头，1,139,458 参数。新对手使用当前发布 actor，分支前版对手整局固定；发布周期分别为新 8、分支前版 10 次更新。默认学习批从 128 改为 512、块长从 64 改为 16；上表中相同批量预算的行保留 32 次更新。以上比较覆盖完整架构与模型变化。

默认 64 并发每次实际产生 4584–4631 个可学习转换，窗口末 ready 为 0–32、partial 为 488–503、pending 为 27–28；默认 256 并发实际产生 6036–6037，ready 为 16–64、partial 为 1876–1925、pending 为 126–128。窗口内消费均为 4096。窗口末最近一秒真实推进的局数分别为 **64 / 256**；所有这些短跑均有在途局，自然终局为 0。

新默认 64 并发的周期 RSS 观察峰值为 1214–1223 MiB，256 并发为 1327–1339 MiB；旧基线周期峰值为 1666–1672 MiB。新默认的 managed 数据观察峰值为 17–23 MiB / 58–59 MiB；该数值计入规则活动分配、轨迹各阶段、收发队列与根缓存，模型及算子临时工作区另占内存。

- Rust 31 项测试、严格 clippy、TS 411 项测试、35 个离线 `file://` 浏览器场景通过。TS/Rust 差分 2218 根 / 5430 节点，最大误差 `5.551115123125783e-17`，4 类私有/未知输入拒绝通过。1109 个规则场景覆盖 10408 次成功命令、22535 次非法命令和 58805 次查询，规范哈希全部一致。

## 剩余主要瓶颈

默认 64 并发的推理调用区间为 1.97–2.01 秒，学习工作区间为 0.86–0.96 秒；256 并发分别为 1.13–1.19 / 0.95–0.98 秒。区间包含组表、设备计算、复制及同步，学习区间还包含提交等待；总成本使用完整管线墙钟。

剩余主线是分解动作仍产生多轮神经请求、概率回到 CPU 的同步点，以及组表和数据记账。当前 GPU 工作按完整学习批和推理批串行提交，CPU actor 可同时推进。进一步收益应优先减少这些提交、传输和依赖，再调整批量或 worker；现有实验不将各局部倍率相乘。

检查点按完整原生构建身份及模型布局校验；本轮验收使用各自同构建恢复。验证范围到上述本机运行及短基准为止。
